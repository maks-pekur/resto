# Quick Task 260615-gl7: Align catalog schema with Syrve `/api/1/nomenclature`

**Goal:** Additive, non-breaking alignment of `category` / `product` / `modifier-option`
field shapes with Syrve nomenclature, to ease future iiko/Syrve (MVP-3) import. No
behavior change to existing menu reads; new fields are optional/nullable everywhere.

**Source of truth for field names:** Syrve `/api/1/nomenclature` —
`ProductsGroupInfo.code`, `ProductInfo.{code,weight,measureUnit}`,
`SimpleModifierInfo.{minAmount,maxAmount}`.

**Conventions:** ZERO code comments (except one WHY for a hidden constraint);
conventional-commit subjects, single line, no body, no footer; TDD where practical;
hand-written migration (db:generate is unusable).

---

## Task 1: DB schema + migration 0050

**Files:** `packages/db/src/schema/menu.ts`,
`packages/db/migrations/0050_catalog_syrve_fields.sql`,
`packages/db/migrations/meta/_journal.json`

- `menu_categories`: add `code text` (nullable).
- `menu_items`: add `code text` (nullable), `weight numeric(10,3)` (nullable),
  `measure_unit text` (nullable).
- `menu_modifier_options`: add `min_amount smallint` (nullable),
  `max_amount smallint` (nullable).
- Constraints (hand-written migration, ALTER TABLE ADD COLUMN/ADD CONSTRAINT/CREATE INDEX —
  tables already FORCE RLS, nothing new there):
  - partial unique `menu_categories_brand_code_uq` on `(tenant_id, brand_id, code) WHERE code IS NOT NULL`
  - partial unique `menu_items_brand_code_uq` on `(tenant_id, brand_id, code) WHERE code IS NOT NULL`
  - `menu_items_weight_nonneg_chk`: `weight IS NULL OR weight >= 0`
  - `menu_items_measure_unit_chk`: `measure_unit IS NULL OR measure_unit IN ('g','kg','ml','l','pcs')`
  - `menu_modifier_options_amount_nonneg_chk`: `min_amount IS NULL OR min_amount >= 0`
  - `menu_modifier_options_amount_order_chk`: `min_amount IS NULL OR max_amount IS NULL OR max_amount >= min_amount`
- Append journal entry idx 50 mirroring the latest `_journal.json` entry shape.

**Verify:** `pnpm nx run db:typecheck`; migration applies cleanly against the dev DB.

## Task 2: Domain Zod schemas

**Files:** `packages/domain/src/schema/menu-category.ts`, `menu-item.ts`, `menu-modifier.ts`

- Category: `code: z.string().max(64).nullable()` (optional/default null at input).
- Item: `code: z.string().max(64).nullable()`, `weight` nonneg number nullable,
  `measureUnit: z.enum(['g','kg','ml','l','pcs']).nullable()`.
- Modifier option: `minAmount` / `maxAmount` nonneg int nullable, with a refine
  `max >= min` when both present.
- Types derived via `z.infer`. All free-text capped per the packages rule.

**Verify:** `pnpm nx run domain:typecheck`; domain spec covers the new validators.
