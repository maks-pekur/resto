<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin role → schema | migrations + role provisioning use the privileged admin string; never the runtime app |
| resto_app → tenant data | NOBYPASSRLS + FORCE RLS is the isolation fence |
| resto_auth → BA credential tables | BYPASSRLS scope strictly limited to BA-owned tables |
| backup artifact → restore target | restored copy contains real (eventually PII) data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-075-06-01 | Elevation of Privilege | resto_auth BYPASSRLS scope | mitigate | auth-role.sql REVOKEs all then grants only BA tables + SELECT/UPDATE on tenants; verified in the role transcript |
| T-075-06-02 | Information Disclosure | resto_app reading BA credential tables | mitigate | roles.sql REVOKEs account/two_factor/verification/session from resto_app; preflight asserts zero privileges at boot |
| T-075-06-03 | Denial of Service | data loss with no restore path | mitigate | G-02: automated backups enabled + one rehearsed, verified restore before go-live; RPO/RTO documented |
| T-075-06-04 | Information Disclosure | connection secrets committed to repo | mitigate | All connection strings live only in the provider console + Secrets Manager (plan 08); runbooks redact; never committed |
| T-075-06-05 | Tampering | migration run under the wrong (runtime) role | mitigate | migrate.ts refuses DATABASE_URL fallback in non-dev; migrations run only under DATABASE_ADMIN_URL |
| T-075-06-SC | Tampering | npm/pip/cargo installs | accept | No package installs; provisioning uses existing committed CLIs |
</threat_model>
