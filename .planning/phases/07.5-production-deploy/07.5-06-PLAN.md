<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → RDS | RDS is in a private subnet with NO public access; its security group admits only the ECS task SG |
| admin role → schema | migrations + role provisioning use the privileged admin/rds_superuser string; never the runtime app |
| resto_app → tenant data | NOBYPASSRLS + FORCE RLS is the isolation fence |
| resto_auth → BA credential tables | BYPASSRLS scope strictly limited to BA-owned tables |
| snapshot → restored instance | restored copy contains real (eventually PII) data; torn down after the drill |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-075-06-00 | Information Disclosure | RDS reachable from the public internet | mitigate | RDS in a private subnet, PubliclyAccessible=false; security group inbound limited to the ECS task SG only; no 0.0.0.0/0 ingress |
| T-075-06-01 | Elevation of Privilege | resto_auth BYPASSRLS scope | mitigate | auth-role.sql REVOKEs all then grants only BA tables + SELECT/UPDATE on tenants; BYPASSRLS confirmed empirically on RDS in Task 1; verified in the role transcript |
| T-075-06-02 | Information Disclosure | resto_app reading BA credential tables | mitigate | roles.sql REVOKEs account/two_factor/verification/session from resto_app; preflight asserts zero privileges at boot |
| T-075-06-03 | Denial of Service | data loss with no restore path | mitigate | G-02: RDS automated backups + PITR enabled + one rehearsed, verified snapshot restore before go-live; RPO/RTO documented |
| T-075-06-04 | Information Disclosure | connection secrets committed to repo | mitigate | All connection strings live only in the RDS console + Secrets Manager (plan 08); runbooks redact; never committed |

| T-075-06-SC | Tampering | npm/pip/cargo installs | accept | No package installs; provisioning uses existing committed CLIs |
