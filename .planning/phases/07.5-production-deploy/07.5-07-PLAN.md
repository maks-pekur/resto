<objective>
Build the two Cloudflare Workers that host the admin and qr-menu SPAs and give each a
same-origin path to the API — with per-tenant cache isolation proven by tests at both
cache layers, not just the one the Worker owns.

Purpose: the committed code requires per-tenant wildcard hosts for both surfaces. Classic
Pages custom domains cannot serve a wildcard host (Pitfall #1), so "Cloudflare Pages" in the
CONTEXT.md prose resolves to **Workers with Static Assets**. The proxy is
not optional plumbing: phase 10.2 F-41 found the operator session cookie silently
dropped whenever admin talks cross-origin, and deleted `VITE_API_ORIGIN` outright (D-39).

This plan also owns the hostname scheme itself. Cloudflare's free Universal SSL covers an
apex and its first-level subdomains only, so the `<slug>.menu.<apex>` and
`<slug>.admin.<apex>` names this app already has in committed code sit one level too deep
and would fail the TLS handshake. The founder's answer is three apexes, one per surface
family; admin needs no code change to move, and the guest menu needs four lines.

Output: two Worker modules, two `wrangler.jsonc` files carrying no hostname, two test
suites, the guest-host configuration change, and the deploy-invocation contract that
supplies the three apexes at deploy time.
</objective>
