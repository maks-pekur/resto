<objective>
Stand up the two self-managed/external data dependencies the runtime needs: the single-node NATS
JetStream broker on EC2+EBS (D-06 — Synadia explicitly does NOT recommend Fargate+EFS for
JetStream) and Cloudflare R2 object storage for menu media (D-07). This is success criterion 2's
object-storage half and the events backbone the outbox dispatches to.

Purpose: NATS is load-bearing for audit, role-change, and the Phase 8 Stripe-webhook inbox-dedup
path — but the single node is a SPOF, made tolerable ONLY because the transactional outbox keeps
events durable in Postgres during a NATS outage. That decoupling must be VERIFIED, not assumed
(investor HIGH #3). R2 is a config swap for the existing S3 adapter, but its presigned-PUT CORS is
a known unverified compat item (RESEARCH A4) and must be smoke-tested with a real browser PUT.
Output: a running authenticated NATS node, an R2 bucket wired to the adapter, and two runbooks.
</objective>

## Trust Boundaries

| Boundary                    | Description                                                                |
| --------------------------- | -------------------------------------------------------------------------- |
| ECS task -> NATS node       | Message bus on the private VPC; must require auth and be VPC-internal only |
| browser -> R2 presigned PUT | Direct-to-bucket upload scoped by presign + CORS                           |
| NATS outage -> order path   | Must degrade (queue in outbox), never block order acceptance               |

| T-075-16  | Denial of Service                | single-node NATS SPOF on order path | accept (mitigated) | Transactional outbox keeps events durable in Postgres during outage; degraded-mode verified; HA deferred post-PMF per CONTEXT |
