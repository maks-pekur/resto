<objective>
Stand up the two managed-but-self-hosted backing services: (D-06) a single-node NATS JetStream with file-backed persistence on EC2+EBS, reachable only from the ECS tasks, with the production stream/consumer config (`max_deliver=5`, `ack_wait`, `dlq.<subject>`) the plan-04 verification recorded; and (D-07) Cloudflare R2 for menu media, wired through the existing S3 adapter as a pure config swap (`S3_ENDPOINT` + `forcePathStyle:true`) with a presigned-PUT round-trip proof.

Purpose: SC#2 requires object storage wired for menu media. R2 is the bootstrap-budget choice (zero egress, S3-compatible — CLAUDE.md prefers it; both personas endorsed). The S3 adapter already uses `forcePathStyle:true` + an `endpoint`, so R2 is config, not code. NATS is the one core dependency the Investor review allows self-hosting (no good free managed JetStream-HA tier), accepted as a SPOF because the outbox decouples order acceptance (proven in plan 04). The CTO precondition — DLQ/`max_deliver` live — was verified in plan 04; this plan sets the matching production config.

Output: a private NATS node + an R2 bucket/token, two runbooks, and the env values (`NATS_*`, `S3_*`) ready for AWS Secrets Manager (plan 08).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ECS tasks → NATS | client port reachable only from the task SG, never public |
| app → R2 | scoped token limited to object r/w on one bucket |
| browser → R2 (direct PUT) | CORS restricted to the admin origin |
| public guest → R2 media | menu images are public-read; cacheable, no per-user data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-075-07-01 | Information Disclosure | public NATS client port | mitigate | SG allows 4222 from the ECS task SG only; no public ingress; credentials required |
| T-075-07-02 | Tampering | overly broad R2 token | mitigate | Token scoped to object r/w on the single menu-photos bucket; no account-wide access |
| T-075-07-03 | Information Disclosure | R2 CORS wildcard leaking bucket to any origin | mitigate | CORS = single admin origin (mirror buckets-cors.tf), never * (T-04b-03-06 carried forward) |
| T-075-07-04 | Denial of Service | JetStream loses events on restart | mitigate | FILE storage on EBS; persistence proven by a restart round-trip; outbox is the durability backstop |
| T-075-07-05 | Elevation of Privilege | presigned PUT with excessive scope/TTL | mitigate | presignPut scoped to a single key with a short TTL; documented in the runbook |
| T-075-07-SC | Tampering | npm/pip/cargo installs | accept | No package installs; R2 is a config-only swap |
</threat_model>
