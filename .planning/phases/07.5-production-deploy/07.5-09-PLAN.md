<objective>
Make deployment boring: merge to main, and the running system becomes that commit —
including the parts of it that are not application code.

Purpose: the box exists (plan 08) but everything on it was placed by hand, and a
hand-placed system drifts from what CI tested within days. The pipeline must never destroy
the database volume and must never run migrations under the wrong role; both are easier to
do accidentally than deliberately, so both get a gate rather than a convention.

Output: `.github/workflows/deploy.yml`, an input-assertion script wired as its first step,
both plan-06 guards wired into CI, a website Dockerfile that can no longer bake a stale
domain, a runbook, and one rollback proven with evidence a script can read.
</objective>

`packages/db/src/cli/migrate.ts` does NOT fail closed on a missing admin URL:

```typescript
const adminUrl = process.env.DATABASE_ADMIN_URL;
const url = adminUrl ?? process.env.DATABASE_URL;      // silent fallback
if (!adminUrl) logger.warn('DATABASE_ADMIN_URL not set — falling back to DATABASE_URL …');
```

A misnamed or empty secret produces a confusing Postgres permission error, or a migration
attempted under the runtime role — never "you forgot the admin URL". The gate has to live
in the workflow (Pitfall #8).

`apps/website/Dockerfile` defaults a domain at build time:

```dockerfile
ARG NEXT_PUBLIC_API_ORIGIN
ARG WEBSITE_URL=https://resto.app        # a baked default nobody chose for this deploy
```

`apps/website/lib/env.ts` validates both with Zod at build time and rejects localhost in
production, so an *absent* value already fails the build loudly — a *defaulted* one does
not. Same class as G-05.

The compose services this workflow drives (plan 06): `api` and `website` recreated by tag;
`migrate` behind `profiles: ["tools"]` so it never starts with `up -d`; `postgres`, `nats`
and `caddy` never touched by CD except when the Caddyfile itself changed. The migrate image
is built from the `migrate` target of `apps/api/Dockerfile`, which exists because the
runtime image lacks `pnpm` and `packages/db/node_modules`.

Provisioning order, everywhere in this phase: migrations first, roles second
(`ci.yml:253-259`). CD only migrates; roles are provisioned once, in plan 08.

      to sha:   <prior>
      journal rows: <n> -> <n>
