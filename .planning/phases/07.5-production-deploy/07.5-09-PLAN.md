<objective>
Build the CD pipeline (D-10) for ALL FOUR production surfaces: on merge to main, after the existing
nx-affected CI gate is green, compute which apps changed and deploy each one — api/admin/website
build to ECR and roll their ECS services; qr-menu builds (vite) and publishes to static hosting.
Database migrations run as a GATED pre-rollout step (pnpm db:migrate under the admin role) before
any ECS service rolls; a failed migration aborts the deploy so the old task definitions keep
serving. This is success criterion 3 (CD on merge to main; migrations as a pre-rollout step),
extended to the full customer surface.

Per RESEARCH: the migration MUST run before the new image rolls (Pitfall 6 — a new image that
rolls ahead of its migration trips assertTenantLockInstalled and fails boot). The migration is a
one-off ECS run-task under DATABASE_ADMIN_URL; the deploy waits on its exit code. AWS Copilot is
EOL — use the ECS Express Mode deploy action. Boot proof is dual and explicit (NOT an either/or):
the docker-api CI gate (07.5-02) proves the SHA boots before merge; CD curls /healthz against the
LIVE ECS service after deploy as the production boot proof.

Purpose: This turns "merge to main" into a safe, gated production rollout of the whole customer
surface that the solo founder can trust, with the migration ordering that prevents the classic
mid-deploy isolation-corruption race, and nx-affected so unchanged apps are not needlessly redeployed.
Output: a cd.yml workflow + a CD runbook.
</objective>

<threat_model>

## Trust Boundaries

| Boundary                          | Description                                                               |
| --------------------------------- | ------------------------------------------------------------------------- |
| GitHub Actions -> AWS (ECR/ECS)   | CD credentials with deploy power; must be least-privilege OIDC            |
| GitHub Actions -> Cloudflare      | qr-menu static publish token; must be scoped to the Pages/R2 target only  |
| migration run-task -> prod schema | DDL under the admin role; a mid-deploy race corrupts isolation if ungated |

## STRIDE Threat Register

| Threat ID | Category               | Component                                                      | Disposition | Mitigation Plan                                                                                                    |
| --------- | ---------------------- | -------------------------------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------ |
| T-075-24  | Tampering/Integrity    | new image rolls before its migration                           | mitigate    | Migrate is a gated pre-rollout step; deploy waits on exit 0; assertTenantLockInstalled is the boot-time safety net |
| T-075-25  | Elevation of Privilege | over-broad CD IAM                                              | mitigate    | OIDC role scoped to ECR push + ECS deploy + the migration run-task only; Cloudflare token scoped to the static target |
| T-075-26  | Tampering              | migrating under the runtime role                               | mitigate    | db:migrate requires DATABASE_ADMIN_URL (no DATABASE_URL fallback in non-dev) — runtime role cannot run DDL         |
| T-075-31  | Information Disclosure  | NEXT_PUBLIC_API_ORIGIN baked wrong / secret in client bundle  | mitigate    | Only the public api origin is a build arg (safe to expose); no secret is passed as a Next build arg                |
| T-075-SC  | Tampering              | GitHub Action supply chain (amazon-ecs-deploy-express-service) | mitigate    | Pin the action to a released version SHA; it is an AWS-published action verified against AWS docs                  |

</threat_model>
