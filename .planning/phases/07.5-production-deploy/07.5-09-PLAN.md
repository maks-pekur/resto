<objective>
Add continuous deployment on merge to `main`, extending the existing nx-affected GitHub Actions CI (D-10): build the `api` + `website` images to ECR (the website build passes `--build-arg NEXT_PUBLIC_API_ORIGIN` = the real prod api host from a repo secret — G-05), publish the `admin` + `qr-menu` static bundles to Cloudflare Pages, run `pnpm db:migrate` as a GATED pre-rollout step under the admin-migration role, deploy all four surfaces, and assert a live `/healthz`. Document the forward-only expand/contract migration + app-only rollback strategy (G-06).

Purpose: SC#3 requires CD on merge to main with database migrations as a pre-rollout step. The migration runs under the admin role (`migrate.ts` refuses the runtime role in non-dev) and must block the rollout on failure — the boot preflight `assertTenantLockInstalled` already fails-closed if a rollout races ahead of migration, so the gate + that net together prevent serving corrupt isolation. `NEXT_PUBLIC_API_ORIGIN` bakes into the Next.js website bundle at build time; the website Dockerfile (07.5-11) defaults it to `https://api.resto.app`, so the CD build MUST override it with the real prod host from a CI secret — relying on the default is exactly the G-05 fallback-bug class CLAUDE.md forbids. Migrations are forward-only with hard deletes forbidden, so rollback is expand/contract + app-only image rollback (G-06) — never a DB rollback; the strategy must be written here and proven in plan 10.

Output: `.github/workflows/deploy.yml` (separate from `ci.yml`, triggered on push to main, depending on green CI) + `docs/runbooks/cd-deploy.md`.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
