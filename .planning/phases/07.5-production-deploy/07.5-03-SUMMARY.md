## What Was Built

### D-05: Direct-connection outbox advisory lock

The outbox dispatcher's `pg_try_advisory_lock(4815115)` was previously acquiring on `this.db.connection.raw.reserve()` — the same pooled connection DATABASE_URL uses. In Neon's PgBouncer transaction-mode, this connection is never session-pinned so the advisory lock is logically unsafe (released at end of transaction, not end of session). The fix routes the lock through a dedicated `DIRECT_DB_CONNECTION` postgres.js client (`max: 1`, `idle_timeout: 0`, `prepare: false`) constructed from `DATABASE_DIRECT_URL` and injected via `@Optional()`. In dev/test where `DATABASE_DIRECT_URL` is unset, the existing pooled path is the fallback — no behavioral change for local development.

### G-03: Leader-aware /readyz

`HealthController.readiness()` now runs three checks in parallel: DB, broker, and outbox leader liveness. The leader check calls `OutboxDispatcherService.getOutboxLeaderHealth()` which returns `{ isLeader, lastDispatchAt, staleMs }`. Non-leader instances return `ok: true` immediately (correct — a non-leader is intentionally idle). Leader instances return `ok: false` when `staleMs` exceeds `OUTBOX_STALL_THRESHOLD_MS` (default 60 000ms, env-tunable). A stalled leader causes `/readyz` to respond 503, enabling the load balancer to drain the wedged instance.

### G-04: Sentry error tracking

All three JS surfaces initialize Sentry behind their respective DSN env, so a missing DSN is a silent no-op (dev/test/CI boot unaffected):

- API: `bootstrap-telemetry.ts` — `Sentry.init()` runs pre-NestFactory when `SENTRY_DSN` is set
- Website: Next.js `instrumentation.ts` — `register()` hook guards init behind `process.env.NEXT_RUNTIME === 'nodejs' && process.env.SENTRY_DSN`
- Admin SPA: `main.tsx` — guard checks `VITE_SENTRY_DSN` before React tree mounts

All inits use `sendDefaultPii: false` and `tracesSampleRate: 0.1`.

### G-05: Fail-loud web env for production

Both web-layer env loaders now reject localhost URLs in production:

- **Website** (`apps/website/lib/env.ts`): `isLocalhostUrl()` check runs after Zod parse when `!isPermissive(NODE_ENV)`, throwing `WebsiteEnvValidationError` if `NEXT_PUBLIC_API_ORIGIN` or `WEBSITE_URL` resolves to localhost.
- **Admin** (`apps/admin/src/env.ts`): `getEnv()` throws when `import.meta.env.PROD` and the resolved value is empty or matches the localhost pattern. Dev default (`http://localhost:3000`) only applied when `import.meta.env.DEV`.
