<objective>
Create the production Dockerfiles for apps/admin and apps/website so the four-surface deploy
(07.5-08 ECS services + 07.5-09 CD) has real images to build and roll. Neither app has a Dockerfile
today, and neither Next config sets output: 'standalone' — both are required to ship admin + website
as lean ECS/Fargate services. This is the build-side enabler for success criterion 1's admin +
website halves (the public storefront surface goes live in 7.5; checkout stays disabled until Phase 8).

Per RESEARCH (Pitfall 9): a Next.js Docker image without output: 'standalone' either copies the
entire node_modules (fat, slow cold starts) or fails to find the server bundle. NEXT_PUBLIC_API_ORIGIN
is baked into the client bundle at build time, so it MUST be a build arg (not only a runtime secret) —
otherwise the localhost fallback (admin's next.config rewrite uses NEXT_PUBLIC_API_ORIGIN ?? 'http://localhost:3000')
would ship in the image. Mirror the existing apps/api/Dockerfile multi-stage shape (deps -> build ->
runner) for cache efficiency and a small final image.

Purpose: This is the missing build artifact that the checker flagged — admin had no CD/deploy path and
website was not yet containerized. Both are needed before the ECS services in 07.5-08 can point at an image.
Output: two production Dockerfiles + output:'standalone' in both Next configs + a verified local image boot.
</objective>
