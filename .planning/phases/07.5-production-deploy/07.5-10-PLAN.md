Guest sticker host precedence — `GuestMenuUrlService.#resolveGuestHost`:

```typescript
const primaryVerifiedCustom = domains.find(
  (d) => d.kind === 'custom' && d.isPrimary && d.verifiedAt !== null,
);
if (primaryVerifiedCustom) return primaryVerifiedCustom.domain;   // outranks the apex
return `${tenant.slug}.${env.GUEST_APEX_DOMAIN}`;   // after plan 07 Task 3
```

One `tenant_domains` row decides what every printed QR code says, and a row left from a dev
tunnel looks legitimate — "verified custom domain" is a production concept, not a dev flag.
`prod-guardrails.ts` inspects env, not rows, and cannot see it.

`tenant_domains` shape (`packages/db/src/schema/tenants.ts`): `domain` (citext, globally
unique), `kind` in `('subdomain','custom')`, `is_primary` under a partial unique index
`tenant_domains_one_primary_per_tenant_uq WHERE is_primary = true`. Clear the old primary
before setting a new one, or the write is rejected — or, under `ON CONFLICT DO NOTHING`,
silently dropped.

**The primary domain is built from a module constant, not from configuration:**

```typescript
// provision-tenant.service.ts:9 and finalize-tenant-onboarding.service.ts:7
const PRIMARY_DOMAIN_SUFFIX = 'menu.resto.app';
```

Plan 07 Task 3 already moved the *reader* side (`guest-menu-url.service.ts`,
`tenant-resolver.service.ts`) onto `GUEST_APEX_DOMAIN` and deleted `GUEST_HOST_LABEL`.
These two *writers* are what is left, and they must write the **guest** apex — not the main
one. Writing `<slug>.<main-apex>` here would collide with the website's own host and hand
the operator a link to the wrong surface.

`GUEST_HOST_LABEL = 'menu'` is duplicated as a module-local const in both
`guest-menu-url.service.ts:7` and `tenant-resolver.service.ts:9`, exported from neither.

That row is what the operator sees as their own menu address —
`apps/admin/src/components/settings/apps-section.tsx:30` renders the link from
`tenant.primaryDomain`, not from the apex — so on any other apex the settings page links to
a domain the founder does not own.

**The ETag is NOT tenant-scoped.** `public-menu.controller.ts:272,298` builds it as
`'"' + version + '"'` — a bare menu-version integer. Two freshly published tenants both sit
at version 1 and emit identical ETags. An isolation assertion built on an ETag difference
fails in exactly the fresh-production case this smoke targets, for a reason unrelated to
isolation — which is how an executor talks itself into deleting the phase's most important
check. Compare bodies.

**`cf-cache-status` is not observable here.** It is emitted by Cloudflare's own cache
pipeline; a Worker serving from `caches.default` does not produce it. Plan 07's Workers emit
`X-Resto-Cache: HIT|MISS|BYPASS` for this purpose.

**CORS cannot prove same-origin.** `security.ts:171`'s `buildOriginMatcher` emits
`Access-Control-Allow-Origin` only when the request carries `Origin`. A Node script sends
none, so the header is absent both in a correct same-origin setup and in a completely broken
cross-origin one; and if the script did send `Origin: https://admin.<apex>`, the API would
emit ACAO on a correct setup because `CORS_ALLOWED_ORIGINS` lists it. Assert the response
*shape* instead.

The public webhook endpoint (`stripe-webhook.controller.ts`):

```
POST /webhook/stripe    @Public()
  no stripe-signature header -> 400 "Missing stripe-signature header"
```

       Do not assert `cf-cache-status`: Cloudflare emits it from its own cache pipeline and a
       Worker serving from `caches.default` never produces it, so that assertion could only
       ever fail.
    5. **Cross-tenant isolation** — the assertion this phase's whole proxy design turns on:

       compare ETags: the origin builds them from a bare menu-version integer, so two freshly

       fresh-production case it exists for. A failure here means the edge is serving one
       restaurant's menu to another's guests, and go-live stops.
    6. `GET https://<admin-apex>/login` → 200 SPA shell; then
       `POST https://<admin-apex>/api/auth/sign-in/email` with a **wrong** password → a 4xx
       whose `content-type` is JSON and whose body is a Better Auth error shape, not
       `text/html`. That proves `run_worker_first` bound `/api/*` and the request reached the
       API rather than being answered by the SPA fallback. Then **sign in once with valid
       credentials** and assert the `Set-Cookie` carries `Domain=.<admin-apex>`. That is the
       actual F-41 regression net: it is the single path that both crosses the Worker proxy
       and depends on cookie-domain scoping. Do not assert on the absence of
       `Access-Control-Allow-Origin` — a Node client sends no `Origin`, so that header is
       absent whether the setup is correct or completely broken.
    7. `POST https://api.<apex>/webhook/stripe` with no `stripe-signature` header → 400

       needed a public URL for.
