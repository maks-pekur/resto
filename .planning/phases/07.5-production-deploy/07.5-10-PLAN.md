<interfaces>
<!-- What the audit and the smoke are checking against. -->

Guest sticker host precedence — `GuestMenuUrlService.#resolveGuestHost`:
```typescript
const primaryVerifiedCustom = domains.find(
  (d) => d.kind === 'custom' && d.isPrimary && d.verifiedAt !== null,
);
if (primaryVerifiedCustom) return primaryVerifiedCustom.domain;   // outranks the apex
return `${tenant.slug}.menu.${env.PUBLIC_APEX_DOMAIN}`;
```
So one `tenant_domains` row decides what every printed QR code says, and a row left over
from a dev tunnel looks entirely legitimate — "verified custom domain" is a production
concept, not a dev flag. `prod-guardrails.ts` cannot see it: it inspects env, not rows.

`tenant_domains` shape (`packages/db/src/schema/tenants.ts`): `domain` (citext, globally
unique), `kind` in `('subdomain','custom')`, `is_primary` boolean under a partial unique
index `tenant_domains_one_primary_per_tenant_uq WHERE is_primary = true`. Clearing the
old primary before setting the new one is mandatory — otherwise the write is rejected or,
under `ON CONFLICT DO NOTHING`, silently dropped.

The public webhook endpoint Phase 8 needs (`stripe-webhook.controller.ts`):
```
POST /webhook/stripe    @Public()
  no stripe-signature header -> 400 "Missing stripe-signature header"
  bad signature           -> 400 "Invalid Stripe signature"
```
An unsigned POST returning 400 proves both reachability and fail-closed verification
without needing a real Stripe event.

Edge cache contract the smoke asserts against (`docs/runbooks/menu-edge-caching.md`):
`GET /v1/menu` → `public, s-maxage=300, stale-while-revalidate=60`, per-tenant `ETag`,
and `cf-cache-status` MISS then HIT on repeat within the window.

    **`infra/scripts/go-live-smoke.mjs`** — a plain Node script (no new dependency),
    run from a laptop, taking `PUBLIC_APEX_DOMAIN` and two seeded tenant slugs from the
    environment. Every hostname is derived; none is written down. It asserts, printing
    one pass/fail line each and exiting non-zero on any failure:

    1. `GET https://api.<apex>/healthz` → 200.
    2. `GET https://api.<apex>/readyz` → 200, and the body reports the outbox leader as
       live — the stall detector added by 07.5-03 is only useful if someone looks at it
       once.
    3. `GET https://<apex>/` → 200 from the website container, and
       `GET https://<slug-a>.<apex>/` → 200 whose body contains a real seeded menu item
       name. A 200 with an empty shell is not an end-to-end render and must fail.
    4. `GET https://<slug-a>.menu.<apex>/` → 200 serving the qr-menu SPA shell, and
       `GET https://<slug-a>.menu.<apex>/v1/menu` → 200 same-origin with the
       `public, s-maxage=300` cache-control and a per-tenant `ETag`. Repeat the second
       request and assert `cf-cache-status` goes MISS (or EXPIRED) then HIT.
    5. **Cross-tenant isolation, the assertion this whole phase's proxy design turns
       on:** `GET https://<slug-b>.menu.<apex>/v1/menu` and assert its `ETag` differs
       from tenant A's and its body contains tenant B's items and none of tenant A's.
       Run it immediately after A's cache is warm, which is when a collapsed cache key
       would show. A pass here is the production counterpart of the unit test written
       in plan 07; a fail means the edge is serving one restaurant's menu to another's
       guests and go-live stops.
    6. `GET https://admin.<apex>/login` → 200 SPA shell, and
       `POST https://admin.<apex>/api/auth/sign-in/email` with a deliberately wrong
       password → a 4xx from the API carrying no `Access-Control-Allow-Origin` header.
       That combination is the proof that the admin Worker's `/api/*` proxy reached the
       API *same-origin*: a cross-origin arrangement would either fail CORS or need the
       header. This is the single highest-value assertion in the smoke — it is the path
       that both crosses the proxy and depends on cookie-domain scoping, which is where
       phase 10.2 F-41 found a failure that fourteen plans and a green e2e suite had all
       missed.
    7. `POST https://api.<apex>/webhook/stripe` with no `stripe-signature` header → 400
       "Missing stripe-signature header". Reachable and fail-closed, which is exactly
       what Phase 8 needed a public URL for.

    A successful operator sign-in with real credentials is deliberately not automated
    here: there is no Playwright harness in this repo (`@playwright/test` is not
    installed and no config exists), and building one to assert a single login would
    cost more than the founder doing it once. Put it in the checklist as a named manual
    step with an explicit observable — after signing in at `admin.<apex>`, the browser
    lands on `<slug>.admin.<apex>` and the session survives that hop — and note that

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| production database → printed QR sticker | one `tenant_domains` row decides a physical artifact guests scan |
| R2 backup bucket → recovery | if the object cannot be restored, the backup was theatre |
| Cloudflare edge cache → guests of a different tenant | the highest-impact silent failure in this architecture |
| internet → `/webhook/stripe` | a public, unauthenticated-by-design endpoint |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07.5-10-01 | Information Disclosure | cross-tenant menu served from the edge | mitigate | live two-tenant assertion in `go-live-smoke.mjs` run while tenant A's cache is warm; failure blocks go-live |
| T-07.5-10-02 | Denial of Service | QR stickers pointing at a dead tunnel host | mitigate | `preflight-prod-data.sh` audits `tenant_domains` for dev-host patterns and reports the ordered fix respecting the one-primary partial unique index |
| T-07.5-10-03 | Denial of Service | unrecoverable backups | mitigate | the drill restores a real R2 object and verifies migration journal, role attributes and tenant data; a failed drill is a finding, not a reason to relax the assertion |
| T-07.5-10-04 | Elevation of Privilege | backup token able to reach guest media | mitigate | a bucket-scoped `resto-backups` token distinct from the media token; `rclone.conf` at mode 600 owned by the deploy user |
