# Phase 7.5: Production Deploy - Context

**Gathered:** 2026-06-21
**Status:** Ready for planning

<domain>
## Phase Boundary

Stand up the **first real production environment** so the MVP-1 spine (api + admin,
later website/qr-menu) is shippable over HTTPS on a real domain, and Phase 8's Stripe
webhooks have a public URL. **Pragmatic over ideal — managed services, not a k8s/Terraform
build-out.** Generates no revenue; it is the gate to revenue (Phase 8).

The five success criteria are fixed by ROADMAP.md §"Phase 7.5": (1) api+admin run on
managed prod over HTTPS with the 3-role Postgres provisioned; (2) object storage wired +
runtime secret injection; (3) CD on merge to `main` with migrations as a pre-rollout step;
(4) boot preflights (`assertProdGuardrails`, RLS-bypass) pass in real prod; (5) a public
HTTPS webhook endpoint + an end-to-end smoke (external request → API → tenant menu renders).

**Not in scope:** Stripe/payments (Phase 8), multi-region, k8s, full IaC platform.

> **SCOPE CHANGE (2026-06-21):** `apps/admin` is being re-platformed to a Vite SPA (Phase 7.6) and will deploy as **static** (Cloudflare Pages/R2 + CDN), NOT an ECS service. For the remaining 7.5 deploy, treat the hosting surface as **api + website (ECS) + qr-menu (static)** — drop the admin ECS service from D-01/D-08 and the admin Dockerfile from the plan set (07.5-11's admin half is superseded; its website Dockerfile stays). The admin static deploy folds into Phase 7.6. D-01..D-10 otherwise unchanged.
> </domain>

<decisions>
## Implementation Decisions

### Hosting

- **D-01:** Host on **AWS ECS/Fargate**. Founder's explicit choice, **made after** seeing
  both persona reviews recommend Fly/Railway instead (experience/credits/control; accepts
  the ops overhead). Plan MUST account for the ECS surface a PaaS would hide: VPC,
  ALB/HTTPS listener, Fargate task/service defs, IAM, log routing, and CD wiring.
- **D-02:** The API must run **≥1 always-on instance** — the outbox dispatcher elects a
  leader via `pg_try_advisory_lock(4815115)` on a reserved Postgres connection
  (`apps/api/src/infrastructure/outbox-dispatcher.service.ts`). No idle-to-zero on the API
  task, or paid-order/email/audit events queue silently. (Leader election makes multi-task
  safe; the constraint is "never zero", not "exactly one".)
- **D-03:** Keep IaC **minimal** despite ECS — AWS Copilot CLI or a small/single Terraform
  module is acceptable; an explicit "**no full k8s, no multi-region, no sprawling Terraform
  estate in 7.5**" constraint is LOCKED (investor BLOCK against gold-plating).

### Database (Postgres)

- **D-04:** **Neon** (serverless Postgres) as primary. **HARD GATE (validate before
  locking):** RestOS needs `resto_auth` with `BYPASSRLS` + a schema-owner role with
  `CREATEROLE`/DDL; Neon ties `BYPASSRLS` to `neon_superuser`. Researcher MUST prove the
  3-role + FORCE-RLS + pgcrypto/citext model is expressible on Neon **before** the plan
  commits to it. **Documented fallback: AWS RDS** (natural now that hosting is AWS; RDS
  gates BYPASSRLS behind `rds_superuser` but supports it) or Supabase.
- **D-05:** The outbox leader's advisory lock needs a **direct, unpooled, session-pinned**
  connection; the request path may use the pooler. Wire two connection strings (pooled for
  app queries, direct for the dispatcher) — a Neon/PgBouncer footgun.

### Events (NATS)

- **D-06:** **Self-hosted single-node NATS JetStream** on the platform with persistence.
  Synadia Cloud / managed is over-engineered for first-customer volume. Single node is a
  SPOF on the order path — **mitigated by the transactional outbox** (writes commit to
  Postgres; dispatch is async/retried). Verify the outbox actually decouples ordering from
  NATS availability; confirm the DLQ / `max_deliver` poison-message handling live.

### Object storage

- **D-07:** **Cloudflare R2** for menu media. Zero egress, S3-compatible (existing AWS S3
  SDK + presigned URLs work unchanged), CLAUDE.md already prefers R2. No conflict — both
  personas endorsed.

### Domains / TLS / CDN

- **D-08:** **Cloudflare in front of the platform**: DNS, free wildcard TLS for
  `*.menu.resto.app`, and CDN cache-rules for the public menu reads (the menu-caching
  feature already emits versioned ETag/Cache-Control — see runbook). Tenant **custom
  domains** via Cloudflare for SaaS (custom hostnames) — wiring can be light in 7.5 (apex +
  wildcard first; full per-tenant custom-domain onboarding may land later).

### Secrets / CD

- **D-09:** Runtime secrets via **AWS Secrets Manager** (native to ECS); never baked into
  images or committed. `assertProdGuardrails` already fails-closed on placeholder secrets
  (BLOCK-4 fix) — it must pass in real prod.
- **D-10:** **CD = existing GitHub Actions** (nx-affected CI) extended to build the image
  and deploy the ECS service on merge to `main`; **`pnpm db:migrate` runs as a gated
  pre-rollout step** under the admin-migration role.

### Locked correctness gates (from persona reviews — planner MUST address)

- **G-01 (BLOCK):** Phase is GATED on a **green production container** passing all six boot
  preflights against **real managed Postgres** — the known `import.meta.dirname`-in-CJS
  Docker bug (deliberately uncaught, see `.github/workflows/ci.yml` note) must be fixed and
  proven, or a public URL ships a binary that crashes on boot.
- **G-02 (BLOCK):** **Backups + a tested restore** on the revenue path. Define RPO/RTO and
  prove a restore once before go-live (paying restaurants' menus/orders/PII live here).
- **G-03 (HIGH):** Pull forward a **minimal outbox-stall detector** — `/readyz` checks DB +
  broker reachability but not leader liveness / dispatch lag
  (`apps/api/src/health/health.controller.ts`). A silent stall = lost paid-order events.
- **G-04 (HIGH):** Add an **error tracker** (Sentry or equivalent) — none exists today.
- **G-05 (HIGH):** Fix the pre-existing **`NEXT_PUBLIC_API_ORIGIN` / `ADMIN_WEB_URL`
  localhost-fallback** bug (CONCERNS.md) — it goes live in exactly this phase and would
  silently route real users to localhost. (Note: CI build now injects placeholders — prod
  must inject real values.)
- **G-06 (MEDIUM):** Migrations are **forward-only** (no `down`, hard deletes forbidden) →
  rollback = **expand/contract migrations + app-only image rollback**, proven before go-live.
- **G-07 (MEDIUM):** This phase **explicitly supersedes** the abandoned AWS-EKS/Terraform
  direction in ADR-0011 + `infra/CLAUDE.md` + the `infra/k8s` / `infra/terraform` stubs
  (we are AWS **ECS**, not EKS).

### Claude's Discretion

- ECS provisioning tool (Copilot vs minimal Terraform vs CDK) — pick the lowest-ops option
  that satisfies D-03; surface the choice in the plan.
- Exact Sentry vs alternative; exact backup cadence within a stated RPO/RTO.
  </decisions>

<code_context>

## Existing Code Insights

### Reusable Assets

- `assertProdGuardrails` + env-schema fail-closed boot (already hardened in BLOCK-4) — the prod-readiness gate is largely built; the phase wires real values + proves it boots.
- Transactional outbox + inbox-dedup (`@resto/events`) — decouples ordering from NATS uptime; the single-node-NATS SPOF risk rests on this holding.
- S3-compatible adapter (`s3-signed-image-url.adapter.ts`) — R2 is a config swap, not code.
- nx-affected GitHub Actions CI — CD extends this, doesn't replace it.

### Established Patterns

- 3-role Postgres + FORCE RLS double-enforcement is the product's core defensibility — "treat managed Postgres as commodity Postgres" (no proprietary primitives) keeps it portable and is the lens for the D-04 gate.
- Migrations forward-only (hard deletes forbidden by role grant) → expand/contract (G-06).

### Integration Points

- ECS task ↔ Neon (two conn strings: pooled + direct) ↔ self-hosted NATS ↔ R2 ↔ AWS Secrets Manager; Cloudflare terminates TLS/CDN in front of the ALB.
  </code_context>

<specifics>
## Specific Ideas

- Founder deliberately chose **AWS ECS over the unanimous persona recommendation** (Fly/Railway) and accepts the ops cost — the plan should make the ECS path as boring/managed as possible (Copilot/minimal Terraform), not a bespoke platform.
- Whole-stack target burn ~$40–90/mo; the scarce resource is **founder-weeks** → bias every plan choice toward fewer moving parts and days-to-HTTPS.

- Managed/HA NATS (Synadia or multi-node) — revisit only if the single node becomes a real bottleneck post-PMF.
