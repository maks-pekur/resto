<objective>
Verify (do not build) the two NATS-related correctness preconditions the persona reviews made load-bearing for the single-node-NATS decision, and record the qr-menu same-origin requirement that shapes plan 08's CDN routing.

Purpose: D-06 self-hosts a single NATS node — a SPOF on the order path. The whole justification is that the transactional outbox decouples order acceptance from NATS uptime (writes commit to Postgres; dispatch is async/retried) and that the DLQ / `max_deliver` poison-message handling (shipped in Phase 3 as AUTH-10 in `packages/events`) is actually live so one malformed envelope cannot wedge a consumer forever. The CTO review made the DLQ a precondition; the Investor review made outbox-decoupling a "must be verified, not assumed" HIGH. Separately: the qr-menu fetches `/v1/menu` as a relative path (`apps/qr-menu/src/api/client.ts`), so it can only work when served same-origin with the API — plan 08 must wire a Cloudflare same-origin rewrite/proxy, not a cross-origin CORS path. That requirement is recorded here so it is not discovered during the live cutover.

Output: an e2e test proving order-create survives a NATS outage and drains on recovery, a live DLQ/max_deliver confirmation, and `PRE-DEPLOY-VERIFY.md` capturing all three findings.
</objective>
