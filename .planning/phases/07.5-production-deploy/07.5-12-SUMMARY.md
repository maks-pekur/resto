# Phase 07.5 Plan 12: Delete the Worker proxies, move both SPAs under a path, land the apex Summary

**Both Cloudflare Worker projects go assets-only (proxy scripts, cache logic and 22 Worker tests deleted outright), the QR menu moves to `<slug>.<apex>/qr` with a base-prefixed route parser and its own cart namespace, and the bare apex now renders a noindex marketing placeholder instead of "Restaurant not found".**

## Performance

- **Duration:** ~60 min
- **Completed:** 2026-09-05T21:44:00Z
- **Tasks:** 3/3
- **Files modified:** 31 (5 created, 20 modified, 6 deleted)

## Accomplishments

- Deleted `apps/admin/worker/` and `apps/qr-menu/worker/` in full (98 lines of Worker source, 444 lines of Worker tests) and rewrote both `wrangler.jsonc` to the assets-only shape — no `main`, no `binding`, no `run_worker_first`, no `routes`/`vars`.
- Removed `@cloudflare/workers-types` from both packages via `pnpm remove` and dropped `worker:dry-run` from both `package.json`.
- Admin now builds into `dist/admin/` (`build.outDir`), qr-menu into `dist/qr/` (`base: '/qr/'` + `build.outDir`); both `build` scripts and both Nx `project.json` build targets copy the subdirectory's `index.html` to `dist/index.html`, working around Workers Static Assets serving the SPA fallback at the asset root rather than the subdirectory root (measured under `wrangler dev --local`, research M-09).
- `apps/qr-menu/src/App.tsx`'s three route regexes and all five `history.pushState`/`replaceState` targets are now anchored against a `BASE_PATH` constant (`import.meta.env.BASE_URL` sans trailing slash) instead of literal `/`-rooted paths; `parseItemId`/`parseDocumentKey`/`parseQrToken` are exported for direct unit testing.
- `apps/qr-menu/src/components/TableScanCard.tsx`'s `qrTokenFromScan` — the in-page camera rescan parser, a call site the plan's own research interfaces section missed — made base-aware with the same `BASE_PATH` source.
- `packages/cart/src/cart.ts` computes its persist key once at store creation from `document.location.pathname`: `resto-cart-qr` under `/qr`, `resto-cart` (unchanged) everywhere else, SSR-guarded.
- `apps/website/lib/apex-host.ts` (`isApexHost`) derives the apex from `websiteUrl()` and matches the apex and `www.<apex>`, port-insensitive; `apps/website/app/page.tsx` branches on it before any tenant lookup in both `MenuPage` and `generateMetadata`.
- `apps/website/components/marketing/apex-landing.tsx` — a minimal `noindex` placeholder (product name, one sentence, a link to `/admin`) using `next-intl`; copy added to all four catalogues (`en`, `es`, `ru`, `uk`).
- `docs/runbooks/spa-workers.md` rewritten in full for the single-apex, no-proxy shape — the three-apex map, the proxy, the cache-key rule and the `X-Resto-Cache` contract are gone rather than annotated.

**1. [Rule 2 - Missing critical] Nx `project.json` build targets bypassed the index.html copy step**
- **Found during:** Task 1
- **Issue:** `apps/admin/project.json` and `apps/qr-menu/project.json` declare their own `build` target as a bare `nx:run-commands` invocation of `vite build`, independent of `package.json`'s `build` script. Once the plan's fix (copying `dist/<subdir>/index.html` to `dist/index.html`) landed only in `package.json`, an `nx build admin` (or `nx build qr-menu`) would still produce a `dist/` with no root `index.html` — reproducing exactly the deep-link-404 defect (T-07.5-12-03) this task exists to close, for any caller that builds through Nx rather than `pnpm run build`.
- **Fix:** Changed both `project.json` build commands to run the same `vite build && cp dist/<subdir>/index.html dist/index.html` sequence.
- **Files modified:** `apps/admin/project.json`, `apps/qr-menu/project.json`
- **Verification:** `pnpm --filter admin build` / `pnpm --filter qr-menu build` (which use the `package.json` script) already proved the copy; the `project.json` fix keeps the two build entry points from diverging. Not independently re-verified via a live `nx build` invocation in this session — the fix is a direct textual mirror of the already-proven `package.json` command.
- **Committed in:** `d5ffd633` (Task 1 commit)

**2. [Rule 1 - Bug] `qrTokenFromScan` (TableScanCard.tsx) — a ninth call site the plan's own census missed**
- **Found during:** Task 2
- **Issue:** The plan's `<interfaces>` section lists "the qr-menu call sites that carry a path, read from the file" as eight lines, all in `App.tsx`. `apps/qr-menu/src/components/TableScanCard.tsx` has a ninth: `qrTokenFromScan`, which parses a scanned QR code's URL for the in-page camera-rescan recovery flow, against a hardcoded `/^\/t\/([^/]+)\/?$/`. With the sticker's real path now `/qr/t/<token>`, a guest whose original scan failed and who re-scans the same printed code via the in-page camera would get a `null` token and a "scan failed" message — the flow the plan's own success criterion ("a scanned sticker path parses its token") is about, just reached through a second code path.
- **Fix:** Extracted `BASE_PATH` into `apps/qr-menu/src/lib/base-path.ts` (App.tsx cannot export it to TableScanCard.tsx — App.tsx → TableProblemSheet → TableScanCard is already an import chain, so the reverse would be circular) and built `SCANNED_TABLE_PATH` from it in `TableScanCard.tsx`, replacing the hardcoded regex.
- **Files modified:** `apps/qr-menu/src/components/TableScanCard.tsx`, `apps/qr-menu/src/lib/base-path.ts` (new)
- **Verification:** `qr-token.spec.ts`'s five existing tests (which run with the default test `BASE_URL` of `/`, so `BASE_PATH` is `''` and the regex is byte-identical to the pre-change literal) all still pass unmodified — no regression; the fix is proven correct by construction (same `BASE_PATH` source as App.tsx's already-tested parsers) rather than by a new dedicated test, since qr-token.spec.ts's existing negative/positive cases already exercise the shared regex shape.
- **Committed in:** `0943a987` (Task 2 commit)

**3. [Rule 1 - Bug] `apps/admin/.env.example`'s stale-and-grep-tripping comment**

**4. [Rule 1 - Bug] The plan's own runbook instructions conflict with its own verify grep**
- **Found during:** Task 1, writing `docs/runbooks/spa-workers.md`
- **Issue:** The plan's action text for the runbook explicitly asks for two sentences that each require a banned literal: "neither Worker has a script, so requests to these routes are free and unlimited and no 429 cliff exists" (naturally cites `run_worker_first`, the field being removed) and "`cf-cache-status` ... replaces `X-Resto-Cache`" (names the literal header being removed). **5. [Rule 1 - Bug] The plan's Task 1 wrangler.jsonc verify script would fail on the pre-existing (JSONC, trailing-comma) files**
- **Found during:** Task 1, running the plan's literal verify script
- **Issue:** `wrangler.jsonc` is JSONC (comments + trailing commas allowed, per Wrangler's own parser) — both the pre-change and post-change files have a trailing comma before the closing `}`. The plan's verify script strips only full-line comments before calling `JSON.parse`, which throws on a trailing comma. Run literally, the check fails regardless of whether the assets-only migration is correct.
- **Fix:** Added a trailing-comma strip (`.replace(/,(\s*[}\]])/g, '$1')`) before `JSON.parse` when running this check manually; did not modify the `wrangler.jsonc` files themselves (JSONC with a trailing comma is the correct, idiomatic format Wrangler expects).
- **Verification:** With the fix, both files parse and satisfy every assertion (no `main`, no `binding`, no `run_worker_first`, correct `not_found_handling`, no `routes`/`vars`) — see Verification Checks below.
- **Committed in:** N/A — this is a verification-methodology note, not a source change.
