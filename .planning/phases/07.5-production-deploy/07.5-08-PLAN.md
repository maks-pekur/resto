<objective>
Stand the real thing up: one VPS behind one Cloudflare zone serving the API, the storefront and the
marketing apex over HTTPS, with both SPA bundles live on their paths and a guest menu request that
actually returns a tenant's menu.

Purpose: this is the plan that spends money and creates state. Everything it does was rehearsed
locally in plans 06 and 07.5-14, so what is left are the failure modes only a real network has —
DNS, TLS trust, firewall scope, whether the guardrails pass against real credentials, and whether
the tenant chain survives contact with Caddy and with Cloudflare.

That last one is why this plan, and not plan 07.5-10, owns the first tenant-resolving request:
without it the phase can reach the end of CD — every hostname at 200, everything green — with the
guest menu completely dead. It is also where research assumption **A7** gets settled, because it is
the first moment a real Cloudflare edge is in the path.

Output: two scripts, two runbooks, a live production origin serving a real tenant, and a repository
configuration that names one apex.
</objective>

**Provisioning order is migrations FIRST, roles SECOND** (`.github/workflows/ci.yml:253-259`,
`packages/db/test/setup.ts:56`). `packages/db/sql/auth-role.sql:14-24` issues an unguarded
`GRANT ... ON "user", session, …` which raises `relation "user" does not exist` on a database with
no tables, exiting non-zero under `set -euo pipefail`. Roles-then-migrate cannot work on a fresh box.

**The TLS boundary, measured on the founder's live zone 2026-09-05:**

```
$ openssl s_client -connect <apex>:443 -servername <apex> </dev/null 2>/dev/null \
    | openssl x509 -noout -ext subjectAltName
    DNS:<apex>, DNS:*.<apex>

$ curl -sS -o /dev/null https://probe123.<apex>/        ; echo $?   # depth 1
28      # handshake OK, nothing behind it

$ curl -sS -o /dev/null https://probe123.menu.<apex>/   ; echo $?   # depth 2
35      # sslv3 alert handshake failure — the edge rejects at the TLS layer
```

Two SANs: the apex and exactly one wildcard level. Round-1 lore predicted exit **60** for a TLS
failure; the real code here is **35**, because the edge rejects without presenting a certificate at
all. Exit 60 is the other shape (a certificate is presented but does not authenticate). Accept
either; reject anything else. This mismatch between the predicted and the observed value is
precisely why this plan requires the command rather than the prediction.

**The seed CLI is API-driven, not database-driven** (`tools/scripts/seed/lib/options.ts`): it needs
`RESTO_API_URL` and `INTERNAL_API_TOKEN`, nothing else.

```
resto-seed provision-tenant --slug <slug> --name <displayName> --country <UA|GB|ES>
                            [--locations 1] [--owner-email <e>] [--password-stdin]
resto-seed seed-menu        --tenant <slug> --file <menu.yaml>
```

`seed-demo` refuses to run outside `NODE_ENV=development`
(`tools/scripts/seed/commands/seed-demo.ts:991`) — use `provision-tenant` plus `seed-menu`.
`/internal*` is protected by `InternalTokenGuard` (`apps/api/src/shared/api/internal-token.guard.ts`)
— a constant-time compare of `X-Internal-Token` that throws outside `NODE_ENV=development` whenever
the token is unset or mismatched. **That guard is the control.** The Caddy `client_ip` matcher
narrows reachability as a second layer; it is not what makes the surface safe and must never be
described as though it were (`07.5-VERIFICATION.md` Round 2 NEW-1).

**Worker deploy invocations after plan 07.5-12** — assets-only, no `--var`, one route each:

```bash
wrangler deploy --routes "$PUBLIC_APEX_DOMAIN/admin*"      # from apps/admin
wrangler deploy --routes "*.$PUBLIC_APEX_DOMAIN/qr*"       # from apps/qr-menu
```

Cloudflare's routing rules, quoted from the current page
(`[CITED: developers.cloudflare.com/workers/configuration/routing/routes/]`, fetched 2026-09-05):
*"The only supported operator is the wildcard (`*`)"*; *"the most specific route pattern wins"*;
*"A route can be specified without being associated with a Worker. This will act to negate any less
specific patterns"*; and *"`*.example.com/` matches `https://www.example.com/` but not
`https://example.com/`"* — so the `*.<apex>/qr*` route never touches the apex and the
`<apex>/admin*` route never touches a tenant host. The two Workers cannot collide.

**Boot failure signature to recognise instantly:** the api container exiting immediately with
`ProdGuardrailsError` naming `STRIPE_SECRET_KEY`, `RESEND_API_KEY`, `RESEND_FROM` or
`RESEND_REPLY_TO` is Pitfall #10 plus plan 06's dev-default guard — the fix is credentials, not
Docker networking or Postgres connectivity.

**What `verify-prod-origin.sh` can and cannot see.** `X-Resto-Cache` no longer exists: plan 07.5-12
deleted the Workers that emitted it, and Cloudflare's own `cf-cache-status` replaces it. But the
Cache Rule that makes `/v1/menu` cacheable at all is deliberately **not** created until plan
07.5-10, so at this plan's `--stage full` the cache header is recorded and printed, never asserted.
Assertion on it here would be a check that must fail for a reason unrelated to anything this plan
does.

    - `nc -z -w3 <vps-ip> 5432` and `4222` both fail.
