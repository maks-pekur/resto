<objective>
Close the four code-side gaps that must ship before a public URL exists, in a single pre-provisioning wave: (D-05) route the outbox dispatcher's advisory-lock connection through a direct, unpooled, session-pinned Postgres connection separate from the pooled app path; (G-03) extend `/readyz` to detect a silently-stalled or dead outbox leader; (G-04) wire an error tracker (Sentry) so a solo founder gets push alerts instead of waiting for a customer report; (G-05) make the website + admin web layers fail loud on a missing/localhost API origin in production.

Purpose: Each of these is a "fly blind in prod" risk the persona reviews escalated. The advisory lock currently reserves a connection from the same pool the request path uses (`db.connection.raw.reserve()`); on a pooler in transaction mode that connection is not session-pinned and the lock is unsafe (CTO Neon-pooler caveat). `/readyz` checks DB + broker reachability but never leader liveness or dispatch lag — a wedged leader queues paid-order/email/audit events invisibly. No Sentry exists. The web-layer localhost fallbacks go live in exactly this phase.

Output: Direct-connection outbox lock + leader-aware `/readyz` + Sentry init in api (and website/admin) + fail-loud web env. New envs: `DATABASE_DIRECT_URL`, `SENTRY_DSN`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pooler → app request path | DATABASE_URL pooled; safe for short-lived queries |
| direct conn → outbox leader | DATABASE_DIRECT_URL unpooled/session-pinned; the only safe place for the advisory lock |
| app → Sentry ingest | unhandled-exception payloads cross to a third-party error tracker |
| browser ← web env | API origin baked/injected into client-reachable config |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-075-03-01 | Denial of Service | outbox advisory lock on a pooled conn | mitigate | Lock moves to DATABASE_DIRECT_URL (unpooled, session-pinned); pooler-released zombie-lock class eliminated |
| T-075-03-02 | Repudiation | silently stalled outbox leader | mitigate | /readyz returns 503 on leader staleness → LB drains the wedged instance instead of serving while events queue invisibly |
| T-075-03-03 | Information Disclosure | Sentry event payloads leaking PII/secrets | mitigate | Sentry init scrubs default PII; do not attach request bodies; existing logger redact (password/token/email/phone) sets the precedent — keep beforeSend conservative |
| T-075-03-04 | Spoofing | web layer routing users to a localhost/attacker origin | mitigate | G-05 fail-loud: production build/boot crashes on missing-or-localhost API origin; no silent fallback |
| T-075-03-SC | Tampering | npm install of @sentry/* | mitigate | Task-0 blocking-human legitimacy checkpoint verifies all three @sentry packages on npmjs.com before install; never auto-approved |
</threat_model>
