## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `import.meta.url.endsWith()` crash in openapi.ts at CJS bundle init**

- **Found during:** Task 1 — local docker boot test
- **Issue:** `openapi.ts` top-level guard `import.meta.url.endsWith(process.argv[1])` ran at bundle init time. esbuild rewrites `import.meta` to `{}` so `import_meta2.url` is `undefined`; calling `.endsWith()` on it throws `TypeError: Cannot read properties of undefined` before any module finishes loading.
- **Fix:** Cast to `(import.meta as { url?: string }).url` and apply optional chain
- **Files modified:** `apps/api/src/openapi.ts`
- **Commit:** 98a84e0

**2. [Rule 1 - Bug] `fileURLToPath(import.meta.url)` crash in preflight.ts during `init_preflight()`**

- **Found during:** Task 1 — local docker boot test
- **Issue:** `findWorkspaceRoot` was called with `dirname(fileURLToPath(import.meta.url))`. In CJS `import.meta.url` is `undefined`; `fileURLToPath(undefined)` throws. `assertWithoutTenantCallsiteRegistered` is called from `main.ts` at boot, triggering `init_preflight()`.
- **Fix:** Same cast pattern; `findWorkspaceRoot` returns `string | null`; `assertWithoutTenantCallsiteRegistered` skips the FS check when `WORKSPACE_ROOT === null` (bundled/Docker context where source files don't exist on disk — the ESLint call-site fence enforced this at build time)
- **Files modified:** `packages/db/src/preflight.ts`
- **Commit:** 98a84e0

**3. [Rule 1 - Bug] `Cannot find module 'nats'` — pnpm virtual-store hoisting gap**

- **Found during:** Task 1 — first docker boot attempt
- **Issue:** pnpm does NOT hoist `nats` to top-level `node_modules/` — it lives only under `.pnpm/nats@2.29.3/node_modules/nats` in the virtual store, which Node's CJS resolver cannot traverse. The Docker image copies `node_modules/` but the symlink chain is broken for packages not directly in the app's own dependency closure.
- **Fix:** Removed `nats` from the `NESTJS_OPTIONAL_PEERS` external list in `build.mjs` and added a special-case to the `externalize-non-workspace` esbuild plugin to bundle `nats`, `nkeys.js` (nats's only runtime dep), and `tweetnacl` (nkeys.js's dep) inline. All three are pure-JS with no native addons — safe to bundle.
- **Bundle size impact:** 560 KB → 1.1 MB (nats + nkeys.js + tweetnacl total ~540 KB minified)
- **Files modified:** `apps/api/build.mjs`
- **Commit:** 98a84e0

**4. [Rule 3 - Blocking] TypeScript ambient module declaration not visible across tsconfig boundaries**

- **Found during:** Task 1 — pre-commit typecheck
- **Issue:** `sql.d.ts` declares `declare module '*.sql'`. Triple-slash `/// <reference path>` directives were used initially but are disallowed by `@typescript-eslint/triple-slash-reference`. The ambient declaration must be in the compilation unit of every tsconfig that transitively compiles files doing `import SQL from '*.sql'`. Three tsconfigs needed updating: `packages/db`, `packages/events` (imports `@resto/db`), `apps/api` (imports `@resto/db`).
- **Fix:** Added `src/**/*.d.ts` to `packages/db/tsconfig.json`; added `../../packages/db/src/sql.d.ts` to `apps/api/tsconfig.json`; added `../db/src/sql.d.ts` to `packages/events/tsconfig.json`.
- **Files modified:** `packages/db/tsconfig.json`, `apps/api/tsconfig.json`, `packages/events/tsconfig.json`
- **Commit:** 98a84e0

**5. [Rule 2 - Missing CI script] `provision-roles-ci.ts` needed for CI Postgres role setup**

- **Found during:** Task 2 — CI job design
- **Issue:** The CI docker-api job needs `resto_app` and `resto_auth` Postgres roles provisioned before the Docker container can run its preflights. No existing script could be invoked without the full dev setup.
- **Fix:** Created `packages/db/src/cli/provision-roles-ci.ts` — minimal script that calls `provisionAppRole` + `provisionAuthRole` against the CI Postgres service container using admin credentials, then exits.
- **Files modified:** `packages/db/src/cli/provision-roles-ci.ts` (new)
- **Commit:** 98a84e0
