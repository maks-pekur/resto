<objective>
Redesign the payments/order/tenant money-path data model FIRST, before any Stripe adapter
work (D-07). Today `payments` has a single nullable `provider_payment_id`, no
`refunded_amount`, no `stripe_account_id`; `Order.refund()` is full-only; the order status
machine has no SCA `requires_action` state; the tenant aggregate has only `stripeAccountId`
(no capability flags to gate money on); and `orders` has `customer_name`/`customer_phone`
but NO guest email (B2 — the email surface in 08-06 has no recipient to send to). Every later
slice (adapter, webhooks, checkout, refunds, emails) writes into this model — getting it right
now avoids a painful mid-phase migration over real payment rows.

Purpose: Make the schema able to represent the truth the money path requires —
partial refunds, N PaymentIntents per order, SCA `requires_action`, Stripe-account linkage,
fee capture, a server-authoritative "can this tenant accept money?" capability state, and a
guest-email column for order/refund notifications (erasure-covered because orders rows are
hard-deleted in tenancy_erase_tenant).
Output: migration 0055, redesigned Drizzle schema, a partial-capable `Order` aggregate,
a new `Payment` aggregate concept (refund accounting invariant), tenant capability fields,
and `orders.customer_email`.
</objective>
