<objective>
Build the net-new guest-notification surface (D-13) over the existing Resend transport.
Today `EmailAdapterPort` has only the three auth methods (sendInvitation/Reset/Verification);
there is no guest email, no order/refund template, no brand theming. Add a `notifications`
context with a NATS subscriber that consumes the Phase-8 payment events and fires
brand-themed, per-locale guest emails: GNOTIF-01 (confirmation on
payments.order_payment_succeeded.v1) and GNOTIF-03 (refund on payments.order_refunded.v1)
fire NOW; GNOTIF-02 (accepted + ready/on-its-way) machinery + templates are BUILT now and
subscribed to ordering.order_status_changed.v1 but only ACTIVATE when the Phase 10 operator
transitions emit that event (cross-phase — explicitly documented). The recipient is
`orders.customer_email` (added in 08-01, persisted at checkout in 08-04b) — no open unknown.
The new subscriber configures `max_deliver` plus a `dlq` subject (B4/AUTH-10), cloned
faithfully from the audit subscriber, so a poison message never stalls the consumer. Because
`runDeduped` guards only the DB write, emails carry their own per-(order, transition)
send-once marker so a redelivered event never double-sends (D-10/D-13).

Purpose: close the guest-comms loop on the money path with brand-correct, idempotent,
DLQ-protected emails without rewriting the Resend transport.
Output: GNOTIF-01/02/03/04 + a guest-notification email port method on the existing adapter.
</objective>
