<objective>
Build the Stripe webhook ingestion as a new lean `payments` bounded context: a @Public
raw-body route at /webhook/stripe that verifies the signature (400 on invalid), then
dispatches each event inside `runDeduped` keyed on the Stripe event id. Handle the five
events from D-10: account.updated, payment_intent.succeeded, payment_intent.payment_failed,
charge.refunded/refund.updated, charge.dispute.created (the last two are RECORDED here and
fully wired in 08-05). The webhook is the SINGLE writer of `paid` (CTO HIGH #4): the browser
confirmation page (08-04b) only polls. Out-of-order/replayed events are tolerated; an
account-scoped event for an unregistered account is a benign no-op (W3); and the
double-charge guard (D-06) flags a late-succeeding orphan PaymentIntent on an already-paid
order for auto-refund.

Purpose: a money-correct, idempotent, signature-verified webhook is the spine that drives
order state. `runDeduped` guards the DB transition only — external side effects (refund,
email) carry their own idempotency (D-09 keys + 08-06 email dedup).
Output: PAY-04/05/07/08/10 + the payment-event contracts that 08-04a/05/06 consume.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stripe → /webhook/stripe | unauthenticated public endpoint; only Stripe-signed payloads are trusted |
| webhook event → order/payment state | event id replay + out-of-order delivery must not corrupt money state |
| account-scoped event → tenant resolution | an unknown/unregistered account must not throw or corrupt state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-13 | Spoofing | forged webhook payload | mitigate | constructEvent signature verify against RAW body; 400 on invalid; raw-body parser scoped to the route so bytes match (PAY-04, D-10) |
| T-08-14 | Tampering/replay | replayed/duplicated event id | mitigate | runDeduped keyed on Stripe event.id → at-most-once DB transition (PAY-10) |
| T-08-15 | Tampering | out-of-order failed-after-succeeded clobber | mitigate | failed handler never transitions an already-paid order; markPaid create/requires_action-only guard |
| T-08-16 | Tampering/financial | double-charge from late orphan PI | mitigate | orphan succeeded on a paid order → idempotent auto-refund (D-06); deterministic refund idempotency key |
| T-08-17 | Information disclosure | cross-tenant write inside BYPASSRLS tx | mitigate | handler filters every write by tenantId resolved from event.account/metadata (runDeduped runs system-context — ADR-0020 I-1) |
| T-08-18 | DoS | webhook in the public 429 bucket drops retries | mitigate | route exempt from per-tenant rate-limit + CORS allowlist |
| T-08-18b | DoS | unregistered-account event triggers infinite Stripe retry / throws | mitigate | account-not-found is a logged no-op returning 200 (W3) — no throw, Stripe stops retrying |
</threat_model>
