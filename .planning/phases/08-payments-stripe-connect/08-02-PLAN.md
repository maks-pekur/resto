Replace `NoopStripeConnectAdapter` with a real Stripe Connect Express adapter implementing
an expanded `StripeConnectPort`, plus the onboarding service + controller. Use the Resend
adapter as the reference implementation for the failure model (bounded retry with jitter,
hard timeout via Promise.race, idempotency keys threaded into the SDK call). Charge model is

refund) with money-correct idempotency before the webhook + checkout slices wire it in.

Stripe node SDK specifics (verified via Stripe docs, 2026-06):
- Direct charge: stripe.paymentIntents.create({ amount, currency, application_fee_amount, … }, { stripeAccount: connectedAccountId, idempotencyKey }).
  On a DIRECT charge the connected account bears Stripe fees + dispute liability; application_fee transfers to the platform.
- Onboarding: stripe.accounts.create({ type: 'express', … }) then stripe.accountLinks.create({ account, refresh_url, return_url, type: 'account_onboarding' }).
- Refund: stripe.refunds.create({ payment_intent | charge, amount, reason }, { stripeAccount, idempotencyKey }).
- Cancel: stripe.paymentIntents.cancel(id, undefined, { stripeAccount, idempotencyKey }).
