## Spacing Scale

Standard 8-point scale — inherits Tailwind 4 defaults. No custom token overrides needed.

| Token | Value                 | Usage                                                                   |
| ----- | --------------------- | ----------------------------------------------------------------------- |
| xs    | 4px (`gap-1`)         | Icon gaps, inline badge padding                                         |
| sm    | 8px (`gap-2`, `p-2`)  | Compact table cell padding, helper text margin                          |
| md    | 16px (`gap-4`, `p-4`) | Default form field spacing, card inner padding                          |
| lg    | 24px (`gap-6`, `p-6`) | Section card padding, editor section headers                            |
| xl    | 32px (`gap-8`)        | Layout column gaps                                                      |
| 2xl   | 48px (`py-12`)        | EmptyState vertical padding (matches existing `<EmptyState>` component) |
| 3xl   | 64px                  | Page-level top spacing (unused in this phase)                           |

Exceptions:

- Table row height: 48px (`h-12`) — thumbnail rows in items list require this height to show 40px thumbnails with 4px padding each side.
- Touch target minimum: 44px (`min-h-11`) — stop-list switch column, action icon buttons in table rows.
- Sticky publish bar: `h-14` (56px) — enough room for copy + two buttons without feeling cramped.

These are layout-height constraints (touch target, sticky bar height), not spacing tokens — do not use them for gap/padding/margin.

## Color

Color tokens are the existing `globals.css` oklch variables — no new tokens required in this phase. One semantic extension needed for status badges (see below).

| Role            | CSS token             | Approximate hex                        | Usage                                                        |
| --------------- | --------------------- | -------------------------------------- | ------------------------------------------------------------ |
| Dominant (60%)  | `--background`        | `#ffffff` (light)                      | Page background, content area                                |
| Secondary (30%) | `--card`, `--sidebar` | `#f9f9f9` / `#fafafa`                  | Editor section cards, sidebar, table stripe                  |
| Accent (10%)    | `--primary`           | `#1a1a1a` (neutral near-black)         | Primary action buttons only — `Publish`, `Save`, primary CTA |
| Destructive     | `--destructive`       | `oklch(0.577 0.245 27.325)` ~`#dc2626` | Archive confirmation button only                             |

**Accent reserved for:** the `Опубликовать меню` button in the sticky publish bar, the primary submit button in category / item / modifier group editors, and the `+ Add` buttons that open a new entity form. Nothing else.

### Status badge color semantics

shadcn `Badge` component uses `variant` prop. The following mapping implements D-09 decisions:

| Status          | Badge variant                                    | Visual result              | Rationale                                                                                                                               |
| --------------- | ------------------------------------------------ | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `draft`         | `outline`                                        | Border-only, no fill       | Default unsaved state — low visual weight                                                                                               |
| `modified`      | `outline` + amber inline style                   | Amber/yellow border + text | Warning signal without destructive weight — requires a thin `className` override: `border-amber-500 text-amber-700 dark:text-amber-400` |
| `published`     | `default`                                        | Filled primary (dark)      | Clear success state — most items will be in this state                                                                                  |
| `paused` / Стоп | `secondary`                                      | Muted grey fill            | Operational pause — NOT destructive per D-09 / GM-MED-1                                                                                 |
| `archived`      | `ghost` (or `outline` + `text-muted-foreground`) | Very low contrast          | Effectively hidden from default filter; dim treatment reinforces that                                                                   |

Note: `modified` badge has no dedicated shadcn variant. Implement as `Badge variant="outline" className="border-amber-500 text-amber-700 dark:border-amber-400 dark:text-amber-400"`. No new CSS variables needed.

**`AI-оценка` badge** (shown when `nutrition_estimated = true` next to БЖУ fields): use `Badge variant="secondary"` with `className="text-xs"` — intentionally low-weight to not distract from the nutrition values themselves.

**"Stop active >24h" warning:** inline `<p className="text-amber-700 dark:text-amber-400 text-xs mt-1">` next to the stop badge — no separate Badge component, just a helper text line.

## Page Layout Contracts

### Shell chrome (inherited, no changes)

Every catalog page follows the existing pattern from `settings/page.tsx`:

```
<header h-16 flex items-center gap-2 px-4>
  <SidebarTrigger -ml-1 />
  <Separator vertical h-4 />
  <TenantBreadcrumb trail="..." />
  [optional: page-level actions flush right]
</header>
<div flex flex-1 flex-col gap-4 p-4 pt-0>
  {children}
</div>
```

### Sidebar extension (D-01)

Add to `navMain` array in `app-sidebar.tsx`:

```typescript
{
  title: 'Меню',
  url: '/dashboard/menu/items',
  icon: UtensilsCrossed,  // lucide-react
  scope: 'brand',
  isActive: false,  // collapsed by default
  items: [
    { title: 'Категории', url: '/dashboard/menu/categories' },
    { title: 'Блюда', url: '/dashboard/menu/items' },
    { title: 'Модификаторы', url: '/dashboard/menu/modifier-groups' },
    { title: 'Стоп-лист', url: '/dashboard/menu/stop-list' },
  ],
}
```

Scope: `brand` — hidden until active brand is selected (same gate as other brand-scoped items).

### Categories page (`/dashboard/menu/categories`)

Layout: single-column list. No search required (categories are few). Header row: breadcrumb + `+ Создать категорию` Button (primary, flush right).

Table columns: `[drag-handle or ↑↓ buttons] | Название | Родитель | Позиция | [edit icon] [archive icon]`

Visual indent for child categories: 16px left padding on the row (`pl-4`) + `↳` text prefix in the name cell. Parent rows show plain name. Two levels max; frontend disables the parent selector when the selected parent is itself a child.

Empty state: `<EmptyState variant="empty" title="Категории не добавлены" description="Добавьте первую категорию, чтобы сгруппировать блюда в меню." action={<Button>Создать категорию</Button>} />`

Reorder: up/down button pair per row (simpler than drag-drop for MVP-1; drag-drop deferred per D-4b-01). Buttons hidden on single-item lists.

### Items list page (`/dashboard/menu/items`)

Layout: filter bar + table.

Filter bar (flex row, `gap-2`, `mb-4`): `[search input placeholder="Поиск блюд…" w-64]` `[Select category — indented options]` `[Select status]` `[+ Добавить блюдо Button primary flush right]`

Default filter: status NOT archived (draft + published + paused visible). Status filter shows "Все кроме архива" as default label.

Table columns:

| Column   | Width  | Notes                                                                                                |
| -------- | ------ | ---------------------------------------------------------------------------------------------------- |
| Photo    | 48px   | `<img className="size-10 rounded object-cover" />` or placeholder `bg-muted rounded` with image icon |
| Название | flex-1 | Name + category path under it in `text-xs text-muted-foreground` (e.g., `Напитки → Кофе`)            |
| Цена     | 80px   | Base price or "от N₽" if sizes exist                                                                 |
| Статус   | 100px  | Status badge (see color semantics above)                                                             |
| Стоп     | 60px   | Switch; click = instant publish (no confirm)                                                         |
| Actions  | 60px   | DropdownMenu: Edit / Archive                                                                         |

Row click → navigate to `/dashboard/menu/items/[id]` (same as Edit action).

### Item editor page (`/dashboard/menu/items/[id]`)

URL: `/dashboard/menu/items/[id]` and `/dashboard/menu/items/new`

Layout:

```
<header>  [breadcrumb: Меню > Блюда > {name}]  [AutoSaveIndicator right]
<div flex flex-col gap-4 p-4 pt-0>
  <Tabs defaultValue="detail">
    <TabsList>
      <TabsTrigger value="detail">Детали</TabsTrigger>
      <TabsTrigger value="sizes">Размеры</TabsTrigger>
      <TabsTrigger value="modifiers">Модификаторы</TabsTrigger>
    </TabsList>
    <TabsContent value="detail">   {ItemDetailTabClient}   </TabsContent>
    <TabsContent value="sizes">    {ItemSizesTabClient}    </TabsContent>
    <TabsContent value="modifiers">{ItemModifiersTabClient}</TabsContent>
  </Tabs>
</div>
```

**Detail tab layout (two-column on md+, single-column on mobile):**

Left column (flex-1): Название (required), Описание (textarea), Категория (Select with indented options), Цена (Input number), Раздел БЖУ (see below), Аллергены (multi-chip or comma-separated text input), Артикул/Slug (read-only, shown as helper text under name field — auto-generated from name).

Right column (w-64 or w-72): Photo upload area (drag-drop + click-to-browse — see photo upload spec below).

**БЖУ section:** Four inputs in a single row with labels: `Б` `Ж` `У` `ккал`. Below the row: `text-xs text-muted-foreground "на 100 г"`. When `nutrition_estimated = true`: `Badge variant="secondary" className="text-xs ml-2"` with text `AI-оценка` placed inline after the "на 100 г" label.

**Sizes tab layout:**

Inline editable rows. Each row: `[Name Input]` `[Price Input (number)]` `[Default toggle — radio-like, only one active]` `[× remove Button ghost]`.

Row grid: `grid-cols-[1fr_120px_80px_40px] gap-2 items-center`.

Below rows: `+ Добавить размер` Button (variant="outline", size="sm").

Empty state: helper text `"Нет размеров — блюдо использует базовую цену."` in `text-sm text-muted-foreground`. No full `<EmptyState>` component needed — inline helper text is sufficient.

**Modifiers tab layout:**

Section title: "Группы модификаторов для этого блюда". Below: chip list of already-assigned modifier groups (each chip: name + `× remove`). Below chips: `+ Добавить группу` Button (variant="outline") opens a Sheet side-panel with a searchable list of existing modifier groups for the current brand. Each group in the sheet list has a "+ Добавить" action button.

Quick-create in Sheet: `+ Создать новую группу` link at bottom of sheet → opens a modal form (Dialog) with just name + min/max fields; on save, redirects to `/dashboard/menu/modifier-groups/[id]` for full editing.

### Modifier groups list page (`/dashboard/menu/modifier-groups`)

Same structure as items list. Table columns:

| Column         | Notes                           |
| -------------- | ------------------------------- |
| Название       | Group name                      |
| Мин / Макс     | e.g., `0–3`                     |
| Вариантов      | Count of options                |
| Используется в | Count of items using this group |
| Actions        | Edit / Archive                  |

Empty state: `<EmptyState variant="empty" title="Нет групп модификаторов" description="Создайте первую группу, чтобы добавлять дополнения к блюдам." action={<Button>Создать группу</Button>} />`

### Modifier group editor page (`/dashboard/menu/modifier-groups/[id]`)

Two sections in a Card layout (no Tabs needed — simpler):

1. **Основное** card: Название (required), Минимум выбора (number 0–99), Максимум выбора (number 0–99, 0 = unlimited).

2. **Варианты** card: inline table of options. Each row: `[Название]` `[Наценка (+N₽)]` `[По умолчанию (amount)]` `[Бесплатно (amount)]` `[× remove]`. The default_amount and free_amount fields are for iiko alignment — display them as small number inputs with `size="sm"`; their labels can be abbreviated to "По ум." and "Бесп." with tooltips explaining the full meaning. Below rows: `+ Добавить вариант` Button.

### Stop-list page (`/dashboard/menu/stop-list`)

Two sections:

**Today's 86 widget** (Card at top): header "Стоп-лист сегодня" + count badge + `Сбросить всё` Button (variant="outline destructive" — secondary styling, not primary destructive because this is a recovery action, not a delete). Show `text-sm text-muted-foreground "Всё остановленные позиции будут возобновлены."` as helper text.

**Stop-list table**: same structure as items table but filtered to paused items only. Switch column shows ON state. Additional: next to the status badge, if the item has been stopped for >24h, show `text-xs text-amber-700 "Остановлено 36ч"` as inline helper text below the badge.

Empty state (no stopped items): `<EmptyState variant="empty" title="Стоп-лист пуст" description="Все позиции в меню сейчас доступны для заказа." />`

## Photo Upload Spec (CAT-03)

Component: `PhotoUploadClient`

Visual: a rectangular drop zone, `rounded-lg border-2 border-dashed border-input bg-muted/40` with dimensions `w-full h-48` (on mobile) / `w-64 h-48` (on desktop right column). Inside when empty: centered column with `ImageIcon` (lucide, `size-8 text-muted-foreground`) + `text-sm text-muted-foreground "Нажмите или перетащите фото"` + `text-xs text-muted-foreground/70 "JPG, PNG, WEBP до 5 МБ"`.

Implementation: native `<input type="file" accept="image/*" className="sr-only" />` + `<label>` wrapping the visual zone. No external drag-drop library — HTML5 `dragover`/`drop` events sufficient for single-file upload.

After file selected / dropped: show `<img src={objectURL} className="w-full h-full object-cover rounded-lg" />` inside the zone. Overlay: `"Изменить фото"` ghost button at bottom-right corner of the image.

Upload flow: client calls server action → server action gets presigned PUT URL from api → client PUTs directly to S3 → server action saves resulting `s3Key` to draft. Show upload progress via a thin `<Progress>` bar below the drop zone while PUT is in flight. On error: replace progress with `text-destructive text-xs "Не удалось загрузить — попробуйте ещё раз"` + retry button.

"Добавить ещё фото" button: rendered as `Button variant="ghost" size="sm" disabled` with `Tooltip` content `"Несколько фото — в следующей версии"`. This communicates the v2 limitation without hiding the affordance.

## Auto-Save Indicator Spec (D-4b-02)

Component: `AutoSaveIndicator` — placed in the item editor page header, flush right, before any other header actions.

States:

| State                     | Display                                                                                    |
| ------------------------- | ------------------------------------------------------------------------------------------ |
| Idle (no unsaved changes) | Hidden (renders nothing)                                                                   |
| Saving                    | `text-xs text-muted-foreground "Сохранение…"`                                              |
| Saved (within last 60s)   | `text-xs text-muted-foreground "Сохранено 2с назад"` (or "1м назад")                       |
| Failed                    | `text-xs text-destructive "Не сохранено — " + Button variant="link" size="xs" "повторить"` |

Implementation: `react-hook-form` `watch()` triggers a 1.5s debounced `setTimeout`. On timer fire, call server action. State tracked in local `useState`: `idle | saving | saved(timestamp) | failed`. Time display: simple string formatter (no external library) — show seconds if <60s, "Xм назад" if <60m, "Xч назад" otherwise.

## Sticky Publish Bar Spec (D-09, D-4b-03)

Component: `StickyPublishBar` — mounted in the `/dashboard/menu` route segment layout (not the global dashboard layout). Only visible when the operator is on a `/dashboard/menu/*` route.

Position: `fixed bottom-0 left-[--sidebar-width] right-0 z-40` (accounts for sidebar width via CSS variable). Height: 56px (`h-14`).

Background: `bg-card border-t border-border shadow-lg` — light mode white with top border.

Content (flex row, `items-center px-6 gap-4`):

- `<span className="text-sm font-semibold">N неопубликованных изменений</span>` (N = count from api draft-diff)
- `<Button variant="ghost" size="sm" onClick={toggleDiffList}>Показать ▾</Button>` — expands inline diff list above the bar (animated, `max-h-0 → max-h-64 overflow-auto`)
- Right side flush: `<Button variant="default" size="sm">Опубликовать меню</Button>`

When diff count is 0: bar is hidden (`display: none` / conditional render).

When a publish is in flight (5s timer active): `Опубликовать меню` button is `disabled` with `Tooltip` content `"Публикация через 5с — нажмите Отменить"`.

Diff list items (expanded): grouped by entity type. Each item: `[EntityTypeIcon] Название (статус-badge)`. Max height 256px with scroll. No pagination in the list.

## Delayed-Publish Toast Spec (D-4b-03)

Triggered by: click `Опубликовать меню` → success response from `POST /internal/v1/catalog/publish`.

Custom Sonner toast content:

```
[row 1] "Публикация через 5с"   [Отменить Button variant="ghost" size="sm"]
[row 2] <Progress value={secondsElapsed / 5 * 100} className="h-1 mt-2" />
```

Implementation: `sonner.toast.custom(id, ...)` with a React component. The component holds a `useEffect` with a `setInterval(100ms)` updating `secondsElapsed` state. On unmount (or when `secondsElapsed >= 5`), clear interval. Width: Sonner default (`360px`).

Post-publish toast: plain `sonner.toast.success("Опубликовано")` replacing the countdown toast.

Cancel success: plain `sonner.toast.success("Публикация отменена")`.

Already-published (undo window expired): plain `sonner.toast.info("Уже опубликовано — окно отмены истекло")`.

Network error: `sonner.toast.error("Не удалось опубликовать — проверьте соединение")`.

## Interaction Contracts

### Stop-list switch (D-11, D-12)

- Click switch ON → immediate `PATCH /internal/v1/catalog/stop-list` → switch shows loading state (opacity-50 pointer-events-none) during request → on success, status badge updates to `paused` with `Стоп` copy → Sonner toast `"Блюдо добавлено в стоп-лист"` (1.5s auto-dismiss).
- Click switch OFF → same flow → badge returns to `published` → Sonner toast `"Блюдо возобновлено"`.
- Error: switch snaps back to previous state + Sonner error toast.

### Category depth enforcement (D-4b-01)

In category create/edit form, the Parent select dropdown: when a category is already a child (has its own `parent_id`), its option is `disabled` in the Select. Label for disabled options: `"— нельзя выбрать как родителя (уже является подкатегорией)"`. Tooltip on hover of disabled option.

Additionally, Zod schema client-side: `parent_id` field carries `.refine()` that rejects IDs of categories that are themselves children — matching the server-side constraint.

### Auto-save debounce (D-4b-02)

- `react-hook-form` `watch()` subscribes to all fields in the editor.
- Each field change: clear existing `setTimeout`, start new 1.5s `setTimeout`.
- On timer fire: call server action with full current form values.
- Indicator transitions: idle → saving → saved / failed.
- Tab switching does NOT trigger a save (tabs switch the view; the form remains mounted). Save is field-change driven only.

### Publish flow (D-4b-03)

1. Operator clicks `Опубликовать меню` in sticky bar.
2. Button goes `disabled` + shows spinner (1 frame before POST response).
3. POST `/internal/v1/catalog/publish` fires.
4. On 2xx: sticky bar button stays disabled + shows `"Публикация через 5с"` text. Sonner custom countdown toast appears bottom-right.
5. On non-2xx: Sonner error toast. Button re-enables.
6. If operator clicks `Отменить` in toast within 5s: DELETE `/internal/v1/catalog/publish`. On 2xx: success toast. Sticky bar re-enables + shows dirty count. On non-2xx (already published): info toast.
7. On 5s elapse: Sonner toast transitions to `"Опубликовано"` success (auto-dismiss 3s). Sticky bar hides (diff count = 0).

### Item editor navigation

Row click in items table: uses Next.js `<Link>` wrapping the row (or navigate programmatically via `router.push`). No Sheet/modal — full page navigation per D-04.

Back navigation from item editor: breadcrumb `Блюда` link returns to items list. Browser back works naturally.

New item: `/dashboard/menu/items/new` → server action creates a stub item with blank name (or pending/draft ID) on first auto-save trigger → URL updates to `/dashboard/menu/items/[id]` via `router.replace`.

## Accessibility Contracts

- All form inputs have associated `<Label htmlFor={...}>` per existing pattern.
- Switch component: `aria-label="Добавить в стоп-лист"` / `aria-label="Убрать из стоп-лист"` on the Switch element.
- Status badges: `aria-label` on the badge itself when status is not obvious from context, e.g., `aria-label="Статус: В стопе"`.
- Sticky publish bar: `role="region" aria-label="Управление публикацией"`.
- CountdownToast: `aria-live="polite"` on the countdown element so screen readers announce the time remaining.
- AlertDialog: uses Radix AlertDialog primitive — focus trap + `aria-describedby` + `aria-labelledby` handled automatically.
- Table: `<table>` with `<thead>`, `<th scope="col">`, `<td>` — do not use `role="grid"` on a data table.
- Photo drop zone: `<label>` wrapping the visual zone with `htmlFor` matching the hidden `<input type="file">`. Zone has `role="button" tabIndex={0}` with keyboard handler for Enter/Space to open file dialog.
- DropdownMenu trigger in the Actions column of every table (Items, Categories, Modifier Groups) must carry `aria-label="Действия с {name}"` where `{name}` is the row's display name (category name, item name, modifier group name). If the row name is not available in context, fall back to `aria-label="Действия"`.
