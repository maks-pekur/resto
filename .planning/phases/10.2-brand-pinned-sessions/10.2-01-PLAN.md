  <action>
Create `packages/domain/src/country.ts` implementing decisions D-32, D-33, D-35 and D-38.

Exports, exactly these names (downstream plans reference them verbatim):

- `CountryCodeValue` — `z.enum(['UA', 'GB', 'ES'])` (D-33 order: UA, GB, ES). Unbranded on purpose:
  it crosses the HTTP boundary in the signup DTO, and a branded schema emits `type: unknown` in the
  `nestjs-zod` OpenAPI output (ADR-0020 I-7). Derive the type with `z.infer`, never hand-write it.
- `SUPPORTED_COUNTRIES` — `readonly CountryCodeValue[]` in D-33 order, used by the admin `Select`.
- `CountryConfig` — interface with `readonly currency: CurrencyValue` (imported from `./money`) and
  `readonly defaultLocale: string`.
- `COUNTRY_REGISTRY` — `Readonly<Record<CountryCodeValue, CountryConfig>>` with exactly:
  `UA -> { currency: 'UAH', defaultLocale: 'ru' }`,
  `GB -> { currency: 'GBP', defaultLocale: 'en' }`,
  `ES -> { currency: 'EUR', defaultLocale: 'es' }`.
- `currencyForCountry(country)` and `defaultLocaleForCountry(country)` — total functions over the
  registry, no fallback branch needed because the record is exhaustive over the enum.

WHY-comment required on the `UA -> 'ru'` entry only (per D-38 and RESEARCH Pitfall 6): `apps/admin`
ships `ru`/`en` and gains `es` in this phase but never `uk`, so mapping UA to `uk` would render a
langSwitcher showing Ukrainian selected while every string falls back to Russian. Keep every default
locale inside the `{ru, en, es}` intersection of what both apps ship. Do not add `uk` to the registry.

No Zod wrapper on `COUNTRY_REGISTRY` itself — it is a compile-time-closed catalogue, matching
`reserved-slugs.ts` and `rbac/permissions.ts`. Only the _input_ `CountryCodeValue` needs Zod.

Zero infrastructure imports: `zod` and `./money` only.

Add to the `packages/domain/src/index.ts` barrel, in the same block as the `money`/`reserved-slugs`
re-exports: `COUNTRY_REGISTRY`, `CountryConfig`, `CountryCodeValue`, `SUPPORTED_COUNTRIES`,
`currencyForCountry`, `defaultLocaleForCountry`.
</action>
