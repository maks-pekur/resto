## Decisions Made

See `key-decisions` in frontmatter for full rationale. Summary:

1. Deleted `findReachableBrandsForMember` (port + implementation) rather than leaving a stub — zero live
   callers, no data model left to back it, and leaving inert-but-live dead code runs against this phase's
   own deletion philosophy (D-39's spirit, applied here to a sibling dead method). Cascaded into 4 spec
   files' mock literals (one-line removal each).
2. Kept `brandId` in `findPinnableLocations`'/`PinnableLocation`'s port shape unchanged — its only live
   caller (`set-active-location.controller.ts`) is out of Task 0a's scope and was green before this plan
   touched anything; touching the port there would have turned it red. Deleted the brand-scoping SQL
   predicate instead and echo `input.brandId` back into the return rows to preserve the compile contract.
3. `initial-location-drizzle.repository.ts`'s unbound-tenant fallback: relies on D-01 (brand merged 1:1
   into tenant) to treat the caller-supplied id directly as the tenant id, removing the now-impossible
   `brands` lookup query entirely rather than leaving a broken translation step.
4. Traced (read-only) `identity-core.module.ts`/`auth.config.ts` to confirm the `onInitialLocationPin` hook
   this repository feeds is currently unreachable at runtime (plan 08 already zeroed `onInitialBrandPin`,
   which gates it). Fixed the repository correctly anyway rather than leaving a "doesn't matter, it's dead"
   shortcut, since 10.2-08-SUMMARY.md flags plan 12 as the owner of reviving/rewriting this hook.
5. Fixed `member.organizationId` → `member.tenantId` in both files even though F-24 only named
   `brands`/`brandId` — this was the sole remaining `member.organizationId` reference in all of
   `apps/api/src` (verified by grep), and without the fix the files could not compile, making it a hard
   blocker to Task 0a's own acceptance criterion. Did not touch the 9 other identity files still carrying
   the same pattern (pre-existing D-41 breakage, plan 21's territory).
