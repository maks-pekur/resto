# Phase 10.2 Plan 11: Location-scope reader repair, dead-activeBrandId fix, and brand-decorator deletion Summary

> **Tasks 0a, 0, 0b, 1, 2 are DONE.** Task 3 (`type="checkpoint:human-verify" gate="blocking"`) is the
> **open checkpoint** — it requires booting the API against the merged dev database and live-probing four
> routes (`/healthz`, the Stripe webhook, `/v1/signup`, `/v1/me`) without an `x-location-id` header. That
> could not be done from this worktree without human/dev-stack involvement; see "Task 3 — Checkpoint status"
> below for what is proven statically and what still needs a live probe.

**Both location-scope infrastructure files compile against the tenant-only schema with scoping intact; the
dead `activeBrandId` session field that silently broke `set-active-location` end to end (F-27) is deleted;
both brand decorators (`@RequireBrand()`, `@BrandNeutral()`) are gone, `LocationScopeGuard` reads exactly one
neutrality marker, and the 18-controller set of routes that bypass location scoping is provably unchanged.**
