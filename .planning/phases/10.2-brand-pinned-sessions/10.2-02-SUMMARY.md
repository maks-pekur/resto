## Decisions Made

- `apps/website/lib/i18n/request.ts` loads catalogues via a dynamic `import(\`../../messages/${locale}.json\`)`, not a static import map — confirmed by reading the file per the plan's explicit instruction, so no edit was needed there. Same for `locale-cookie.ts`and`middleware.ts`: both derive locale validity from `isLocale`/`LOCALES`, so adding `'es'` to the tuple alone is sufficient — no separate allowlist exists.
- English `_few`/`_many` plural-form keys were added as literal duplicates of `_other` (not translated distinctly) — English/CLDR only ever selects the `one`/`other` categories for the `en` locale, so these keys are present purely for key-set symmetry with `ru.json` (which needs distinct Russian `_few`/`_many` forms) and are never resolved at runtime.
- Locale names in the switcher (`localeEn`: "English", `localeEs`: "Español") are shown in their own language rather than translated into the active UI language, matching the existing `localeRu`: "Русский" precedent.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Pre-existing en/ru plural-key asymmetry blocked Task 1's own key-drift verification**

- **Found during:** Task 1 (author new admin namespaces)
- **Issue:** `ru.json` already carried Russian-specific `_few`/`_many` plural suffixes (`menu.publishBar.unpublishedChanges_few/_many`, `orders.card.itemCount_few/_many`, `orders.feed.refundBanner_few/_many`) that `en.json` never needed (English CLDR has only `one`/`other`). This pre-dated my changes but caused Task 1's own `<verify>` script — a flattened-key-set symmetric-difference check — to fail on files this task owns, blocking the task's stated done-criterion.
- **Fix:** Added inert `_few`/`_many` keys to `en.json` for the three affected paths, each a literal copy of the existing `_other` string. i18next never selects these categories for the `en` locale (CLDR-driven), so this changes no observable behavior — it only restores key-set symmetry.
- **Files modified:** `apps/admin/src/lib/i18n/messages/en.json`
- **Verification:** Re-ran the plan's key-drift `node -e` script — exits 0, `en/ru key sets identical: 462`.
- **Committed in:** `f27f0348` (Task 1 commit)

**2. [Rule 1 - Bug] ESLint `no-unsafe-argument` in the new `flattenKeys` test helper**

- **Found during:** Task 2, first commit attempt (pre-commit hook)
- **Issue:** `flattenKeys(obj: object, ...)` caused `Object.entries(obj)` to type `value` as `any`, tripping `@typescript-eslint/no-unsafe-argument` on the recursive call.
- **Fix:** Retyped the parameter as `Record<string, unknown>` and cast the recursive call accordingly (`value as Record<string, unknown>`).
- **Files modified:** `apps/admin/src/lib/i18n/i18n.spec.ts`
- **Verification:** `npx eslint apps/admin/src/lib/i18n/i18n.spec.ts --max-warnings=0 --no-warn-ignored` clean; `npx vitest run src/lib/i18n` still 8/8 green.
- **Committed in:** `4e0dbd38` (Task 2 commit)
