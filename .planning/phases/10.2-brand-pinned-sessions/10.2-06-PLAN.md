<objective>
Collapse the tenancy context's two entities into one: fold `Brand` into the `Tenant` aggregate, merge the
two provisioning services and the two repositories, and strip `brandId` from the tenancy event contracts.

Purpose: this is where the merged database shape becomes a merged domain model. Every downstream consumer
(identity, catalog, ordering, payments, seeds) reads the ports this plan defines.
Output: `apps/api/src/contexts/tenancy/{domain,application/provision*,infrastructure}` contains no brand
vocabulary; one service provisions a restaurant from a country.
</objective>

  <action>
Move every field and behaviour from `Brand` onto `Tenant` and delete `brand.aggregate.ts`.

`TenantSnapshot` gains, mirroring the merged table exactly: `country` (`CountryCodeValue`), `theme`,
`legalName`, `legalForm`, `taxId`, `stripeAccountId`, `paymentProvider`, `accountType`,
`stripeChargesEnabled`, `stripePayoutsEnabled`, `stripeOnboardingStatus`, `stripeRequirementsDue`,
`fiscalizationConfig`.

Replace `Tenant.linkStripeAccount(_accountId: string): void {}` — a no-op with an intentionally-unused
parameter — with `Brand`'s real implementation, and replace `Tenant.getStatus()`'s hardcoded
`{ onboardingStatus: 'not_started', chargesEnabled: false, payoutsEnabled: false, canAcceptPayments: false, requirementsDue: null }`
with `Brand`'s real derivation from the `stripe_*` columns. This is D-39's "second, legacy Stripe onboarding
path": the tenant-level one is a confirmed dead stub, the brand-level one is live and driven by the
`account.updated` webhook (PAY-05). The dead one loses.

`Tenant.provision(...)` gains a required `country` parameter and derives `defaultCurrency` via
`currencyForCountry(country)` and — when the caller does not pass one — `locale` via
`defaultLocaleForCountry(country)` (D-35: currency is never asked). Keep the existing
`primaryDomainHostname: \`${slug}.${PRIMARY_DOMAIN_SUFFIX}\``behaviour; after D-23 it is written to`tenant_domains` and nowhere else.

`ports.ts`: delete `BRAND_REPOSITORY` and the `BrandRepository` interface. Extend `TenantRepository` with
whatever methods the deleted `BrandRepository` uniquely provided and that survive the merge (e.g. domain
listing, Stripe-account lookup) — do not create a second repository token for the same table.

`errors.ts`: rename `BrandSlugConflictError` -> `TenantSlugConflictError` and
`BrandDisplayNameTakenError` -> delete it (plan 03 dropped the per-tenant display-name unique index, so the
error has no constraint left to represent). Keep the plain-`Error`-subclass shape with an explicit
`this.name`, no error codes, no HTTP status (CLAUDE.md).

`events.ts`: drop any brand-emitting domain event or rename it to its tenant equivalent so the emitted
`type` string matches the contract change in Task 3.

Do NOT introduce a `Brand` type alias, a `@deprecated` export or a re-export shim (D-39).
</action>
