**1. [Rule 1 - Bug] Menu unique-index names didn't match this plan's locked interface shape**

- **Found during:** Task 1 verification
- **Issue:** Plan 03 collapsed `menu_categories_brand_slug_uq`/`menu_categories_brand_code_uq`
  (and the `menu_items` equivalents) to `menu_categories_slug_uq`/`menu_categories_code_uq` —
  correct key shape `(tenant_id, slug)` / `(tenant_id, code)`, but the wrong name. This plan's
  own `<action>` text says explicitly: "rename the index from `*_brand_slug_uq` /
  `*_brand_code_uq` to `*_tenant_slug_uq` / `*_tenant_code_uq`", and the acceptance criterion
  `rg -n "tenant_slug_uq|tenant_code_uq" packages/db/src/schema/menu.ts` (>=4 matches) failed
  against plan 03's names.
- **Fix:** Renamed all four to `menu_categories_tenant_slug_uq`, `menu_categories_tenant_code_uq`,
  `menu_items_tenant_slug_uq`, `menu_items_tenant_code_uq`.
- **Files modified:** `packages/db/src/schema/menu.ts`
- **Verification:** `rg -n "tenant_slug_uq|tenant_code_uq" packages/db/src/schema/menu.ts`
  matches 4 times; `rg -n "IS NOT NULL"` still matches (partial-index predicates intact);
  `npx tsc -p packages/db/tsconfig.json --noEmit` exits 0.
- **Committed in:** `c39317f5`
- **Note for plan 09:** `apps/api/src/contexts/catalog/infrastructure/catalog-drizzle.repository.ts`
  still references the old names `menu_categories_brand_code_uq` (line 340) and
  `menu_items_brand_code_uq` (line 537) in `isCodeUniqueViolation(err, '...')` calls. This was
  already broken (referencing a name that didn't exist even under plan 03's version) — not a

  rewrite picks up the correct new name (`menu_categories_tenant_code_uq` /
