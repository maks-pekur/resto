# Phase 10.2: Organization-per-restaurant and account onboarding Verification Report

**Phase Goal:** Collapse tenant and brand into a single entity — the Better Auth organization — so one
restaurant is one organization, an owner may belong to several, and the active organization chosen at
sign-in is the entire context of a session; and give a new owner a working path from "create account" to
"first restaurant".

## Method

This phase's own findings log (48 entries) documents several cases where a green static gate hid a dead
endpoint or a disabled security check. Verification here therefore prioritized **re-execution over reading
claims**: every gate command named in the phase's SUMMARYs was re-run independently against the live dev
stack (Postgres on :5433 as the schema owner `resto`, a booted `apps/api` on :5001, a live `apps/admin` Vite
dev server), not accepted from prose. Where the phase's own findings identified a class of previously-hidden
bug (dead in-memory field, disabled origin check, dead frontend route, invisible DB object), the fix for
that specific finding was independently re-checked, not merely re-read.

Two additional steps went beyond the standard protocol given this phase's own admission that curl-level and
static checks missed a real cookie-transport bug (F-41): a full live `POST /api/auth/switch-organization`
curl walkthrough was run end-to-end (signup → sign-in → activate → onboard → dashboard-equivalent read,
with real `GB→GBP` currency derivation observed), and a temporary Playwright spec was written, run, and
deleted to **screenshot** the signup, onboarding, dashboard, language-switcher, and multi-organization
picker screens and inspect the rendered pixels directly — not just DOM assertions. All temporary
verification artifacts (screenshot spec, `.env` overrides used only to work around this machine's stale
dev-cookie config per F-42, stray background server processes) were removed/reverted before finishing;
`git status` confirms the repository is unchanged (only the pre-existing, phase-unrelated
`apps/website/next-env.d.ts` churn from F-08 remains, as it did before this session started).
