## 1. Pattern Families (grouped, not individually enumerated)

### F1 — Drizzle schema column `brand_id: uuid('brand_id').notNull()` + composite FK to `brands`

**Count:** 9 columns across 6 files, confirmed exact match to D-08: `menu.ts` ×6 (menu_categories:35, menu_items:89, menu_item_sizes:170, menu_modifier_groups:207, menu_modifier_options:240, menu_item_modifier_groups:288), `ordering.ts` ×1 (orders:27), `customer-profiles.ts` ×1 (nullable:18), `outbox.ts` ×1 (nullable:39).

**Canonical analog:** `packages/db/src/schema/menu.ts:30-70` (`menuCategories` table)

**Before-shape** (`packages/db/src/schema/menu.ts:30-70`):

```typescript
import { brands, locations } from './brands';

export const menuCategories = pgTable(
  'menu_categories',
  {
    id: pkUuid(),
    tenantId: tenantIdColumn(),
    brandId: uuid('brand_id').notNull(),
    parentId: uuid('parent_id'),
    slug: text('slug').notNull(),
    // ...
  },
  (table) => [
    foreignKey({
      name: 'menu_categories_tenant_fk',
      columns: [table.tenantId],
      foreignColumns: [tenants.id],
    }).onDelete('cascade'),
    compositeTenantFk({
      name: 'menu_categories_brand_fk',
      child: { id: table.brandId, tenantId: table.tenantId },
      parent: { id: brands.id, tenantId: brands.tenantId },
    }).onDelete('restrict'),
    uniqueIndex('menu_categories_brand_slug_uq').on(
      table.tenantId,
      table.brandId,
      table.slug,
    ),
    uniqueIndex('menu_categories_brand_code_uq')
      .on(table.tenantId, table.brandId, table.code)
      .where(sql`${table.code} IS NOT NULL`),
    // ...
  ],
);
```

**After-shape (what the merge produces):** drop the `brandId` column, the `compositeTenantFk` block that references it, and the `brands` import; any unique index keyed on `(tenantId, brandId, slug)` collapses to `(tenantId, slug)` — this is a **behavior change**, not just a column drop: `menu_categories_brand_slug_uq` today allows the same slug in two brands of one tenant; post-merge the same slug can only exist once per tenant. Flag this for the planner's migration-writing task — it is the single largest semantic consequence of the merge on the catalog schema, not called out explicitly in CONTEXT.md's D-08 (which only lists the column drop, not the index-collapse consequence).

**`outbox.ts:39` and `customer-profiles.ts:18` are nullable `brand_id`** (not `.notNull()`) — simple drop, no composite FK, no index consequence.

**`_columns.ts`'s `compositeTenantFk` helper** (used by every one of the 9 drops) stays — it is the general ADR-0020 I-2 mechanism, not brand-specific. No change needed there.

```typescript
  const existing = await this.repo.findBySlug(input.slug);
```

### F4 — Global guard chain order

**CONTEXT.md/RESEARCH.md claim:** "Six global guards run in order: `AuthGuard → PermissionsGuard → BrandScopeGuard → LocationScopeGuard → OwnerOnlyGuard → RateLimitGuard`."

**Measured** (`apps/api/src/contexts/identity/identity-http.module.ts:95-99`, the only file in the repo with `provide: APP_GUARD`):

```typescript
{ provide: APP_GUARD, useClass: AuthGuard },
{ provide: APP_GUARD, useClass: PermissionsGuard },
{ provide: APP_GUARD, useClass: BrandScopeGuard },
{ provide: APP_GUARD, useClass: LocationScopeGuard },
{ provide: APP_GUARD, useClass: OwnerOnlyGuard },
```

**Flag: this is FIVE global guards, not six.** `RateLimitGuard` (`apps/api/src/shared/rate-limit.guard.ts`) is never registered as `APP_GUARD` anywhere in the repo — the only rate-limit guard wired at all in identity is `BrandSlugRateLimitGuard`, applied **per-route** (`@UseGuards(BrandSlugRateLimitGuard)` on `GET /v1/me/brands/slug-availability`, `me-brands.controller.ts:148`), not globally. Correcting the phase's mental model: the merge removes `BrandScopeGuard` from a 5-guard chain (`AuthGuard → PermissionsGuard → LocationScopeGuard → OwnerOnlyGuard`, 4 remaining), and the route-scoped `BrandSlugRateLimitGuard` is renamed per Pitfall 5 below, not touched as part of the global chain.

**Analog for the surviving 4-guard chain:** `LocationScopeGuard` (`apps/api/src/contexts/identity/interfaces/http/guards/location-scope.guard.ts`, full file read) is structurally identical to `BrandScopeGuard` and is the template for how any future scope guard should look — same `ForbiddenException` codes shape (`{resource}.context_required`, `{resource}.operator_required`, `{resource}.tenant_required`, `{resource}.access_denied`), same `principal.baseRole === 'owner'` bypass, same reader-port injection pattern. No new guard is being built this phase, but if the planner needs to touch `LocationScopeGuard`, note it dual-checks `LOCATION_NEUTRAL_KEY` **and** `BRAND_NEUTRAL_KEY` (line 33-37) — the `BRAND_NEUTRAL_KEY` check must be removed from `LocationScopeGuard` once `BrandNeutral()` stops being applied for its original purpose, or left as inert-but-harmless (never-true) dead code, which is against D-39's spirit.

**Pattern to copy — Zod value-object with doc-commented rationale** (`money.ts:81-100`, the `Currency`/`CurrencyValue` pair — the closest existing precedent for a small closed enum with an HTTP-boundary unbranded form):

```typescript
const currencyRegex = /^[A-Z]{3}$/;

  .string()
  .regex(currencyRegex, 'must be a 3-letter uppercase ISO-4217 code');
export type CurrencyValue = z.infer<typeof CurrencyValue>;
export const Currency = CurrencyValue.brand<'Currency'>();
export type Currency = z.infer<typeof Currency>;
```

**Recommended shape for `country.ts`** (synthesized from the two analogs, not existing code): a `z.enum(['UA', 'GB', 'ES'])`-based `CountryCode`/`CountryCodeValue` pair (branded/unbranded, per ADR-0020 I-7 — an HTTP-boundary signup DTO will reference this) plus a plain `COUNTRY_REGISTRY: Record<CountryCodeValue, { currency: CurrencyValue; defaultLocale: string }>` const (not Zod-wrapped, mirrors `reserved-slugs.ts`'s plain-object style) mapping `UA → { currency: 'UAH', defaultLocale: 'ru' }` (Pitfall 6's locked recommendation), `GB → { currency: 'GBP', defaultLocale: 'en' }`, `ES → { currency: 'EUR', defaultLocale: 'es' }`. **RBAC precedent for "shared registry, zero infra imports"** (`packages/domain/src/rbac/permissions.ts`, full file, 16 lines) — confirms the project's established shape for a small closed catalogue: a single `as const` object, a derived `keyof typeof` type, no runtime validation needed for compile-time-closed sets. `country.ts`'s registry object can follow this exact shape if the planner decides Zod validation is unnecessary for the registry values themselves (only the _input_ `CountryCode` needs Zod, since it crosses the HTTP boundary at signup).
