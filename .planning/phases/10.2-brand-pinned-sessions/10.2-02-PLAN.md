<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser locale cookie / `Accept-Language` -> i18n resolver | An attacker-controlled locale string reaches the catalogue lookup in both apps |
| Translated string -> rendered DOM | Catalogue values are interpolated into React output |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10.2-02-01 | Tampering | Website locale resolution from an arbitrary cookie/path value | mitigate | `isLocale` derives from the `LOCALES` tuple and is the only admission path; adding `'es'` to the tuple is the whole change — no string is trusted unvalidated |
| T-10.2-02-02 | Information Disclosure | i18next `escapeValue: false` in the admin config | accept | React escapes interpolated children by default; the setting exists so `{{name}}` renders literally. No catalogue value in this plan is rendered via `dangerouslySetInnerHTML`, and none is user-supplied — the `{{name}}`/`{{host}}` values come from the session and the derived slug |
| T-10.2-02-03 | Denial of Service (UX) | Incomplete `es` catalogue silently rendering Russian | mitigate | Key-set completeness assertion in `i18n.spec.ts` fails the build on drift; the deliberate-fallback test asserts rendered output, not configuration |
| T-10.2-02-SC | Tampering | npm/pip/cargo installs | accept | No packages installed — `i18next`, `react-i18next` and `next-intl` are already resolved in the lockfile at the versions RESEARCH.md verified |
</threat_model>
