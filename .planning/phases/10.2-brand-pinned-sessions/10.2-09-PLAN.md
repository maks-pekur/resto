  <action>
Delete every `brandId` parameter, field and predicate from the catalog domain contracts and the Drizzle
repository.

`domain/ports.ts`: remove `brandId` from every port method signature. Where a method took
`(tenantId, brandId, ...)` it now takes `(tenantId, ...)`. Do not introduce an optional `brandId?` — an
optional parameter is a deprecation in disguise (D-39). Keep the Symbol-token + interface pairing convention.

`domain/published-menu.ts`: remove `brandId` from the published-menu document if present. This document is
what the version-keyed HTTP/CDN ETag is computed over (the menu-caching feature that replaced Redis), so
changing its shape changes every cached ETag — expected and harmless given D-12's reset, but say so in the
SUMMARY so a stale-cache report during smoke testing is not misdiagnosed.

`domain/errors.ts`: rename or delete brand-named errors. A catalog error that referred to a brand boundary
that no longer exists is deleted, not renamed to a tenant equivalent that can never be thrown.

`catalog-drizzle.repository.ts`: remove `brandId` from every insert payload, every `eq(...)` predicate and
every returned projection. Do NOT replace a removed brand predicate with a hand-written
`eq(table.tenantId, ...)` — `ScopedTx` already appends the tenant filter automatically on SELECT/UPDATE and
injects `tenant_id` on INSERT. Adding a manual tenant predicate is redundant, and writing one implies the
author was not sure ScopedTx applies. Every query must remain inside `db.withTenant((tx, scoped) => ...)`;
raw `tx` on a tenant-scoped table is forbidden (ADR-0020 I-1). If any query currently uses raw `tx`, that is
a pre-existing violation — report it in the SUMMARY rather than silently fixing or silently keeping it.

Watch for uniqueness assumptions: code that previously relied on `(tenant_id, brand_id, slug)` allowing the
same slug twice inside one tenant will now hit a `(tenant_id, slug)` conflict. Search for catch blocks or
upsert `onConflictDoUpdate` targets naming the old index and re-point them at the new
`menu_categories_tenant_slug_uq` / `menu_items_tenant_slug_uq` / `*_tenant_code_uq` names from plan 04.
  </action>
