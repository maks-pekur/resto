## Sequencing and gate ownership

This plan lands BEFORE plan 15 (the admin route-tree collapse), and plan 15 declares it as a dependency.
The two are coupled in both directions — plan 15's route files pass `brandSlug` into components this plan
owns, and this plan's components navigate through TanStack Router's typed `to` prop into a route tree only
plan 15 can change — so neither can be proven by a whole-package build while running in an isolated
worktree. The split of ownership is: this plan owns `src/components/{menu,orders,roles}/`; plan 15 owns
`src/routes/` and the sidebar chrome at `src/components/*.tsx`.

At the end of THIS plan the admin package deliberately does NOT typecheck green. The residual errors are
bounded to six files whose navigation targets are written here to their FINAL flat paths and only become
valid once plan 15 rewrites the route tree: `menu/items-table.tsx`, `menu/item-detail-form.tsx`,
`menu/modifier-group-form.tsx`, `menu/item-modifier-groups-card.tsx`, `roles/role-form.tsx`,
`roles/role-list.tsx` — plus files plan 15 owns and this plan must not touch. Every gate below is
file-bounded and therefore satisfiable inside this plan's own worktree with no sibling plan present.

**The "the whole admin package typechecks and builds" claim has MOVED to plan 15**, which is the first plan
at which it is true. This mirrors the pattern plans 07-10 use with plan 11 for the API package.

Command note: `apps/admin` has no `typecheck` or `test` npm script — both are Nx targets, so
the package-level pnpm filter forms do not run. Typecheck is invoked directly as
`cd apps/admin && npx tsc -p tsconfig.json --noEmit` and tests as `cd apps/admin && npx vitest run <paths>`,
matching the `cd apps/api && npx vitest run` form used elsewhere in this phase. `pnpm --filter admin build`
does exist and works.
