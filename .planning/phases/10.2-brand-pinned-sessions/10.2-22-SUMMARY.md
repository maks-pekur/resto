### Root cause (diagnosed via read-only queries, database NOT modified)

```
SELECT has_schema_privilege('resto_app','public','USAGE'), has_schema_privilege('resto_auth','public','USAGE');
 app_usage | auth_usage
-----------+------------
 f         | f

SELECT count(*) FILTER (WHERE has_table_privilege('resto_app', schemaname||'.'||tablename, 'SELECT')), count(*)
FROM pg_tables WHERE schemaname='public';
 app_can_select | total_tables
----------------+--------------
              1 |           32
```

`resto_app` and `resto_auth` both lack `USAGE` on schema `public`; `resto_app` can `SELECT` from only 1 of 32 tables. `packages/db/sql/roles.sql:18` declares `GRANT USAGE ON SCHEMA public TO resto_app;` (plus the `ALL TABLES`/`ALL SEQUENCES`/`ALL FUNCTIONS` grants immediately after) — none of it is currently in effect.

The mechanism: `packages/db/src/cli/reset.ts` (`db:reset`) runs `DROP SCHEMA IF EXISTS public CASCADE; ... CREATE SCHEMA public;` — a fresh `CREATE SCHEMA public` carries none of `roles.sql`'s grants. `10.2-05-SUMMARY.md`'s "Task 3 results (orchestrator-run, 2026-08-20)" confirms `db:reset` ran live that session to apply migration 0079. Re-granting requires a **separate** step — `packages/db/src/cli/provision-roles-ci.ts` (`provisionAppRole` + `provisionAuthRole`, which re-run `roles.sql`/`auth-role.sql`) — which has no wired `db:*` package-manager script (only reachable via a direct `tsx` invocation with `DATABASE_ADMIN_URL`/`APP_ROLE_PASSWORD`/`AUTH_ROLE_PASSWORD` env vars) and was evidently not re-run after that reset. This has been latent since 2026-08-20 and was invisible until now purely because `apps/api` could not compile (and therefore never attempted a live boot) at any point between plan 05 and this plan — exactly the gap F-29 was created to close.

**Not fixed, per explicit plan instruction.** Remediation (for the orchestrator/founder to authorize, not run blind — this touches shared dev-database role state):

```
DATABASE_ADMIN_URL=postgres://resto:resto_dev_password@localhost:5433/resto \
APP_ROLE_PASSWORD=resto_app_dev_password \
AUTH_ROLE_PASSWORD=auth_password_dev \
tsx packages/db/src/cli/provision-roles-ci.ts
```

(passwords read from `.env`'s existing `DATABASE_URL`/`BETTER_AUTH_DATABASE_URL`, matching the roles' current credentials — this is a grants-only operation, not a schema reset, and does not touch any table data.)
