<objective>
Make the menu-version storage and the publish/cancel/draft-diff data path brand-scoped (CR-04, founder decision 2026-06-23: publish PER BRAND, not tenant-wide). Today `catalog_menu_version` has a tenant-only PK so one publish bumps the version for every brand of the tenant simultaneously, and `publish`/`cancelPublish`/`draft-diff` run without a bound brand. This plan rebuilds the version table to PK `(brand_id, tenant_id)` mirroring `catalog_brand_stop_version`, makes the menu-version adapter brand-aware, brand-keys the delayed-publish timer, adds `@RequireBrand()` to the three routes, and closes the actual CR-04 cross-brand draft-diff leak by filtering `computeDraftDiff` by `brandId`.

This plan is the DATA PATH (schema → migration → port → adapter → services → controller). The event-v2 contracts, the `finalizeMenuPublish` UPSERT rewrite, the public ETag path, and the cross-brand e2e isolation tests are in plan 07.6-09, which depends on this plan.

Purpose: Per-brand publish is required for correct multibrand isolation — a Brand A publish must not affect Brand B's menu version, public ETag, or pending timer. The draft-diff filter closes a confirmed cross-brand data leak.
Output: Brand-keyed `catalog_menu_version` table (migration applied to dev DB), brand-aware menu-version port/adapter, brand-keyed delayed-publish, guarded routes, brand-filtered draft-diff.

NOTE TO REVIEWER (founder gate): this plan is to be reviewed via /gsd-review BEFORE execution.
</objective>

export const catalogBrandStopVersion = pgTable(
  'catalog_brand_stop_version',
