## Decisions Made

- Code-based TanStack Router (no file-based codegen) — simpler bootstrap, Wave 2 owns full route tree
- Russian plural keys include `_many` (for 5+) because Intl.PluralRules('ru').select(5) returns 'many', not 'other'; plan spec said `_one/_few/_other` but that silently drops count≥5 strings
- Legacy `app/`, `lib/`, `components/`, `test/`, `e2e/` dirs remain (Wave 2 will port or delete them) and are excluded from ESLint projectService to prevent `server-only` parse failures

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Added `unpublishedChanges_many` plural key for Russian count≥5**

- **Found during:** Task 3 (i18n port + vitest spec)
- **Issue:** Plan spec said `_one/_few/_other` but Russian uses 'many' for counts 5, 7, 11 etc (Intl.PluralRules('ru').select(5) === 'many'). Without `_many`, i18next falls back to the key name string for count=5.
- **Fix:** Added `"unpublishedChanges_many": "{{count}} неопубликованных изменений"` to ru.json alongside `_other` (which remains as the true catch-all fallback)
- **Files modified:** `apps/admin/src/lib/i18n/messages/ru.json`
- **Verification:** vitest spec for count=5 passes
- **Committed in:** `109dd95` (Task 3 commit)

**2. [Rule 3 - Blocking] ESLint projectService failing on legacy Next.js dirs**

- **Found during:** Post-Task-3 lint run
- **Issue:** `projectService: true` in eslint.config.mjs caused ESLint to pick up `app/`, `lib/`, `components/`, `test/`, `e2e/`, `playwright.config.ts` — all legacy Next.js files outside tsconfig include paths, all importing `server-only`
- **Fix:** Added `app/**`, `lib/**`, `components/**`, `test/**`, `e2e/**`, `playwright.config.ts` to eslint ignores. These directories will be ported/deleted in Wave 2 plans (07.6-04 through 07.6-06)
- **Files modified:** `apps/admin/eslint.config.mjs`
- **Verification:** `admin:lint` exits 0
- **Committed in:** `109dd95` (Task 3 commit)
