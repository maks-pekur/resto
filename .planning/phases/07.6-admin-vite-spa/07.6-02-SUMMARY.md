# Phase 7.6 Plan 02: Operator Offboard Endpoints + CORS Docs Summary

**One-liner:** Operator `POST/DELETE /v1/tenants/me/offboard` endpoints session-scoped to owner role, plus `admin.resto.app` CORS/cookie documentation for the SPA deploy.

## What Was Built

### Task 1 — POST/DELETE /v1/tenants/me/offboard in TenantsController

Added two new handlers to `apps/api/src/contexts/tenancy/interfaces/http/tenants.controller.ts`:

- `POST me/offboard` — `@HttpCode(202)`, `@Permissions({ tenant: ['delete'] })`, `@RequiresTenantContext()`. Calls `OffboardTenantService.schedule({ tenantId, requestedBy })`. Tenant derived from ALS via `requireTenantContext()` (not a URL `:id` param).
- `DELETE me/offboard` — `@HttpCode(200)`, same permission gate. Calls `OffboardTenantService.cancel({ tenantId })`.

Both handlers use `try/catch + mapDomainError` matching the existing `getMe` idiom. `OffboardTenantService` was already exported from `TenancyModule` so no module wiring change needed.

Permission `tenant: ['delete']` gates to owner-only: `PERMISSIONS_STATEMENT.tenant = ['read', 'delete', 'transfer']` and only `SYSTEM_ROLES.owner` holds `delete`; `admin` holds only `read`.

### Task 2 — .env.example CORS + trusted-origins documentation

Updated `/.env.example`:

- Added production-shape comment for `CORS_ALLOWED_ORIGINS` showing `https://admin.resto.app` alongside `*.menu.resto.app`
- Expanded `ADMIN_WEB_URL` comment to note it auto-populates BA's `trustedOrigins` allowlist
- Added `AUTH_COOKIE_DOMAIN` production example (`.resto.app`) with note about leading-dot requirement
- Added `BETTER_AUTH_TRUSTED_ORIGINS` as a documented opt-in env var for supplemental trusted origins

No schema change to `env.schema.ts` — `CORS_ALLOWED_ORIGINS` already accepts comma-separated origins; `ADMIN_WEB_URL` is already wired to BA's `trustedOrigins` in `identity-core.module.ts`.

### Task 3 — E2E tests for offboard endpoints

Extended `apps/api/test/e2e/tenants-controller.e2e.spec.ts` with two `describe` blocks:

**POST /v1/tenants/me/offboard:**

- 401 without auth
- 403 for admin-role operator (tenant:delete gate)
- 202 + `offboardingScheduledAt` set for owner
- 403 when session tenant ≠ request tenant (cross-tenant isolation via AuthGuard)

**DELETE /v1/tenants/me/offboard:**

- 401 without auth
- 403 for admin-role operator
- 200 + `offboardingScheduledAt` cleared for owner (full schedule→cancel round-trip)

Uses existing `addMemberWithRole`, `provisionTenant`, `runBootstrap`, `signInAsOperator` fixtures.
