## Auth & session

Locked without a question (Claude recommendation, unopposed): `better-auth/react` client replaces server-actions; tenant from session org; active brand as client state authorized by BrandScopeGuard (HMAC brand cookie removed); `proxy.ts` cookie-gate → client route guard.

Session transport — the one real fork:

| Option                    | Description                                                                                                                                                                                                                                 | Selected |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| Cookie between subdomains | httpOnly better-auth session cookie, `Domain=.resto.app`, SameSite=Lax, Secure; same-site so cookie flows; fetch `credentials:'include'` + CORS explicit-origin + Allow-Credentials. Token unreachable from JS; matches AUTH_COOKIE_DOMAIN. | ✓        |
| Bearer token in storage   | better-auth-issued token in memory/localStorage, `Authorization: Bearer`. Simpler CORS, domain-independent, but JS-readable (XSS exfil risk); localStorage = classic anti-pattern, in-memory lost on refresh.                               |          |

**User's choice:** Cookie between subdomains.
**Notes:** Aligns with already-provisioned `AUTH_COOKIE_DOMAIN`; works in dev (localhost:3000 ↔ :3001 are same-site). CORS specifics left to planning.

## Frontend stack (router + data)

Data layer locked without a question (near-unanimous): **TanStack Query** for reads/mutations/optimistic publish/auto-save/retry parity.

Router — the fork:

| Option          | Description                                                                                                                                                           | Selected |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| TanStack Router | Full type-safety on routes/params/search; native TanStack Query integration (loaders/prefetch); aligns with strict-TS/zod/branded codebase. Newer, smaller ecosystem. | ✓        |
| react-router v7 | Ubiquitous, huge ecosystem/docs, "boring/safe" for solo tempo. Weaker param type-safety; manual Query wiring.                                                         |          |

**User's choice:** TanStack Router.
**Notes:** Paired with TanStack Query — loaders + cache + type-safety end to end.

## Migration strategy + API parity

Scaffold/cutover locked without a question: fresh Vite scaffold in `apps/admin`, port components, **big-bang** — admin has zero prod exposure, so "migration" is "rebuild before first deploy."

API parity — the fork (precise gap surfaced first: operator `v1/catalog` holds all writes; `internal/v1/catalog` holds the 7 GET reads; admin is the only caller of internal catalog; `INTERNAL_API_TOKEN` still needed by `internal/v1/tenants`):

| Option              | Description                                                                                                                                                                                     | Selected |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| Relocate and delete | Move 7 GET handlers to `v1/catalog` (operator guard + tenant/brand from session/param, same app services), then delete `internal/v1/catalog`. Cleanest end state, low risk (admin-only caller). | ✓        |
| Add, leave internal | Add 7 operator GETs, admin switches, leave `internal/v1/catalog` as dead-but-present. Less change now, but duplicate internal read-surface + future confusion.                                  |          |

**User's choice:** Relocate and delete.
**Notes:** `INTERNAL_API_TOKEN` / `InternalTokenGuard` stay in the system for `internal/v1/tenants`; only the admin browser stops using internal endpoints.

## i18n & Next bindings

`next-themes` → lightweight localStorage+class theme: locked as Claude's discretion (mechanical).

i18n library — the fork:

| Option                | Description                                                                                                                                          | Selected |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| react-i18next         | Closest to current next-intl: same namespaced JSON, interpolation, cookie/localStorage detection, lazy-load; en/ru JSON port with minimal reshaping. | ✓        |
| Lightweight custom    | Mini context + t(key) + JSON, no external dep; but hand-write interpolation/pluralization/detection.                                                 |          |

**User's choice:** react-i18next.
**Notes:** Default locale stays **ru**.
