# Phase 7.6 Plan 06: Remaining Operator Surface Port — Summary

**One-liner:** Brands/domains/payouts/theme, settings offboard danger-zone via operator `me/offboard`, 2FA via `authClient.twoFactor`, and team invite via `authClient.organization` — eliminating the last `apiFetchInternal` call from the admin browser (SC-2).

## What Was Built

### Task 1 — Tenancy + team Query factories + brand routes (`de7dabc`)

`apps/admin/src/lib/queries/tenancy.ts`:

- `tenancyQuery()` → `GET /v1/tenants/me`
- `tenantDomainsQuery()` → `GET /v1/tenants/me/domains`
- `scheduleOffboard(userId)` → `POST /v1/tenants/me/offboard`
- `cancelOffboard()` → `DELETE /v1/tenants/me/offboard`
- `friendlyOffboardError()` — preserves legacy 404/401/403/409 error copy

`apps/admin/src/lib/queries/team.ts`:

- `memberListQuery()` → `authClient.organization.listMembers()`
- `invitationListQuery()` → `authClient.organization.listInvitations()`

Three brand routes registered under `$brandSlug/brands.$slug.*`:

- `brands.$slug.domains.tsx` — prefetches `tenantDomainsQuery`, renders domains table
- `brands.$slug.theme.tsx` — placeholder for RES-91
- `brands.$slug.payouts.tsx` — placeholder for RES-92

All three use `useParams({ strict: false })` to read `brandSlug` from the parent route param. Zero `next/*` / `'use server'` imports.

### Task 2 — Settings route + offboard danger-zone + 2FA (`09d6b1d`)

`apps/admin/src/components/danger-zone-card.tsx`:

- Ported from `apps/admin/components/danger-zone-card.tsx`
- Calls `scheduleOffboard(userId)` and `cancelOffboard()` from tenancy.ts (operator endpoint, no internal token)
- Preserves all friendly error copy and the owner-only guard (card shows non-owner message when `isOwner=false`; API still enforces 403)
- `useMutation` + `queryClient.invalidateQueries(['tenancy','me'])` on settle

`apps/admin/src/components/settings/two-factor-section.tsx`:

- Ported from legacy `two-factor-enable-client.tsx`
- Calls `authClient.twoFactor.enable`, `authClient.twoFactor.verifyTotp`, `authClient.twoFactor.disable` (no server actions)
- State machine: idle → password-enable → showing-codes → verify → reload; parallel disable flow
- `twoFactorClient()` plugin added to `authClient` to expose `twoFactor` methods

`apps/admin/src/routes/(protected)/dashboard/settings.tsx`:

- Loader prefetches `meQuery()` + `tenancyQuery()`
- Renders `TwoFactorSection` + `DangerZoneCard`
- Owner guard: `me.baseRole === 'owner'` passed as `isOwner` prop

### Task 3 — Team route + invite components (`625cfb0`)

`apps/admin/src/components/team/invite-form.tsx`:

- Calls `authClient.organization.inviteMember({ email, role: baRole })` where `baRole = role === 'staff' ? 'member' : role`
- `useMutation` with `queryClient.invalidateQueries(['team','invitations'])` on success
- Preserves 403 / 409 / generic error copy from legacy `invite-action.ts`

`apps/admin/src/components/team/team-invite-button.tsx`:

- Sheet wrapper with `useTranslation('translation', { keyPrefix: 'dashboard' })`
- Zero `next-intl` / `next/link` / `'use server'` imports

`apps/admin/src/routes/(protected)/dashboard/team.tsx`:

- Loader prefetches `meQuery()`; renders `TeamInviteButton` + pending invitations table
- Falls back to `EmptyState` when no invitations

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `authClient.twoFactor` not typed — `twoFactorClient()` plugin missing**

- Found during: Task 2 typecheck
- Issue: `authClient.twoFactor` does not exist — `twoFactorClient()` was not in the `plugins` array of `createAuthClient`
- Fix: Added `twoFactorClient()` import from `better-auth/client/plugins` and included it in the `plugins` array in `auth-client.ts`
- Files modified: `apps/admin/src/lib/auth-client.ts`

**2. [Rule 1 - Bug] `authClient.organization.inviteMember` role type mismatch**

- Found during: Task 3 typecheck
- Issue: BA organization client accepts `"owner" | "admin" | "member"` but internal `Role` type includes `"staff"`
- Fix: Added `const baRole = role === 'staff' ? 'member' : role` mapping before the `inviteMember` call
- Files modified: `apps/admin/src/components/team/invite-form.tsx`

**3. [Rule 1 - Bug] `useParams({ strict: false })` required for parent route params**

- Found during: Task 1 typecheck
- Issue: `Route.useParams()` in nested routes only exposes that route's own params (e.g. `slug`), not parent params (`brandSlug`). TypeScript error `Property 'brandSlug' does not exist on type '{ slug: string; }'`
- Fix: Changed to `useParams({ strict: false })` in all three brand routes to access parent `$brandSlug`
- Files modified: `brands.$slug.domains.tsx`, `brands.$slug.theme.tsx`, `brands.$slug.payouts.tsx`
