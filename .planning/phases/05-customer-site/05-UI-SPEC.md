### Per-Tenant Theming

The storefront is brand-facing. `packages/domain/src/brand-theme.ts` defines:

- `primaryColor` — hex color string (nullable, falls back to `--primary: #16a34a` from admin palette)
- `logoUrl` — URL string (nullable)
- `font` — string from allowlist (nullable, falls back to Inter)

The website MUST inject `primaryColor` as `--primary` CSS variable at the `<html>` element level, derived at RSC render time from the resolved tenant's brand theme. When `primaryColor` is null, fall back to the default green `#16a34a`. When `font` is null, fall back to Inter.

## Spacing Scale

Standard 8-point scale. All values are multiples of 4.

| Token | Value | Usage                                                        |
| ----- | ----- | ------------------------------------------------------------ |
| xs    | 4px   | Icon gaps, badge padding, inline micro-spacing               |
| sm    | 8px   | Compact element spacing (item card inner padding, chip gaps) |
| md    | 16px  | Default element spacing (form field gaps, card padding)      |
| lg    | 24px  | Section padding, modal content padding                       |
| xl    | 32px  | Layout column gaps, major card spacing                       |
| 2xl   | 48px  | Major section breaks (menu category separation)              |
| 3xl   | 64px  | Page-level top/bottom padding (hero, footer)                 |

Exceptions:

- Touch targets on mobile: minimum 44px hit area for all interactive elements (buttons, modifier checkboxes, quantity +/−). This is a padding addition on top of visual size, not a spacing token override.
- Sticky category nav height: 48px (2xl) — fixed for predictable layout offset calculation.
- Cart drawer width: 400px on desktop, full-width on mobile (< 640px breakpoint).
- Item modal max-width: 560px, centered, with 24px horizontal padding inside.

## Typography

Three sizes, two weights. Body defaults to English (`en`) per D-05.

| Role    | Size | Weight         | Line Height | Usage                                                                             |
| ------- | ---- | -------------- | ----------- | --------------------------------------------------------------------------------- |
| Body    | 16px | 400 (regular)  | 1.5         | Menu item descriptions, form labels, cart line items, content page body           |
| Label   | 14px | 400 (regular)  | 1.4         | Secondary metadata (allergens, calorie counts, category pill labels, helper text) |
| Heading | 20px | 600 (semibold) | 1.2         | Category section headings, modal item name, checkout section headings             |
| Display | 28px | 600 (semibold) | 1.1         | Restaurant name in site header (brand identity element)                           |

Font stack: `var(--font-inter), ui-sans-serif, system-ui, sans-serif`

Price values: 16px, weight 600 (semibold) — visually distinct from description text but does not introduce a new type role. Use `tabular-nums` font variant for price alignment in cart rows.

## Color

The storefront uses light mode only in Phase 5. Dark mode is deferred to Phase 15 (Content & SEO).

| Role             | Default Value                              | Usage                                                                                                |
| ---------------- | ------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| Dominant (60%)   | `oklch(1 0 0)` — white                     | Page background, menu content area, modal background                                                 |
| Secondary (30%)  | `oklch(0.97 0 0)` — near-white grey        | Cart drawer background, sticky category nav background, item card background, delivery/pickup banner |
| Accent (10%)     | Tenant `primaryColor` (fallback `#16a34a`) | See reserved-for list below                                                                          |
| Destructive      | `#ef4444`                                  | Remove-from-cart button, clear-cart action only                                                      |
| Muted foreground | `oklch(0.45 0 0)`                          | Placeholder text, helper text, disabled states                                                       |
| Border           | `oklch(0.9 0 0)`                           | Card borders, input borders, dividers                                                                |

**Accent reserved for:**

- The selected delivery/pickup mode pill (active state background)
- The "Add to cart" primary button inside the item modal
- Quantity increment (+) button active fill
- Cart item count badge on the cart trigger button
- Sticky category nav active/selected category underline indicator
- Checkout CTA button (disabled state uses muted, enabled state in Phase 8 uses accent)
- Promo code "Apply" button (stub, renders in accent at 50% opacity to signal non-functionality)

**Stop-listed items:** Render item cards at 50% opacity with a `cursor-not-allowed` overlay. Do not use destructive red — unavailability is not an error.

**Delivery/Pickup mode banner:**

- Unselected mode: secondary background, muted foreground border
- Selected mode: accent color border (2px), accent foreground label

Source: D-06, D-07

```

│ TenantHeader (sticky, z-50)                     │
│ logo · restaurant name · cart trigger badge     │
├─────────────────────────────────────────────────┤
```

- TenantHeader: height 64px. Position `sticky top-0`.
- DeliveryPickupBanner: height 48px. Position `sticky top-[64px]`.

- Menu content area: `pt-[160px]` to clear all sticky layers.
- On mobile (< 640px): CartDrawer becomes full-width bottom sheet instead of right sidebar.

### Checkout Page (`/checkout`)

Single page, no stepper. Layout is a centered single-column form (max-width 640px) with these sections:

1. Delivery address (shown only if delivery mode selected) + inline zone stub feedback
2. Contact info (name, phone) + optional account creation hint (non-functional in Phase 5)
3. Order time (ASAP / scheduled)
4. Promo code input (non-functional placeholder)
5. Order summary (read-only: items, subtotal, stub delivery fee)
6. Disabled pay button with "Payment coming soon" tooltip

## Interaction Contracts

### Item Selection Flow (D-06 — modal pattern)

1. Guest clicks `MenuItemCard` → `ItemModal` opens (`Dialog` with `DialogContent`)
2. Modal shows: item photo, name, description, allergens, sizes (if any), modifier groups (if any)
3. Guest selects size and modifiers → live price total updates in modal footer
4. Guest clicks "Add to cart" → item added to cart state, modal closes, Sonner toast "Added to cart"
5. If item is stop-listed: card renders at 50% opacity, click is a no-op, no modal opens

### Delivery / Pickup Selection (D-07 — up-front banner)

1. Default state on page load: no mode selected. Banner shows both pills unselected with placeholder copy "How would you like to receive your order?"
2. Guest selects Delivery: address input field appears below banner inline (not a modal)
3. Guest selects Pickup: address input disappears; pickup location info shown as static text
4. Mode selection persists in client state for the session (not persisted to server in Phase 5)

### Address Input (SITE-04 — stub)

1. Guest types delivery address in free-text input
2. On blur/submit: stub validation fires. In Phase 5 this always returns "We deliver to this area" (green badge). Real zone check wires in at Phase 9.
3. Visual feedback: green `Badge` with check icon when "valid", yellow `Badge` with warning icon for "outside zone" (stub never shows yellow in Phase 5 but component must support the state for Phase 9 wiring)

### Cart State

- Cart state is client-side only in Phase 5 (React state / zustand / context — implementation choice for planner)
- Cart trigger in TenantHeader shows item count `Badge` (accent background) when cart is non-empty
- CartDrawer opens via `Sheet` from the right
- Quantity controls: − and + buttons. Minimum quantity is 1. Removing last unit of an item does not auto-remove it — a dedicated remove (×) button handles removal
- Cart empty state: illustration-free, copy only (see Copywriting)

### Checkout Button (SITE-06, D-07 — disabled until Phase 8)

- Button renders with full visual weight (accent background) but `disabled` attribute set
- `Tooltip` on hover/focus: "Payment processing coming soon"
- Screen reader: `aria-disabled="true"`, `aria-describedby` pointing to tooltip text
- No loading state in Phase 5 — button stays disabled, never transitions to loading

### Content Pages (SITE-10, D-08 — minimal static)

- Routes: `/about`, `/delivery`, `/contact`, `/faq`
- Rendered from seeded per-tenant content field (plain text → paragraph split on newlines)
- No WYSIWYG, no rich text in Phase 5
- Layout: centered, max-width 720px, same TenantHeader, no CategoryNav or CartDrawer

### Locale Resolution (D-05)

Order of precedence: URL path prefix (`/en/`, `/uk/`) > `NEXT_LOCALE` cookie > `Accept-Language` header > fallback `en`. Default locale `en` is pathless (no `/en/` prefix in URL) to keep SEO URLs clean.

### Tenant Resolution (SITE-09)

- Production: subdomain `<slug>.resto.app` → tenant resolution via `TenantContextMiddleware` pattern
- Custom domain: `tenant_domains` table lookup via `findByDomainHost`
- Dev: query-param fallback `?tenant=<slug>` (local subdomains are awkward) — planner to implement as Next.js middleware header injection

## SEO & Meta Contract (SITE-09, D-03)

The website is the SEO surface. The following meta tags are required on the menu page:

- `<title>`: `{restaurantName} — Menu`
- `<meta name="description">`: `Order online from {restaurantName}. Browse our menu and place your order.`
- `<meta name="robots">`: `index, follow`
- `<link rel="canonical">`: `https://{slug}.resto.app/` (or custom domain equivalent)
- Open Graph: `og:title`, `og:description`, `og:image` (logo URL from brand theme, fallback to generic RestOS OG image)

Content pages get their own `<title>` from the page heading (e.g. `About — {restaurantName}`).

QR-menu (`apps/qr-menu`) must have `<meta name="robots" content="noindex">` — confirmed in D-03, to be enforced in Phase 6.

## Accessibility Contract

- All interactive elements must have visible focus ring (Tailwind `focus-visible:ring-2` using `--ring` token)
- Minimum contrast ratio: 4.5:1 for body text, 3:1 for large text and UI components (WCAG AA)
- Item modal: focus trap via Radix Dialog; `Escape` closes modal
- Cart drawer: focus trap via Radix Sheet; `Escape` closes drawer
- CategoryNav: keyboard-navigable with arrow keys; active category announces via `aria-current`
- Stop-listed items: `aria-disabled="true"` on card, `role="img"` for unavailability overlay text
- Price values: include accessible label combining value and currency (e.g. `aria-label="12.50 EUR"`)
- Cart count badge: `aria-label="{n} items in cart"` on cart trigger button

## Implementation Notes for Planner / Executor

1. **`apps/website` is a greenfield Next.js app.** It starts from `.gitkeep`. Scaffold with `pnpm create next-app` at the latest Next.js version (not pinned to admin's `^16.2.6` per D-04), then run `npx shadcn init` with new-york / neutral / cssVariables / lucide. Follow `apps/admin` patterns for `apiFetch`, env loading, and App Router structure.

2. **`@resto/ui` extraction.** `MenuItemCard` and `ItemModal` are candidates for the shared `packages/ui` layer (D-02) so Phase 6 (QR-menu) can consume them. The planner should decide whether to extract at Phase 5 or factor in Phase 6 — either is acceptable, but the components must live in a package-importable location, never imported app-to-app.

3. **Cart state.** Phase 5 requires no server-side cart — client state only. Use React context or Zustand in `apps/website`. The cart shape must match the future `ORD-03` payload shape (items with modifier snapshots and prices) so Phase 7/8 wiring is a server action addition, not a state refactor.

4. **Dev tenant resolution fallback.** Subdomains don't work on `localhost` without `/etc/hosts` edits. Implement a `?tenant=<slug>` query-param header injection in Next.js middleware for local development. This must not be active in production.

5. **Theming injection.** Inject tenant `primaryColor` as an inline style on `<html style="--primary: {hex}">` from the RSC layout. This overrides the default `--primary` token without duplicating the entire CSS file.

6. **Content pages (SITE-10).** Seeded content is plain text per tenant. Render as split-on-newline `<p>` tags inside the `ContentPage` component. No markdown parsing. Full WYSIWYG editor is Phase 15/MVP-2.
