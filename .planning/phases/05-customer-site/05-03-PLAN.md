## Trust Boundaries

| ------------------------------------ | --------------------------------------------------------------------------------------- |
| API `/v1/menu` response → RSC render | Tenant-authored menu strings (item names/descriptions/allergens) rendered to all guests |
| Brand theme → DOM                    | logoUrl + primaryColor flow into image src + CSS var                                    |

## STRIDE Threat Register

| Threat ID | Category                       | Component                                                | Disposition | Mitigation Plan                                                                                                                                                                     |
| --------- | ------------------------------ | -------------------------------------------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-05-03-X | Tampering (XSS)                | rendered menu item names/descriptions/allergens, content | mitigate    | Render all tenant strings as React text children (auto-escaped); never `dangerouslySetInnerHTML`; `localized()` returns plain strings. Item description is plain text, not markdown |
| T-05-03-I | Information Disclosure         | image src from brand.logoUrl / item.imageUrl             | mitigate    | Use `next/image`; image URLs are short-lived presigned GET links from the API (raw S3 keys never exposed per RES-92). No user-controlled `src` beyond API-provided URLs             |
| T-05-03-D | Denial of Service              | cold-Redis 5xx on menu fetch                             | mitigate    | RSC try/catch re-throws to `error.tsx` boundary (Pitfall 3) — page degrades, never white-screens; layout fetch already swallows the error for theming                               |
| T-05-03-E | Elevation (tenant enumeration) | notFound vs suspended distinction                        | accept      | 404 vs 403 distinction is inherent to the public API; reveals only existence, no tenant data — acceptable for a public storefront                                                   |
