# Phase 08.4 Plan 05: LocationScopeGuard + re-pointed BrandScopeGuard Summary

**Дефолтный `LocationScopeGuard` на location-grain (owner-bypass + existence-hiding 404 + 403 `location.access_denied`), 1:1 копия `BrandScopeGuard`, плюс перевод `BrandScopeGuard` на `findReachableBrandsForMember` — бренд теперь достижим только через активные scoped-локации, а не через отдельную `member_brand_scope`-таблицу.**

## Accomplishments

- `LocationScopeGuard` — байт-в-байт копия формы `BrandScopeGuard`: `@LocationNeutral()` opt-out (никакого opt-in декоратора), `baseRole === 'owner'` bypass, `NotFoundException` (404, не 403) при `activeLocationId === null` или `!= getLocationId()` (session-vs-request reconciliation, скрывает существование локации от non-owner), `ForbiddenException` с кодом `location.access_denied` при отсутствии location в `findLocationScopeForMember`.
- Зарегистрирован как `APP_GUARD` в `identity-http.module.ts` СРАЗУ после `BrandScopeGuard` — тот же порядок цепочки guard'ов (`AuthGuard → PermissionsGuard → BrandScopeGuard → LocationScopeGuard`), дефолтный fence на каждом operator-маршруте.
- `BrandScopeGuard` non-owner ветка перестала читать суперседед `member_brand_scope` — теперь джойнит `findReachableBrandsForMember` (`member_location_scope → locations(status='active') → brands`, D-04): бренд без активных scoped-локаций недостижим никому кроме owner.
- 11-кейсный юнит-матрикс на `LocationScopeGuard` (opt-out, context_required, operator_required, tenant_required, 2× owner-bypass, 2× session-mismatch → 404, 3× scope-denied/allow) + существующие 13 кейсов `brand-scope-guard.spec.ts` адаптированы под новую сигнатуру ридера — все зелёные.
