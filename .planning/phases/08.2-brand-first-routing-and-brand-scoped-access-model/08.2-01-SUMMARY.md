# Phase 08.2 Plan 01: Reserved Slug Expansion + D-06/D-07 Gates Summary

Reserved-slug contract extended with the 4 missing admin route words; ADMIN_ROOT_ROUTE_SEGMENTS exported as the shared D-06 contract; domain drift spec + admin route-derivation spec ship as the dual-gate; D-07 collision detector script ready as the Plan-04 pre-rename preflight gate.

## What Was Built

### Task 1 + 2: Expand RESERVED_SLUGS + domain drift spec (TDD)

`packages/domain/src/reserved-slugs.ts` — added 4 words: `onboarding`, `forgot-password`, `reset-password`, `accept-invitation`. Added `ADMIN_ROOT_ROUTE_SEGMENTS` constant listing all 6 non-dynamic admin root route segments.

`packages/domain/src/index.ts` — re-exports `ADMIN_ROOT_ROUTE_SEGMENTS` alongside existing exports.

`packages/domain/src/reserved-slugs.spec.ts` (new) — two describe blocks:

1. Drift gate: iterates `ADMIN_ROOT_ROUTE_SEGMENTS` and asserts each is in `RESERVED_SLUG_SET` — fails the domain test suite if a dev edits the constant without reserving the word.
2. Rejection gate: parses each newly-reserved word through `BrandSlugValue` and asserts `.success === false`, plus control `my-cafe` that passes.

### Task 3: D-07 collision detector script

`scripts/check-brand-slug-collisions.ts` (new) — tsx-runnable preflight gate. Opens platform-level DB read via `TenantAwareDb.withoutTenant('D-07 brand slug collision preflight audit', ...)`, selects `id, slug, status` from `brands` where `slug = ANY(RESERVED_SLUGS)`, exits 0 + "no collisions" or non-zero + offending rows. Imports `RESERVED_SLUGS` from `@resto/domain` (shared source, no duplicate literal). Uses `withoutTenant` (not raw connection) per CLAUDE.md no-raw-SQL-outside-packages/db rule.

Verified clean on dev DB (exit 0, `withoutTenant` WARN log confirms RLS bypass path used).

### Task 4: D-06 real route↔reserved coupling spec

`apps/admin/test/reserved-slugs-route-derivation.spec.ts` (new) — imports the live `router` from `apps/admin/src/main.tsx` (mocking `react-dom/client` and `@sentry/react` for safe jsdom import). Enumerates `router.routesById` using `route.fullPath` (not `options.path`) to get fully-assembled paths, extracts the first static path segment (excluding `$`-params, bare index, pathless group/layout routes), and asserts each is in `RESERVED_SLUG_SET` from `@resto/domain`.

Failure mode covered: adding `routes/(protected)/billing.tsx` with `path: '/billing'` and wiring it into main.tsx causes the spec to fail immediately because `router.routesById` will include `/billing` and `billing` won't be in `RESERVED_SLUG_SET`.

## Deviations from Plan

None — plan executed exactly as written. One implementation choice worth noting:

**Approach to main.tsx import:** Used `vi.mock('react-dom/client', ...)` + `vi.mock('@sentry/react', ...)` + jsdom `#root` element injection in `beforeAll` to safely import `main.tsx` without triggering DOM side effects. This is cleaner than the "acceptable alternative" (importing individual route files) because it reads from the truly assembled router.

**fullPath vs options.path:** Initial attempt using `route.options.path` extracted relative segment paths, causing `/dashboard/settings` to contribute `settings` (incorrect). Switched to `route.fullPath` (TanStack Router's assembled full path) which correctly gives `dashboard` for `/dashboard/settings`. The spec passes with this fix.
