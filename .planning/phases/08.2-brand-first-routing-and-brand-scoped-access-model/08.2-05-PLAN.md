guard with `@BrandNeutral`, D-10 reconciliation, and the inverted/extended unit test matrix.

## Trust Boundaries

| Boundary                                 | Description                                                                             |
| ---------------------------------------- | --------------------------------------------------------------------------------------- |
| non-owner member → brand-scoped route    | empty scope must mean zero access, not all-access                                       |
| controller author → guard                | a route missing the guard would leak; default-on + @BrandNeutral opt-out closes the gap |
| request brand (URL/header) → session pin | a non-owner presenting a brand != their pinned brand                                    |
| anonymous guest → @Public customer route | default-on guard 403s anonymous traffic unless the route is @BrandNeutral               |

## Default-On Blast Radius (D-11)

Flipping `BrandScopeGuard` to default-on means it runs on EVERY route without `@BrandNeutral`. The
guard throws `brand.operator_required` (L56) for any non-operator principal once a brand resolves,
so the blast radius includes all `@Public` routes — most dangerously the two anonymous,
customer-facing ones (`GET /v1/menu`, `POST /v1/orders`). The mitigation is the explicit
`@BrandNeutral` enumeration in Task 2 (PublicMenuController + OrdersController are named, not left
to a generic phrase), grep-asserted in Task 2 acceptance, unit-covered in Task 3, and
e2e-regression-guarded by a positive public-traffic case in Plan 06.
