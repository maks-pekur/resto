<objective>
Extend the reserved-slug contract so brand slugs can never shadow an admin root route once
the `/dashboard` prefix is dropped (D-06), add BOTH a domain-side drift test AND a real
route↔reserved coupling test in the admin app that fails when a new root route is added without
reserving it, and ship a one-shot collision detector for existing brand slugs (D-07). This plan
is the shared dependency that makes the Wave-2 SPA route move (Plan 04) safe.

Purpose: D-03's clean `/{brand}` form makes the first URL path segment a brand slug. Without
reserved-word coverage of the auth/onboarding root routes, a brand named `login` would shadow
the login route. D-06 mandates route-DERIVED reservation — not just a second hand-maintained
list. The genuine maintenance landmine is "add a root route to apps/admin and forget to reserve
the word"; the `ADMIN_ROOT_ROUTE_SEGMENTS` constant + a domain drift test alone does NOT catch
that (the drift test only fires if the constant itself changes). The fix is an admin-side test
that enumerates the ACTUAL assembled root-route segments from the router tree and asserts each is
reserved — so adding an unreserved root route is a failing test in the admin app. D-07 mandates a
pre-ship collision check.

Output: 4 new reserved words, an `ADMIN_ROOT_ROUTE_SEGMENTS` exported contract, a domain Vitest
drift spec, a unit spec proving the new words are rejected, an admin-side route-derivation spec
(the real route↔reserved coupling), and a collision-check script.

Scope guard (D-01/D-02): brand-level only. No `locations`, no `dynamicAccessControl`, no
custom-role primitives touched here.
</objective>
