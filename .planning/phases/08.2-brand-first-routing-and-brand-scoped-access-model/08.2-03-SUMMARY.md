Server-side `activeBrandId` session pin (D-09): BA additionalField(input:false) + injectable write adapter + `POST /v1/me/set-active-brand` with owner/non-owner scope semantics + AuthGuard surfacing.

## What Was Built

### Task 1: DB Column + BA Session Field + Initial Pin

`packages/db/src/schema/auth.ts` gained `activeBrandId: text('active_brand_id')`. Migration `0059_session_active_brand.sql` adds the column via `ALTER TABLE "session" ADD COLUMN IF NOT EXISTS "active_brand_id" text`.

`auth.config.ts` session block gains:

```ts
additionalFields: {
  activeBrandId: { type: 'string', defaultValue: null, input: false, returned: true }
}
```

`input: false` is the D-09 tamper-resistance gate: BA's `/update-session` endpoint (and any BA client `$update` call) silently ignores this field, identical to the existing `requiresPasswordChange` field.

`databaseHooks.session.update.after` detects the `/api/auth/organization/set-active` path and calls `resolveInitialBrandId` (inside the BA closure) to deterministically pin the first brand (`ORDER BY created_at ASC, id ASC`). Owner gets first tenant brand; non-owner gets first scoped brand via JOIN on `member_brand_scope`.

### Task 2: Injectable Write Adapter + Service + Endpoint

`SESSION_ACTIVE_BRAND_WRITER` (Symbol token + `SessionActiveBrandWriter` interface) at `application/ports/session-active-brand-writer.port.ts`.

`BetterAuthSessionActiveBrandWriter` at `infrastructure/better-auth/session-active-brand.adapter.ts`: resolves `auth.$context` (Promise) then calls `ctx.internalAdapter.updateSession(token, { activeBrandId })`.

`SetActiveBrandService.execute`:

- Owner path: validates brandId ∈ tenant brands via `BrandProvisioningPort.listForTenant`, writes via `SessionActiveBrandWriter`
- Non-owner path: reads `MemberBrandScopeReader.findBrandScopeForMember`, checks inclusion, throws `BrandOutOfScopeError` if not in scope or scope is empty, then writes
- Returns `{ slug }` of the pinned brand

`SetActiveBrandController`: `POST /v1/me/set-active-brand`, `@HttpCode(200)`, `@RequiresTenantContext()`, `@Permissions({ tenant: ['read'] })`. Body: `{ brandId: z.string().uuid() }`.

### Task 3: AuthGuard Surfacing + E2E Spec

`AuthGuard.canActivate` now sets `req.activeBrandId = sessionData.session.activeBrandId ?? null` and `req.sessionToken = sessionData.session.token` after successful session resolution.

`declare module 'fastify'` augmentation in `auth.guard.ts` adds these three fields to `FastifyRequest`.

E2E spec (`set-active-brand.e2e.spec.ts`) covers:

- Tamper resistance via `/api/auth/update-user` (cannot forge `activeBrandId`)
- Owner re-pin to any tenant brand → 200 + slug
- Non-owner in-scope re-pin → 200 + slug
- Non-owner out-of-scope re-pin → 403 + `{ code: 'brand.out_of_scope' }`
- Deterministic initial pin after org-switch: `session.activeBrandId` is non-null and matches the first brand by `created_at ASC`
- Unauthenticated → 401
- Invalid UUID body → 400
- Owner cross-tenant brand attempt → 403
- Non-owner null scope (no scope rows) → 200 (unrestricted within tenant)
