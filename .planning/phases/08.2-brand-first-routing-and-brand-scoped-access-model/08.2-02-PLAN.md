Add brand-level Postgres RLS (D-14) mirroring the established tenant RLS double-enforcement
pattern: a new `app.current_brand` GUC, a `current_brand_id()` reader, an `app_bind_brand`

mask a DB missing the policy.

catalog + orders surface. This is the defense-in-depth net beneath the BrandScopeGuard.

Output: migration 0058, client `withBrand`-binding inside `withTenant`, preflight assertion,
and an explicit accepted-debt note for payments.

## RECONCILIATION DECISION (tracked — do NOT bury)

CONTEXT D-14 names "payments/payouts + catalog" for brand RLS. RESEARCH (VERIFIED:
packages/db/src/schema/ordering.ts:126-202) found `payments` and `payment_refunds` have NO
`brand_id` column — they reach a brand only via `orders.brand_id`. Adding brand RLS to them
requires a `brand_id` column + data backfill, which is OUT OF SCOPE this phase (D-02 "no schema
bloat beyond what's needed"). RESOLUTION: apply brand RLS now to the directly-addressable
`brand_id NOT NULL` tables (9 `menu_*` + `orders`); document payments/payouts brand isolation
as **app-layer-only accepted debt** (BrandScopeGuard on the payouts controller + tenant RLS).
This is exactly ROADMAP SC-6's escape hatch ("otherwise app-layer-only isolation is documented
as accepted debt"). Record this in 08.2-02-SUMMARY.md "Accepted Debt" + a `-- D-14 SCOPE NOTE`
comment block at the top of 0058_brand_rls.sql.
