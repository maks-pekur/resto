# Cross-AI Plan Review — Phase 08.2

> Reviewers available this run: **Codex** only. `claude` skipped (self — running inside Claude Code); gemini / opencode / qwen / cursor / coderabbit not installed.

## Codex Review

## Summary

The six plans are directionally strong and likely achieve Phase 08.2’s core goal: clean brand-first admin routing plus the real access-control delta of default-deny brand scope, server-session active-brand pinning, default-on brand guard coverage, and brand RLS on catalog/orders. The plan set is unusually explicit about threat cases and verification. I would approve the architecture with revisions before execution, mainly around route-derived reserved slugs, default-on guard opt-out completeness, session pin initialization edge cases, and the exact RLS policy semantics.

## Strengths

- Strong sequencing: 08.2-01/02/03 prepare shared contracts, DB policy, and session pin before 08.2-04/05 consume them; 08.2-06 correctly waits for all security primitives.
- D-08 default-deny is handled with the right owner-safety invariant: owner bypass before scope lookup, non-owner null scope denied.
- D-09 uses Better Auth session state instead of cookies, with `input:false` and an e2e planned to prove client writes cannot mutate `activeBrandId`.
- D-10 reconciliation is explicitly tested as existence-hiding 404 for non-owner pin mismatch.
- The `authClient.organization.setActive({ organizationId: brand.id })` bug is correctly identified and removed.
- 08.2-02 makes the payments RLS limitation explicit instead of pretending to protect tables without `brand_id`.
- 08.2-06 includes positive public-traffic tests, which is essential after making `BrandScopeGuard` default-on.

## Concerns

- **HIGH: 08.2-01 does not truly satisfy D-06 “derived automatically from admin route table.”**  
  `ADMIN_ROOT_ROUTE_SEGMENTS` is another manually maintained list. The drift test only fails if someone updates that constant but forgets `RESERVED_SLUGS`; it will not catch a new root route added in `apps/admin/src/main.tsx` while the constant is untouched.

- **HIGH: 08.2-05 default-on opt-out audit is risky and underspecified for non-HTTP/public-adjacent routes.**  
  The plan names public menu/orders, `/v1/me`, internal routes, team/settings, auth/health, but explicitly calls out “webhooks?” only in the review prompt, not in the plan. Stripe/payment webhooks, Better Auth-mounted routes, health/readiness, metrics, invitation acceptance, password reset, onboarding, tenant provisioning/offboarding, and any API routes that intentionally do not bind a brand need a concrete audited list.

- **HIGH: 08.2-03 session pin initialization has possible null-pin bypass semantics.**  
  08.2-05 only checks mismatch “when both are non-null.” A non-owner with `activeBrandId = null` but valid scope rows could access any scoped brand in their scope, which violates D-13’s “pinned to exactly one active brand at a time.” Null should be treated as invalid for non-owner brand-scoped requests unless the endpoint is the controlled re-pin path.

- **MEDIUM: 08.2-02 RLS pass-through `current_brand_id() IS NULL` weakens DB defense for brand-scoped tables.**  
  It preserves tenant-level queries, but it also means any application path that forgets to bind a brand still sees all tenant brands. That is better than breakage, but it is not full defense-in-depth. The plan should distinguish tenant-level repository methods from brand-scoped methods and test that brand-scoped HTTP paths actually bind the GUC.

- **MEDIUM: 08.2-02 accepted debt on payments/payouts is reasonable, but payouts must be audited route-by-route.**  
  Because payouts are named in D-14, relying on app-layer guards is acceptable only if all payout/payment read/write endpoints are default-guarded, use brand slug reconciliation, and do not have brand-neutral annotations by accident.

- **MEDIUM: 08.2-03 depends on `internalAdapter.updateSession` access from Nest services.**  
  The plan assumes a clean injectable path to Better Auth internals. If auth config currently creates BA in a closure, this may require a small adapter service. That should be planned explicitly to avoid reaching into config internals from application services.

- **MEDIUM: 08.2-04 old `/dashboard/...` handling is weak.**  
  Success criteria say old links handled per context, but plan mostly removes `/dashboard` and allows 404. Given Stripe and bookmarked admin links, add an explicit temporary redirect route for `/dashboard/$brandSlug/*` to `/$brandSlug/*`, or document a deliberate breaking change.

- **LOW: 08.2-01 D-07 collision detector is not actually migration-time.**  
  It is a script gate, not migration-enforced. That may be fine, but then the plan should stop calling it migration-time or add a migration/preflight that fails on collisions.

- **LOW: 08.2-06 e2e around guest `POST /v1/orders` is too loose.**  
  “200/201 or domain-level validation error” is acceptable, but it should explicitly assert the error code is not `brand.operator_required`, `brand.context_required`, or `brand.access_denied`.

## Suggestions

- Replace 08.2-01’s manual drift seam with a real shared route contract: either make `apps/admin` import `ADMIN_ROOT_ROUTE_SEGMENTS` to build root routes, or add an admin-side test that inspects/parses the actual route assembly and compares it to `RESERVED_SLUG_SET`.

- In 08.2-05, add a generated or grep-backed controller audit artifact listing every controller and its classification: `brand-scoped`, `brand-neutral`, `public brand-neutral`, `internal`, `webhook`, `BA-managed`. Require reviewer signoff for every `@BrandNeutral`.

- Change D-10 implementation to: for non-owner brand-scoped requests, `activeBrandId` must be non-null and equal to resolved `brandId`. Only owners and explicitly brand-neutral endpoints may proceed with null pin.

- In 08.2-02, consider adding a `withTenantNoBrand()` or explicit repository escape hatch for tenant-level queries, while making brand-bound HTTP paths bind brand by default. At minimum, 08.2-06 should prove a normal admin brand route binds `app.current_brand`.

- Add payout/payment endpoint tests to 08.2-06: non-owner scoped to Brand A cannot read or start onboarding/payout flows for Brand B; owner can.

- Add a short-lived `/dashboard/$brandSlug/*` SPA redirect route in 08.2-04 unless the team intentionally accepts bookmark breakage.

- Make 08.2-03 specify how the BA session updater is injected, and add a test for login/org-switch where a non-owner with multiple allowed brands gets a deterministic initial pin.

## Risk Assessment

**Overall risk: MEDIUM-HIGH.** The architecture is sound and the plans cover the right security invariants, but this phase changes foundational access-control defaults and routing at the same time. The biggest remaining risks are false confidence in reserved-slug “derivation,” incomplete `@BrandNeutral` auditing after default-on guard inversion, and null active-brand session behavior for non-owners. Fix those before execution and the plan drops closer to MEDIUM.

### Top Concerns (highest priority — all HIGH)

1. **D-06 reserved-slug "derivation" is still manual (08.2-01).** `ADMIN_ROOT_ROUTE_SEGMENTS` is a hand-maintained constant; the drift test only fires if that constant changes, NOT when a new root route is added to `apps/admin/src/main.tsx`. The maintenance landmine D-06 was meant to close is still open. → Either have the admin route tree be *built from* `ADMIN_ROOT_ROUTE_SEGMENTS` (single source), or add an admin-side test that parses the actual assembled route tree and diffs it against `RESERVED_SLUG_SET`.

2. **Default-on `@BrandNeutral` opt-out audit is incomplete (08.2-05).** The plan names public menu/orders/me/team/settings/auth/health but does not enumerate webhooks (Stripe/payment), Better-Auth-mounted routes, metrics/readiness, invitation-acceptance, password-reset, onboarding, and tenant provisioning/offboarding. After the guard goes default-on, any missed brand-neutral route 403s (breakage) — and any wrongly-neutral route leaks. → Produce a grep-backed controller-classification audit artifact (`brand-scoped | brand-neutral | public | internal | webhook | BA-managed`) with explicit signoff for every `@BrandNeutral`.

3. **Null active-brand pin may bypass single-active-brand (08.2-03 / 08.2-05).** Reconciliation only checks mismatch "when both non-null"; a non-owner with `activeBrandId = null` but valid scope rows could reach any in-scope brand, violating D-13. → For non-owner brand-scoped requests, require `activeBrandId` non-null AND equal to the resolved brand; only owners and explicitly brand-neutral endpoints proceed with a null pin. Also specify the deterministic initial pin on login for a non-owner with multiple allowed brands.

### Secondary (MEDIUM)

- RLS `current_brand_id() IS NULL` pass-through means any path that forgets to bind a brand still sees all tenant brands — add a test proving a normal admin brand route actually binds `app.current_brand` (08.2-02/06).
- Payouts are named in D-14 but only app-layer-protected — audit every payout/payment endpoint is default-guarded with brand reconciliation and not accidentally `@BrandNeutral`; add cross-brand payout e2e (08.2-02/06).
- Specify how `internalAdapter.updateSession` is injected into Nest services (likely a small adapter rather than reaching into BA config internals) (08.2-03).
- Old `/dashboard/...` links: add an explicit temporary `/dashboard/$brandSlug/*` → `/$brandSlug/*` SPA redirect, or document the deliberate breaking change (08.2-04).
