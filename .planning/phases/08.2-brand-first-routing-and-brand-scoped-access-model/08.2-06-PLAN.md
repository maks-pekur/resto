<objective>
Prove the security model end-to-end against a LIVE database that already carries the brand RLS
policy (Plan 02's BLOCKING apply must have run). This is the SC-4 named isolation test: forge a
cookie/URL to a brand outside the session pin or the member's scope and assert an existence-hiding
404/403; read a brand-owned table cross-brand within one tenant and assert zero rows (brand RLS);
AND prove a normal admin brand-scoped HTTP request actually BINDS `app.current_brand` on the real
request path (not just that the policy exists). Plus the D-14 payout boundary: a non-owner scoped
to Brand A cannot read or start onboarding/payout flows for Brand B while an owner can, and no
payout/payment controller is accidentally `@BrandNeutral`. Plus two regression nets: the Stripe
return URL points at `/{slug}/payouts` (no `/dashboard/`), and `/update-session` cannot move the
active-brand pin (input:false). And — a POSITIVE public-traffic case proving the Plan 05 default-on
guard flip did NOT 403 the two anonymous customer routes.

Purpose: this is the goal-backward proof that the access core actually isolates — not just that
the code typechecks — AND that it did not regress the customer order/menu path or the payout flow.
It is the final gate; it depends on the default-deny flip + D-10 reconciliation + the @BrandNeutral
opt-out audit on the customer/webhook/payout controllers (Plan 05), the session pin (Plan 03), the
flattened Stripe return URL + legacy redirect (Plan 04), and the applied brand RLS migration
(Plan 02).

PRECONDITION (BLOCKING, from Plan 02 Task 3): migration 0058 is applied to the live test DB and
the boot preflight `assertBrandRlsInstalled` passes. If the policy is not live, this e2e would
false-positive. The e2e harness MUST run against the migrated DB.

Output: the brand-isolation e2e matrix (incl. the GUC-binding proof + public-traffic survival
case), the cross-brand payout/payment app-layer e2e, an extension to the cross-tenant isolation
spec covering the new brand-owned tables, and the Stripe-URL unit regression test.

Scope guard (D-01/D-02): tests cover brand-level isolation only. No location-level fixtures, no
dynamic-AC. Payments brand isolation is NOT asserted at the RLS layer (accepted debt, Plan 02);
the payout/payment controllers' app-layer BrandScopeGuard is the boundary tested instead.
</objective>
