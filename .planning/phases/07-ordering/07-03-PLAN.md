<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client cart input → Order.create totals | Client must not control the computed price; totals are derived server-side from snapshot values |
| state transition requests → aggregate guards | Illegal transitions (e.g. completing an unpaid order) must be rejected in the domain |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-05 | Tampering | Order.create totals | mitigate | Server computes subtotal/discount/total from snapshot values in minor units; client-supplied prices are the snapshot the guest already saw, never an arbitrary total field (no `total` input accepted) |
| T-07-06 | Tampering | state machine transitions | mitigate | Every transition validates its source state and throws InvalidOrderTransitionError; spec asserts each illegal source is rejected |
| T-07-04 | Tampering | discount in totals | mitigate | Discount comes from `applyDiscount` (clamped ≥0, ≤base in Plan 01); aggregate never subtracts an unclamped value |
| T-07-DRAIN | Repudiation | event emission | mitigate | pullEvents drains exactly once (spec-asserted); no duplicate or lost domain events feeding the outbox |
</threat_model>
