<threat_model>

## Trust Boundaries

| Boundary                                     | Description                                                                     |
| -------------------------------------------- | ------------------------------------------------------------------------------- |
| anonymous client → POST create-order         | Untrusted, unauthenticated input; spam/abuse + price/currency tampering surface |
| client idempotency-key → orders unique index | Client controls the key; cross-tenant collisions must be harmless               |
| order rows → cross-tenant read               | RLS + ScopedTx must isolate every read                                          |

## STRIDE Threat Register

| Threat ID | Category               | Component                                | Disposition | Mitigation Plan                                                                                                                                                      |
| --------- | ---------------------- | ---------------------------------------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-07-05   | Tampering              | price/total tampering                    | mitigate    | Totals computed server-side from the snapshot; DTO accepts no `total`/`subtotal`/`discount` amount field — only `discountSpec` (clamped by applyDiscount)            |
| T-07-07   | Tampering              | mismatched currency across cart items    | mitigate    | Service validates every cart item currency equals the brand currency; rejects on mismatch (RESEARCH open-Q3)                                                         |
| T-07-08   | Spoofing               | idempotency-key collision across tenants | mitigate    | UNIQUE (tenant_id, idempotency_key) + composite ON CONFLICT target — cross-tenant same-key is two independent orders; spec asserts it                                |
| T-07-01   | Information disclosure | order reads                              | mitigate    | findById/findByIdempotencyKey go through db.withTenant + explicit `eq(tenant)` filter on parent AND child reads (RLS + ScopedTx, I-1)                                |
| T-07-09   | Denial of service      | anonymous create-order spam              | accept      | Input is bounded by Zod (items array, max lengths); rate-limiting is a platform concern (RateLimitGuard exists) and out of Phase 7 scope — flagged, accepted for now |
| T-07-PII  | Information disclosure | customer_name/phone                      | mitigate    | PII stored only in orders table (tenant-erasure-covered); never copied into the OrderCreated outbox payload (enforced in Plan 02)                                    |

</threat_model>
