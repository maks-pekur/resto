# Phase 10.6 Plan 03: Published-menu read model and the ingredient wire contract Summary

**`/v1/menu` now emits a top-level `modifierOptions[]` deduped-by-id, groups carry `display`/`behaviour`/`optionIds` instead of a numeric range, items carry their composition, and `/v1/menu/availability` answers two stop lists on one ETag — the catalog repository assembles all of it through the two new link tables.**

- **Completed:** 2026-09-03T11:33Z
- **Tasks:** 3
- **Files modified:** 8 (5 planned + 3 unplanned test-fixture fixes, see Deviations)

## Accomplishments

- `PublishedMenu.modifierOptions[]` is a single deduped array built from a `Map<string, PublishedMenuModifierOption>` fed by three sources (group links, item links, assembled composition lines) — one bacon in three groups is one payload entry and one price (D-03/ING-09)
- `PublishedMenuModifierGroup` now carries `display` (tiles\|tabs) + `behaviour` (one\|several) + `optionIds`, with no numeric selection range and no per-dish override surface (D-07/D-12)
- `PublishedMenuItem` carries `extraOptionIds` (the dish's single ingredients), `compositionMode`, `composition` (free text) and `compositionLines` (assembled, `{ optionId, removable }` only — no grams/unit/cost, D-15)
- `CatalogRepository.listStoppedIngredientIds` reads `menu_option_stop_list` per location, computed per read and never materialised at publish (D-23)
- `GET /v1/menu/availability` answers `stoppedIngredientIds` beside `stoppedItemIds` on the same `stopVersion` ETag — no second cache key, no change to the menu ETag (D-21/D-23)
- Every new public-facing free-text array (`composition`, `compositionLines`) carries an explicit `.max(...)` bound at the HTTP boundary (ASVS V5)
- `menu_modifier_options.image_s3_key` never crosses the wire — the repository emits `imageUrl` via the existing `ImageUrlPort.publicUrl`, and the wire schema has no `s3Key`/`imageS3Key` field
