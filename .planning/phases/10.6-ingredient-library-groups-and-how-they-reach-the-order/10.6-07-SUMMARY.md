## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `SetItemCompositionInputSchema` built as a flat object, not `z.discriminatedUnion`**
- **Found during:** Task 2, first `pnpm exec nx run api:typecheck` after adding the DTO
- **Issue:** `10.6-PATTERNS.md`'s suggested shape (`z.discriminatedUnion('mode', [...])`) fails to compile once `export class SetItemCompositionInputDto extends createZodDto(SetItemCompositionInputSchema) {}` tries to extend a class from it — TS2509: "Base constructor return type ... is not an object type ... with statically known members." `nestjs-zod`'s `createZodDto` requires the schema's `z.infer` to resolve to a single object type; a discriminated union's inferred type is a union of two object types, which TypeScript cannot use as a class base.
- **Fix:** Replaced the union with a flat `z.object({ mode, text: [].default([]), lines: [].default([]) })` — the same shape `UpsertItemInputSchema` already uses for these three composition fields, proven to compile there. `SetItemCompositionService.execute` clears whichever array doesn't match `input.mode` before calling the repository, so the wire contract stays "one array is authoritative per mode" even though both are technically present on the DTO.
- **Files modified:** `apps/api/src/contexts/catalog/application/dto.ts`
- **Verification:** `pnpm exec nx run api:typecheck --skip-nx-cache` — 0 errors, confirmed the compiler actually ran (not a cache hit) both before the fix (saw the TS2509 error) and after (clean).
- **Committed in:** `4f9378c1`
