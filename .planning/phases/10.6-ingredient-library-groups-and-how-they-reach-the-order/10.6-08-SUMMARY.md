## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `catalog.e2e.spec.ts`'s IMAGE_URL_PORT test stub was missing `publicUrl`, causing every `/v1/menu` read with a photo or an `imageS3Key` to 500**
- **Found during:** Task 3, first run of `catalog.e2e.spec.ts` after migrating the modifier-group bodies — nine tests failed with `expected 500 to be 200`, including the very first, unmodified test in the file
- **Issue:** A raw-exception debug trace (temporarily added to `exception.filter.ts`, then reverted) showed `TypeError: this.imageUrl.publicUrl is not a function` at `catalog-drizzle.repository.ts:89`, inside `publicPhotos()`. `ImageUrlPort` has three methods (`publishPublicCopy`, `publicUrl`, `presignGet`); the production `S3SignedImageUrlAdapter` implements all three, but `catalog.e2e.spec.ts`'s `overrideProviders` stub (added well before this phase — `git blame` traces the `publicUrl`/"addressed public photo" architecture to commit `df8c9f87`, unrelated to phase 10.6) only implemented `presignGet`. Every `/v1/menu` read whose item had a photo or whose modifier option had an `imageS3Key` crashed the moment `loadPublishedMenu` tried to compute a public photo URL.
- **Fix:** Added `publicUrl: (key) => \`https://public.test/${key}\`` and `publishPublicCopy: () => Promise.resolve()` to the stub, matching the pattern already proven correct in `catalog-public-photo-url.e2e.spec.ts`. Updated the two assertions that still expected the old presigned-URL format (`'https://signed.test/...?expires=300'`) to the new addressed format (`'https://public.test/menu/margherita.webp'`) — those two assertions were themselves stale from the same pre-10.6 architecture change and would never have passed even with a correct mock.
- **Files modified:** `apps/api/test/e2e/catalog.e2e.spec.ts`
- **Verification:** `catalog.e2e.spec.ts` went from 20/29 to 29/29 passing after the fix; confirmed `catalog-reads.e2e.spec.ts` did not need the same fix (it never calls `/v1/menu`, only operator-surface routes that use `presignGet`).
- **Committed in:** `bedb152f` (Task 3 commit)

**2. [Rule 1 - Bug] `SetItemCompositionInputDto` cannot be spread onto a plain object (`no-misused-spread`)**
- **Found during:** Task 1, first pre-commit hook run after adding `setItemCompositionRoute`
- **Issue:** `this.setItemCompositionService.execute({ itemId: id, ...input })` spreads a `createZodDto`-generated class instance; ESLint's `@typescript-eslint/no-misused-spread` correctly flags this as losing the class prototype.
- **Fix:** Replaced the spread with explicit field access (`mode: input.mode, text: input.text, lines: input.lines`).
- **Files modified:** `apps/api/src/contexts/catalog/interfaces/http/catalog.controller.ts`
- **Verification:** `pnpm exec eslint` clean; `pnpm exec nx run api:typecheck --skip-nx-cache` 0 errors.
- **Committed in:** `6ec19899` (Task 1 commit)

**3. [Rule 3 - Blocking, `RESTO_SPINE_MIGRATION=1`] Regenerating the OpenAPI contract broke `apps/admin`'s typecheck**
- **Found during:** Task 2, first commit attempt of the regenerated `docs/api/openapi.yaml` / `packages/api-client/src/generated/api.ts`
- **Issue:** The repo's pre-commit hook runs `nx affected -t typecheck --uncommitted`, which correctly identifies `apps/admin` as affected by a `packages/api-client` change. `apps/admin`'s existing components still read the retired `minSelectable`/`maxSelectable`/`ingredients` fields the new contract dropped — 5 type errors across 4 files. Fixing `apps/admin`'s call sites is explicitly out of this plan's `files_modified` scope and explicitly scoped to plans 11-15 (this plan's own `<why_this_plan_matters>` states so directly, and the orchestrator's `<expected_baseline>` list deliberately omits `apps/admin`).
- **Fix:** Committed Task 2 with `RESTO_SPINE_MIGRATION=1`, the repo's documented escape hatch for exactly this situation ("a rename that crosses packages and cannot leave the repo type-green until every call site is fixed... the phase that sets it owes a green gate before it closes" — `.husky/pre-commit`). `lint-staged` (prettier/eslint) still ran normally; only the affected-typecheck step was skipped for this one commit.
- **Files modified:** none beyond the two generated artifacts already being committed
- **Verification:** `apps/api:typecheck` (the baseline this plan owns) confirmed 0 errors via a separate, non-bypassed `pnpm exec nx run api:typecheck --skip-nx-cache` run both before and after this commit. `apps/admin`'s red state is a known, expected, cross-plan handoff — not a signal something in this plan's own scope broke.
- **Committed in:** `2381aded` (Task 2 commit)
