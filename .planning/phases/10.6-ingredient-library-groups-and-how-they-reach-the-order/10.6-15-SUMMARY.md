## Accomplishments

- `IngredientStopListTable` mirrors `stop-list-table.tsx` minus the Category column (ingredients carry none), reading `OptionStopListItemApi`'s `optionName`/`imageUrl` shape and calling `toggleIngredientStopList`; the stop-list route hides the whole sub-section (no `Separator`, no heading, no table) when the ingredient stop list is empty, and the Today's-86 badge now counts `items.length + ingredients.length`
- Found and fixed a real, pre-existing production bug while extending `resetStopList` for ingredients: the function deleted stop-list rows by the row's own primary key (`item.id`) instead of the stopped item's id (`item.itemId`) — the two are different UUIDs (`catalog-drizzle.repository.ts`'s `listStopListWithStoppedAt` returns both on the same row), and the DELETE route filters on the latter, so every reset silently failed to resume anything. Fixed inside `resetStopList` (in this plan's own file list) for both items and the new ingredients loop; the identical bug in `stop-list-table.tsx`'s per-row resume `Switch` is out of this plan's `files_modified` scope and logged to `deferred-items.md` instead

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `resetStopList` deleted by the wrong id for items (pre-existing, found while extending it for ingredients)**
- **Found during:** Task 1
- **Issue:** `menu_stop_list` rows carry their own primary key (`id`) separate from the FK to the stopped item (`itemId`) — confirmed in `catalog-drizzle.repository.ts`'s `listStopListWithStoppedAt` (`return { id: s.id, itemId: s.itemId, ... }`) and in the schema (`id: pkUuid()`, unrelated to `itemId`). The DELETE route (`DELETE stop-list/:itemId`) filters by `itemId` (`removeFromStopList`'s `eq(schema.menuStopList.itemId, input.itemId)`), confirmed against the ingredient-side e2e test's identical pattern (`ingredient-stop.e2e.spec.ts:224`, `DELETE stop-list/options/:optionId`). `resetStopList`'s existing loop called `apiFetch(\`/v1/catalog/stop-list/${item.id}\`, ...)` — the row's own PK, not the item id — so every reset silently failed to resume any item (`StopListService.unstop` throws `StopListItemNotFoundError` when the filter matches nothing).
- **Fix:** Changed the item loop to `item.itemId`. The new ingredients loop was written correctly from the start (`item.optionId`, matching `toggleIngredientStopList`'s own signature).
- **Files modified:** `apps/admin/src/lib/queries/catalog.ts`
- **Verification:** Read `catalog-drizzle.repository.ts` and the e2e test directly; `admin:typecheck` and the full `apps/admin` test suite stayed green.
- **Committed in:** `d62fe6ba` (Task 1 commit)

**2. [Rule 2 - Missing critical functionality] `resetStopList`'s reset never invalidated the ingredient stop-list cache**
- **Found during:** Task 1
- **Issue:** `todays-86-reset-button.tsx` only invalidated `['catalog', 'stop-list']` after a reset. Since Task 1 extends `resetStopList` to also clear ingredient stops, the UI would show stale (still-stopped) ingredient rows until an unrelated refetch, even though the server-side data was correctly cleared — the plan's own must-have truth ("the Today's-86 count and reset both cover them") requires the UI to actually reflect it.
- **Fix:** Added `void queryClient.invalidateQueries({ queryKey: ['catalog', 'ingredient-stop-list'] })` alongside the existing invalidation.
- **Files modified:** `apps/admin/src/components/menu/todays-86-reset-button.tsx`
- **Verification:** Read the component; matches the existing invalidation pattern exactly.
- **Committed in:** `d62fe6ba` (Task 1 commit)

**3. [Rule 2 - Missing critical functionality] No aria-label existed for the "stop" direction of the new bidirectional Switch**
- **Found during:** Task 2
- **Issue:** The only existing stop-list aria-label key, `resumeAriaLabel` ("Возобновить {{name}}"), only makes sense for a resume-only control. The Ingredients grid's new Switch is bidirectional (can stop or resume the same ingredient), so using `resumeAriaLabel` unconditionally would announce "Resume X" to a screen reader on an ingredient that is not yet stopped.
- **Fix:** Added one new key, `menu.stopList.stopAriaLabel` ("Остановить {{name}}"/"Stop {{name}}"/"Pausar {{name}}"), to all three catalogs; the grid picks between the two based on the ingredient's current stopped state.
- **Files modified:** `apps/admin/src/lib/i18n/messages/{ru,en,es}.json`
- **Verification:** `admin:typecheck` clean; JSON validity confirmed for all three files.
- **Committed in:** `aa4359ca` (Task 2 commit)
