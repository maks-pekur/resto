## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Worktree `node_modules` resolved `@resto/*` packages to the main repo checkout instead of this worktree**
- **Found during:** Task 2 commit attempt (lint-staged's type-aware `eslint --fix`)
- **Issue:** Every `node_modules` directory in this worktree (root + every `apps/*`/`packages/*`) was a symlink pointing at the corresponding directory in the main repo checkout (`/Users/mp_dev/projects/RestOS/...`), not a worktree-local install. `apps/qr-menu/tsconfig.json` and `apps/website/tsconfig.json` already carry an explicit `paths` override for `@resto/api-client` (bypassing this for that one package), but `packages/ui/tsconfig.json` has no such override for any `@resto/*` package, and none of the three tsconfigs override `@resto/cart`. As a result, `tsc`/ESLint's type-aware rules and — more seriously — Vite/Vitest's actual runtime module resolution for `@resto/api-client`, `@resto/cart` and `@resto/ui` inside `apps/qr-menu`/`apps/website` were reading the **main repo's stale copies** of packages this plan edits, not this worktree's edits. This would have made `pnpm exec nx run qr-menu:typecheck`/`website:typecheck`/`ui:typecheck` and `pnpm -C apps/qr-menu exec vitest run`/`pnpm -C apps/website exec vitest run` unreliable for the rest of the plan (false errors from Task 1's own already-committed types, and test runs exercising code that wasn't actually mine).
- **Fix:** Removed every `node_modules` symlink in the worktree (a plain `rm` on the symlink object itself — never anything reached through it) and ran `pnpm install --frozen-lockfile` from the worktree root, which materialized a real, worktree-local `node_modules` tree (9.7s, served from the shared pnpm content-addressable store — no new package versions, same lockfile). Every `@resto/*` package now resolves within this worktree for both type-checking and actual test execution.
- **Files modified:** None (node_modules is gitignored / not tracked; no source or config file was changed by this fix).
- **Verification:** `pnpm exec nx run ui:typecheck --skip-nx-cache` dropped from a spurious `modifierOptions does not exist on MenuDto` error to exactly the expected task-3-not-done-yet error set; after task 3, `ui:typecheck`, `qr-menu:typecheck`, `website:typecheck` all pass, and `pnpm -C apps/qr-menu exec vitest run` / `pnpm -C apps/website exec vitest run` both pass in full (89 and 65 tests respectively).
- **Committed in:** not committed — filesystem/environment fix only, no tracked-file diff.
- **Caution for the orchestrator:** my first attempt at `pnpm install --frozen-lockfile` (before removing the symlinks) was run while `node_modules` was still a symlink, and pnpm followed it, recreating the **main repo's** real `node_modules` directory in place (same lockfile, so package content should be equivalent — this was a `--frozen-lockfile` reinstall, not a version change). No tracked file was touched, but the main checkout's `node_modules` directory was touched by this worktree's execution. Confirmed the directory still exists and is populated afterward; not independently verified as byte-identical to its pre-existing state.
