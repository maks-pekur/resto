## Known Stubs / Limitations

- **`tabs`+`one` groups (`SegmentedChoice`) do not grey out a stopped ingredient.** Per this plan's own acceptance criteria, `segmented-choice.tsx` must be unchanged (`git diff --stat` confirms zero diff) and the tabs+one branch's JSX is byte-identical to before this plan. `SegmentedChoice` has no per-option disabled/unavailable concept, so a stopped ingredient inside a `tabs`+`one` group (e.g. the two dev groups, dough/sauce) currently renders selectable with no visual warning. This is a narrow, deliberate scope boundary set by the plan text itself (not something this plan silently dropped), consistent with D-25's "known consequence, accepted" framing — the order is still refused server-side if the guest picks a stopped option (plan 04). Extending `SegmentedChoice` with a disabled-option concept, if wanted, is a Rule-4 architectural change out of this plan's scope.
