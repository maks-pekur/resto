end to end (RESEARCH §8.4), and an exclusion has nowhere structured to land (D-18).

<design_decisions_this_plan_owns>
These have no analog in the codebase; they are decided here, not discovered mid-implementation.

1. **One ingredient can sit in several groups**, so `PricedModifierOption.groupId: string` becomes
   `groupIds: readonly string[]`. A direct dish attachment has an empty array.
2. **The group an order row records** is resolved server-side: the first id in `option.groupIds`
   that is also in `published.modifierGroupIds`, otherwise `null`. `order_modifiers.modifier_group_id`
   is already nullable and needs no migration.
3. **An exclusion is validated, not trusted.** `PricedMenuItem.removableOptionIds` carries the ids
   the dish's assembled composition marks `removable: true`; an `excluded` row whose option is not
   in that list is refused exactly like an option outside the allowed set.
4. **Exclusions do not count toward group rules and carry no money**: `priceDelta` is forced to
   `'0'` and `amount` to `1` server-side, regardless of what the request said.
</design_decisions_this_plan_owns>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| guest browser → `POST /v1/orders` | fully untrusted: item ids, option ids, names, amounts and now `kind` all arrive from the client |
| pricing snapshot → order total | the server's only source of money; anything the client claims about price is ignored |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10.6-04-01 | Tampering | client-forged price on a modifier row | mitigate | `priceDelta` is read from `optionsById`, never from the request; the request schema has no price field (existing invariant, preserved) |
| T-10.6-04-02 | Tampering | client-forged allowed-set — ordering an ingredient the dish does not offer | mitigate | union check against `published.modifierGroupIds` and `published.extraOptionIds`; the union EXTENDS the check, it never weakens it |
| T-10.6-04-03 | Tampering | client-forged exclusion — sending `kind: 'excluded'` for an arbitrary option to smuggle a free row onto the ticket | mitigate | refused unless the option is in `published.removableOptionIds`, derived server-side from the dish's assembled composition |
| T-10.6-04-04 | Repudiation | exclusion smuggled into the order comment where it can be neither counted nor handed to a POS | mitigate | D-18 forbids it; the exclusion is a structured `order_modifiers` row with a name snapshot, and the acceptance criteria assert no comment write was added |
| T-10.6-04-05 | Tampering | ordering an ingredient that has run out | mitigate | `OrderIngredientUnavailableError` on the `stoppedIngredientIds` set, mirroring the stopped-item refusal |
| T-10.6-04-06 | Denial of Service | an uncapped `several` group letting a client attach thousands of rows | accept | the request DTO already caps `items` and each line's `modifiers` array by Zod; D-33 removed the numeric ceiling deliberately and no menu has enough ingredients for this to matter |
| T-10.6-04-SC | Tampering | npm/pip/cargo installs | mitigate | no package is installed by this plan |
</threat_model>
