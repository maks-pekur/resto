## Ingredient vs attachment

| Option | Description | Selected |
|--------|-------------|----------|
| On the ingredient | Columns stay on the shared row. One behaviour per ingredient restaurant-wide; onion cannot be default in a burger and an add-on in a salad without creating two onions. | |
| On the attachment | The Ingredients screen holds photo, name, description, price; behaviour is set where the ingredient is attached, with quiet defaults. | ✓ |
| Ingredient default plus override | Value on the ingredient, attachment may override. Most flexible; two levels to hold in mind and paired nullable columns in the schema. | |

**User's choice:** on the attachment — after answering "не знаю как лучше" to the first pass and asking for a recommendation.
**Notes:** the recommendation given was identity-versus-behaviour: identity is what gets reused, behaviour is what varies per dish. Later trims (default-in removed, stepper deferred) left the attachment carrying only `sort_order`, so the decision survives as a principle for later phases rather than as work now.

| Option | Description | Selected |
|--------|-------------|----------|
| Forbid | An ingredient appears on a dish exactly once; the admin refuses the second attachment and says where it already is. | ✓ |
| Allow, two rows | Two order rows with different group ids — how iiko behaves and what `order_modifiers` already supports. | |
| Allow, collapse | One row with a summed amount; loses which block it came from. | |

**User's choice:** forbid.

## The group maximum

| Option | Description | Selected |
|--------|-------------|----------|
| Counts distinct options | The note's reading: group "up to 2" means two different ingredients; amounts are the ingredient's business. | |
| Counts amounts | "Up to 2" means two pieces in total. | |
| Both, lower wins | Most flexible, hardest to explain to a guest. | |

**User's choice:** free text — "это ненужно" / "думаю что ненужно максимум блока".
**Notes:** it was put back that `max_selectable` is what makes dough a radio group today, so removing the number outright removes the distinction. The reply reframed it: groups should all be configured the same way, with an added display setting — "плитка или сетка и табы или переключатель".

| Option | Description | Selected |
|--------|-------------|----------|
| Display carries behaviour | One setting: tabs mean one, tiles mean many. Nothing to confuse, but no way to render a choose-one block as photo tiles. | |
| Two settings | Display and behaviour set separately; a single-sauce choice can be photo tiles. | ✓ |

| Option | Description | Selected |
|--------|-------------|----------|
| All four (tiles, grid, tabs, rows) | Most freedom, four layouts to build and preview. | |
| Three (tiles, tabs, rows) | Grid is tiles at another size — leave that to layout. | |
| Two (tiles, tabs) | Rows disappear; a photoless group becomes name-only tiles. | ✓ |

**User's choice:** two settings, two display variants.
**Notes:** this overrides ROADMAP decision 4 and ING-11 — display no longer follows from whether an ingredient has a photo. Removing the numbers also removes the silent bug where a tap past the cap did nothing.

| Option | Description | Selected |
|--------|-------------|----------|
| Stepper stays | Per-attachment "how many times it can be added", `− n +` on a selected tile. ING-07. | |
| Defer it | Every ingredient taken once; double cheese is a separate ingredient. | ✓ |

## Claude's Discretion

- The stop overlay is computed per read rather than materialised at publish — a stop is set after
  publish, so materialising would mean recomputing on every stop write anyway.
- Exclusions render in the order detail sheet and not on the feed card — the feed card shows no
  modifiers today.
- Layout details left open: tab overflow behaviour, tile column counts, placeholder iconography.

## Deferred Ideas

- Disliked ingredients: remember them, ask on the first exclusion, warn on other dishes. The
  founder's own request and their own "needs proper UX thought".
- Amounts and the stepper (ING-07).
- Default-in / pre-checked modifiers and `amount: 0` (ING-06).
- An exact numeric group minimum or maximum.
- Price per size, per-dish group rules, gram-and-cost assembly charts, nested modifiers.
- Search and paging in the ingredients list.
