> Visual and interaction contract for **two surfaces**: the admin Ingredients screen
> (`apps/admin`, shadcn/new-york) and the guest ingredient-picker + composition line
> (`packages/ui/src/guest`, consumed by both `apps/qr-menu` and `apps/website`). Every

**New guest icon exports required** in `packages/ui/src/icons.ts` (the guest allowlist file): `ImageOff as NoPhotoIcon` lucide export for the photoless tile placeholder (D-09), and `Minus as MinusIcon` for the order-detail exclusion line. ## Spacing Scale

Declared values (must be multiples of 4) — this is the project-wide scale already in force, not new to this phase:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge/chip inline padding |
| sm | 8px | Compact element spacing (chip rows, form field gaps) |
| md | 16px | Default element spacing (card padding, grid gaps) |
| lg | 24px | Section padding (`FieldGroup` stacks, sheet body) |
| xl | 32px | Layout gaps (between form sections) |
| 2xl | 48px | Major section breaks (rare in this phase) |
| 3xl | 64px | Page-level spacing (not used in this phase) |

Exceptions (both pre-existing codebase idioms, reused as-is, not new deviations):
- Sub-4px micro-spacing (`gap-1.5`=6px, `gap-0.5`=2px, `px-1`=4px) on icon-adjacent chip controls — matches `item-modifier-groups-card.tsx`'s existing chip row.
- The guest photo grid's breakpoint-fluid gaps (`gap-x-2 gap-y-5 xs:gap-x-3 xs:gap-y-6 sm:gap-x-5 sm:gap-y-8`) are the establish pattern in `menu-screen.tsx:290`; the new ingredient-tile grid (narrower, inside the item-detail column — see Guest Surface Contract) uses a simpler fixed `gap-3` (12px) instead because it never spans full page width.

## Guest Surface Contract (`packages/ui/src/guest`)

Applies identically to `apps/qr-menu` and `apps/website` — both consume the same component, per the guest-surface-visual-parity rule in `apps/CLAUDE.md`. This is new code inside `item-detail.tsx` plus one or two new files in `packages/ui/src/guest`.

### `useItemSelection` (`use-item-selection.ts`) — logic changes only, no new visuals

- `isSingleChoiceGroup(group)` (keyed on `minSelectable===1 && maxSelectable===1 && isRequired`) is **replaced** by reading the group's own `behaviour === 'one'` field directly off the DTO (ING-05/09/11 — the numeric fields are gone from the admin and should not gate guest logic either).
- `preselected()` and the `defaultAmount` filter are **deleted** (D-05 — no default-in this phase).
- The `current.size >= group.maxSelectable` cap inside `toggleOption` is **deleted** — `several` now means "pick any number of this group's ingredients," there is no numeric ceiling left in the model (D-07 removed `max_selectable` from the admin entirely).
- `requiredCount(group)` simplifies to `group.isRequired ? 1 : 0` (the `Math.max(group.minSelectable, ...)` term is dead code once `minSelectable` no longer exists on the DTO).
- Every `amount` stays `1` (D-06 — the stepper is deferred); `chosenModifiers` construction is otherwise unchanged.

### Group rendering — `item-detail.tsx` — branches on `group.display`, not on whether any option has a photo

**`display === 'tiles'`** (new visual — this is the component this phase actually adds):

- Grid: `grid grid-cols-2 xs:grid-cols-3 gap-3` — narrower than the page-level menu grid (`menu-screen.tsx`'s `lg:grid-cols-3 xl:grid-cols-4`) because this renders inside the item-detail's already-constrained content column, never full page width. This is a deliberate deviation, not an oversight.
- Each tile: `aspect-square` photo well (`bg-muted rounded-2xl overflow-hidden`), the ingredient's `imageUrl` if present, else the new `NoPhotoIcon` centered (D-09 — a mixed block must keep an even row, so the placeholder occupies the same photo slot, not a smaller icon-only tile).
- Name below the photo: 14px/800 extrabold, `line-clamp-1`.
- Description (if present) directly under the name: 12px/400 regular, `text-muted-foreground`, `line-clamp-1` — never bold (D-10; see Typography's guest exception).
- Price: a small pill under the name/description, reusing `menu-item-card.tsx`'s exact price-pill treatment — unselected `bg-primary-tint text-primary-strong`, selected `bg-primary text-primary-foreground`. `+price` when non-zero, `formatPrice` helper, no pill at all (or an empty "included" state — same convention as size options with `Number(priceDelta)===0`) when free.
- Selection state: `border-primary` 2px ring + `bg-primary-tint` wash on the whole tile, plus a round check badge top-right (`size-5`, `bg-primary text-primary-foreground`, `CheckIcon` centered), matching the note's exact spec ("Chosen: border-primary, bg-primary-tint, and a round check in the corner").
- Underlying control stays a real `<input type="radio">` (behaviour `one`) or `<input type="checkbox">` (behaviour `several`), `sr-only`, wrapping `<label>` — same accessibility approach the current checkbox rows already use; keyboard/screen-reader behavior is not rebuilt.
- No stepper anywhere on the tile (ING-07 deferred) — a tap toggles selected/unselected only.
- A stopped ingredient (D-21) renders the tile at `opacity-45` with the reused `item.unavailable` badge/copy pinned to the tile exactly as `menu-item-card.tsx` already does for a stopped item, and its input is `disabled`.

**`display === 'tabs'`** — a pill/segmented control, physically incapable of holding two selections when `behaviour === 'one'` (reuse `SegmentedChoice` unchanged — it is already exactly this). When `behaviour === 'several'` on a `tabs` group, `SegmentedChoice`'s single-selection sliding-indicator model does not apply (there is no one active index to slide to); build a small sibling variant — same pill visual language, `<input type="checkbox">` per pill instead of `type="radio">`, no shared sliding highlight, each pill independently toggles `bg-background text-foreground shadow-sm ring-1 ring-primary/30` (selected) vs `text-muted-foreground` (unselected). Do not silently coerce a `several` + `tabs` group into `one` behaviour — both fields are independent per D-07/D-12, and this combination is legal even if the current dev menu's two `tabs` groups (dough, sauce) both happen to be `one`.

### Composition line (D-13…D-19) — new, inside `item-detail.tsx`, directly under the description paragraph

- A small text block labelled `item.composition` ("Состав"), then a flowing, comma-joined line — **plain text spans for non-removable entries**, **small tappable pill-buttons for removable entries** (each: the ingredient name + a leading `XIcon` `size-3`). - Tap a removable entry → its button state flips to `line-through text-muted-foreground/70` with the `XIcon` recoloured `text-foreground`; tap again to restore (undo). `aria-pressed` reflects excluded state; `aria-label` uses `compositionExcludeAriaLabel`/`compositionIncludeAriaLabel`.
- Non-removable entries render as plain `<span>` text, no button, no icon — per D-16, "not removable → it reads as plain text."
