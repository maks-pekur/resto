<design_decisions_this_plan_owns>
1. **Usage means three relationships, reported separately.** An ingredient appears in a group
   (`menu_modifier_group_options`), on a dish as a single attachment
   (`menu_item_modifier_options`), and inside a dish's assembled composition
   (`menu_items.composition_assembled`). `getModifierOptionUsage` returns all three lists
   separately, because two different screens read them: the archive warning shows the union (D-28),
   the stop dialog shows composition only (D-22). `archiveModifierOption` removes all three.
2. **The D-04 duplicate check queries across two tables.** The set an ingredient must not already be
   in is: every option id reachable from the dish's assigned groups (join
   `menu_item_modifier_groups` to `menu_modifier_group_options`) plus its existing single
   attachments. There is no existing "is this id already reachable another way" check in this
   codebase to copy — this is the shape.
3. **The composition write is one call, both modes.** `setItemComposition` takes
   `{ itemId, mode, text, lines }` and writes all three columns, so a mode switch can never leave
   the two payloads disagreeing about which one is live.
</design_decisions_this_plan_owns>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator browser to catalog write paths | ids in the request body are attacker-controlled and must be re-resolved server-side, never trusted as existing or as belonging to this tenant |
| membership write to Postgres | delete-then-reinsert briefly empties a set; it must be inside one tenant-bound transaction |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10.6-06-01 | Tampering | attaching another tenant's ingredient to a group or dish | mitigate | every incoming id is re-resolved through `scoped.selectFrom` under the bound tenant before the insert; the composite FK from plan 02 refuses it at the database even if the check were skipped |
| T-10.6-06-02 | Tampering | composition lines referencing an ingredient the tenant does not own | mitigate | `setItemComposition` resolves every `optionId` before writing the jsonb |
| T-10.6-06-03 | Elevation of Privilege | the DELETE grant being used to hard-delete a business row | mitigate | DELETE is issued only against the two link tables; `archiveModifierOption` sets `archivedAt` and the acceptance criteria assert no delete against `menu_modifier_options` |
| T-10.6-06-04 | Information Disclosure | the usage report naming another tenant's dishes | mitigate | the containment query runs inside `db.withTenant` through `scoped.selectFrom`, so RLS and the application filter both apply |
| T-10.6-06-SC | Tampering | npm/pip/cargo installs | mitigate | no package is installed by this plan |
</threat_model>
