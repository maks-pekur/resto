# Phase 10.6 Plan 13: Group editor rewrite — display/behaviour/required form and the ordered ingredients picker Summary

**modifier-group-form.tsx rebuilt around two RadioGroup pairs (display, behaviour) plus a required Switch — no numeric input anywhere — and a new group-ingredients-picker.tsx that lets an operator add, remove and drag-reorder a group's library ingredients, replacing the deleted option-editing screen.**

## Accomplishments

- Replaced the `grid-cols-[1fr_8rem_8rem]` name/min/max row in `modifier-group-form.tsx` with `LocalizedField` name (unchanged) + a `grid-cols-2` row of two horizontal `RadioGroup`s (display: tiles/tabs, behaviour: one/several) + a `Switch` for required — every field bound through `menu.groups.*` copy, zero literal strings
- Retargeted the post-create `navigate` from the deleted `/menu/modifier-groups/$id` to `/menu/ingredients/$id`, the route plan 12 registers this same wave
- Added `modifier-group-form.spec.tsx` (3 tests): no `input[type=number]` renders, choosing Tabs+One submits `{display:'tabs', behaviour:'one'}`, toggling Required submits `{isRequired:true}`
- Built `GroupIngredientsPicker` — a flat dnd-kit sortable list (`DndContext`+`SortableContext`+`useSortable`, the same skeleton `categories-table.tsx` uses) showing each member's photo/name/price read-only, a drag handle and a remove button; adding opens the shared `IngredientPickerSheet` with `showPrice: true` and no `disabledIds`
- Every add/remove/reorder writes the full ordered id array through `setGroupIngredients` with optimistic local state and rollback-plus-toast on failure — no per-row endpoint exists, so there is no batched "Save" step the way the old options table had one
- Rewired `group-editor-shell.tsx`: `emptyValues()`/`valuesFromGroup()` now build `{name, display, behaviour, isRequired}`; the "Варианты" card mounts `GroupIngredientsPicker` instead of `ModifierOptionsList`
- Deleted `modifier-options-list.tsx` (287 lines) after confirming `group-editor-shell.tsx` was its only importer — option editing inside a group is superseded by the ingredient library, not extended
- Closed all 9 typecheck errors this plan owned across its three files (`modifier-group-form.tsx`, `group-editor-shell.tsx`, `modifier-options-list.tsx`) — the only two lines still red in `modifier-group-form.tsx` are the plan-documented router exception (`/menu/ingredients/$id` isn't a known route id until plan 12 lands in this same wave)
