<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator browser to `/v1/catalog/*` | authenticated but untrusted input: names, descriptions, prices, S3 keys |
| admin-supplied `imageS3Key` to storage | the client hands back a key it received from the presign endpoint; it must not be able to name an arbitrary path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10.6-05-01 | Denial of Service | unbounded `description` / `composition` free text | mitigate | `.max(140)` on the ingredient description per UI-SPEC, `.max(100)` per composition entry and `.max(50)` on both arrays, enforced by the Zod DTO at the HTTP boundary |
| T-10.6-05-02 | Tampering | a client-supplied `imageS3Key` pointing at another tenant's prefix | mitigate | the write stores the key verbatim, so plan 07's presign service is what constrains the prefix; here the field is capped and the read path only ever presigns, never trusts, the stored key. Cross-tenant read is separately blocked by RLS (plan 02) |
| T-10.6-05-03 | Information Disclosure | the group detail leaking options from another tenant | mitigate | the new `menu_modifier_group_options` read goes through `scoped.selectFrom` inside `db.withTenant`, never raw `tx.select` |
| T-10.6-05-SC | Tampering | npm/pip/cargo installs | mitigate | no package is installed by this plan |
</threat_model>
