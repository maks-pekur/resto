# Phase 10.6 Plan 04: Ordering context — union allowed-set, group behaviour, exclusions Summary

**`create-order.service.ts` now accepts a directly-attached ingredient, enforces required+at-most-one instead of numeric min/max, refuses a stopped ingredient with its own error code, and lands an excluded composition line as its own zero-price `order_modifiers` row with `kind` persisted through the repository and the operator API.**

## Accomplishments

- `PricedModifierOption.groupIds: readonly string[]` replaces `groupId: string` — one ingredient can sit in several groups; a direct dish attachment carries an empty array (D-84 design decision 1)
- `PricedModifierGroup` drops `minSelectable`/`maxSelectable` for `behaviour: 'one' | 'several'`; `create-order.service.ts`'s group-count block enforces exactly `isRequired && count === 0` and `behaviour === 'one' && count > 1` — no numeric ceiling anywhere (D-33/ING-05)
- `catalog-menu-pricing.adapter.ts` rebuilds `modifierOptions` from the published menu's top-level `modifierOptions[]` array (not a flat-map over groups), inverting `group.optionIds` into a `Map<optionId, groupId[]>` in one pass, and loads `listStoppedIngredientIds` alongside `listStoppedItemIds` in the same `Promise.all`
- The order path's allowed-set check is now a union: `option.groupIds.some(g => published.modifierGroupIds.includes(g)) || published.extraOptionIds.includes(option.optionId)` — a single ingredient attached straight to a dish can be ordered (ING-04/ING-10)
- `OrderIngredientUnavailableError` refuses an ingredient on `stoppedIngredientIds`, mapped to `ordering.modifier_unavailable`, mirroring the existing stopped-item refusal (D-24)
- An `excluded` row is validated against `published.removableOptionIds` (refused with the same `OrderModifierNotAvailableError` as any other forged option) and, once accepted, is written with `priceDelta: '0'`, `amount: 1`, `modifierGroupId: null`, `kind: 'excluded'` — never counted into any group's selection total and never written into the order comment (D-16/D-18/ING-15)
- `order_modifiers.kind` round-trips end to end: the aggregate's `OrderModifierSnapshot`, the Drizzle insert/select, and `operator-orders.dto.ts`'s `OrderModifierResponseSchema` all carry it, so the admin can split one collection into two renders without a second API field (D-19/D-34)
