# Phase 10.6 Plan 01: Schema reshape for ingredient library, groups and composition Summary

**Drizzle schema reshape: ingredients become tenant-level entities via two link tables, groups drop numeric min/max for display+behaviour enums, menu items gain a two-mode composition, and order_modifiers gains an added/excluded discriminator — no migration yet.**

## Performance

- **Duration:** ~20 min
- **Started:** 2026-09-03T08:09Z (approx, first commit)
- **Completed:** 2026-09-03T08:14Z
- **Tasks:** 3
- **Files modified:** 7 (5 planned + 2 unplanned test-fixture fixes, see Deviations)

## Accomplishments

- `menuModifierOptions` is now a tenant-level ingredient with its own identity (description, image key, provenance) and no longer belongs to a group
- `menuModifierGroups` is described by `display` (tiles|tabs) + `behaviour` (one|several) instead of a numeric selection range
- `menuItems.ingredients` renamed to `composition`, with a new `compositionMode`/`compositionAssembled` pair backing the two-mode authoring flow (free text vs. assembled from ingredients)
- Two new composite-PK link tables (`menu_modifier_group_options`, `menu_item_modifier_options`) and one new location-scoped stop table (`menu_option_stop_list`) added, each with tenant FK + composite parent FKs (ADR-0020 I-2)
- `order_modifiers.kind` distinguishes an added modifier from an excluded composition line at the schema level
- `packages/domain`'s `MenuModifier`/`MenuModifierOption` Zod schemas rewritten to match; `MenuModifier` no longer carries a root `.refine()`, so it composes with `.extend()`/`.pick()` for future consumers
