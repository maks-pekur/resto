<objective>
PR 03 is the feature-work PR. Per D-04 it ships in one commit covering five distinct but architecturally adjacent pieces:

1. **TEN-01..04** — Suspend/resume tenant lifecycle (aggregate methods, error classes, service, internal HTTP routes, event contracts, audit wire-up).
2. **TEN-02 enforcement surface** — Locked decision from OQ-3: `@RequireActiveTenant()` decorator on customer-facing controllers. Middleware stays purely informational.
3. **TEN-05/06 + TEN-13** — Single `BackgroundJobsModule` (per D-12) hosting two `@Cron` services: erasure scheduler (sequential per-tenant try/catch, OTel error span on failure, no destructive retry per D-11) and `inbox_processed` retention sweep.
4. **TEN-14** — `buildEnvelope` helper in `@resto/events` reading `correlationId` from ALS with `randomUUID() + WARN` fallback (per D-10). Used by the NEW Suspend/Resumed branches in `domainEventToEnvelope` (the 8 existing call-site migrations are in PR 5 per D-15).
5. **Migration 0028** — Narrow `GRANT DELETE ON inbox_processed TO resto_app` (per OQ-2 locked here). Hand-authored SQL; not Drizzle-generated.

**Locked open questions (recommended answers from RESEARCH.md):**

- **OQ-1 → 403 Forbidden** for suspended tenants (recoverable). Reserve **410 Gone** for fully-erased tenants (future-proofing, not implemented in this PR).
- **OQ-2 → Option B (narrow GRANT)** in migration 0028. Reasoning: `SECURITY DEFINER` adds `search_path` attack surface; narrow GRANT is auditable and reversible.
- **OQ-3 → Decorator approach** for TEN-02. Per-controller opt-in beats global middleware rejection; operator routes (`/internal/v1/...`) stay reachable for suspended tenants so operators can resume them.

Purpose: Ship the user-visible suspend/resume capability + GDPR-native scheduled erasure + the envelope helper that PR 5 will migrate the remaining 8 call sites to. This is the largest single PR by surface area but the pieces are tightly coupled (suspend/resume needs `buildEnvelope` for its NEW envelope branches; cron services need `buildEnvelope` for their emitted events; D-11 requires both schedulers in the same module to share `ScheduleModule.forRoot()`).

Output: 21 modified or new code files, 1 new migration, 1 OpenAPI regeneration, 1 new dependency (`@nestjs/schedule@=4.1.2`).
