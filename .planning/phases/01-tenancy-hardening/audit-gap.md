## Closure Audit

The 7 CLOSED rows above flow events through the same pipeline:

1. **Producer** — domain aggregate (`Tenant`) or BA hook (`identity-core.module.ts`) calls `buildEnvelope(<contract>, payload, { tenantId, occurredAt })`. After PR 5, all 8 prior literal envelope sites use the helper.
2. **Outbox** — `appendToOutbox(tx, { envelope, aggregateId })` writes the envelope in the same DB transaction as the state change.
3. **Dispatch** — `OutboxDispatcherService` claims rows and publishes to NATS via `wrapPublisherForMetrics`; after PR 5 every emission carries `tenant.id` (or `'platform'`) as an OTel attribute.
4. **Subscribe** — `NatsAuditSubscriber` listens on `tenancy.>` and `identity.>`, calls `RecordAuditService.fromEnvelopeWithTx` inside `runDeduped` (inbox dedup + handler tx, ADR-0020 I-5).
5. **Project** — `RecordAuditService.project` resolves `targetType` via `ACTION_TARGET_KIND`; after PR 5 the map covers all 7 closed actions, so every closed row's audit entry has a non-null `target_type`.

E2E proof of materialization: `apps/api/test/e2e/identity-audit.e2e.spec.ts` covers `sign-in`, `sign-out`, `password-reset` (the closed identity rows); `apps/api/test/e2e/tenancy-suspend.e2e.spec.ts` covers `suspend`/`resume`; `provision` is exercised by every spec that calls `provisionTenant`. `outbox-dispatcher.e2e.spec.ts` proves the publish path independent of audit projection.

## BLOCKED row tracking

- **role-change / identity → AUTH-09 (Phase 3).** The BLOCKED disposition is intentional and explicit per Persona-skeptic's "premature done" risk. Re-evaluate when AUTH-09 lands; at that point either:
  - BA exposes a member hook → add `databaseHooks.member.update.after` mapping in `auth.config.ts`, emit a new `identity.role_changed.v1` event, extend `ACTION_TARGET_KIND['identity.role_changed']='user'`, and add an e2e test.
  - BA still lacks the hook → use a non-BA control plane (custom NestJS endpoint that mutates the BA member row and emits the event in a single tx) wired to AUTH-09's role-management UI.
