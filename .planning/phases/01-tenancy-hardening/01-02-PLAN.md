<objective>
PR 02 stands up the test infrastructure that PR 4 (TEN-07 preflight integration test) and PR 6 (TEN-08 cross-tenant fixture matrix) depend on. Per D-06, both PRs use a real Docker stack — not mocks — because ALS leaks and NATS subscriber tenant-context mix can only be exercised against real async boundaries.

The canonical setups already exist (`apps/api/test/e2e/with-real-stack.setup.ts` uses testcontainers; `packages/db/test/setup.ts:startPostgres()` uses `@testcontainers/postgresql`). This PR adds a parallel artifact: a `docker-compose.test.yml` modeled on `infra/docker/docker-compose.dev.yml` for cases where a long-running stack is wanted (manual debugging, CI matrix where testcontainers is too slow). Plus a convenience wrapper script.

Purpose: D-04 locks PR 2 as a prerequisite for PR 4 and PR 6. Building this once upfront beats letting each downstream PR invent its own stack and diverge.

Output: One new compose file, one optional wrapper script, two `pnpm` script entries at the root, and a sanity-check spec that confirms the stack starts.
</objective>

    4. Reduce Postgres resource hints: `mem_limit: 512m` (dev is 1g or unlimited), `cpus: '1.0'`. NATS: `mem_limit: 256m`.
    5. Use the SAME image tags as dev (`postgres:16-alpine`, `nats:2.10-alpine`) to avoid version drift between dev and test.

    7. Healthchecks: copy from dev — `pg_isready -U resto` for postgres, `nats -s nats://localhost:4222 server check` for NATS (whichever pattern dev uses; mirror it).
    8. Add a YAML comment header: `# docker-compose.test.yml — ephemeral test stack. Mirror of dev. Per D-06 of Phase 1 plan. Do NOT add Redis / MinIO / MailHog / Jaeger — they are not test-path dependencies.`
