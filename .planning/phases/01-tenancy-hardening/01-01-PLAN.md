<objective>
PR 01 fixes the two outbox bugs identified by persona-cto and persona-skeptic that block the rest of Phase 1: `OutboxDispatcher.stop()` is not idempotent (concurrent callers race on `#stopResolver` nullification per `packages/events/src/outbox/dispatcher.ts:118-141`), and `appendToOutbox` does not validate envelopes before insert (allows malformed payloads to reach the DB and crash consumers; `packages/events/src/outbox/repository.ts:23`). Also verifies (does NOT re-pin) TEN-18 — `better-auth: =1.4.22` exact — already shipped in commit `19a9da2`.

Purpose: TEN-16 fix removes the test-teardown flake that would mask TEN-08 isolation test failures (D-04 PR 1 rationale). TEN-17 enforces envelope contract at the application boundary, not at the broker — failing fast surfaces contract drift in CI. Together these unblock every downstream PR.

Output: Two patched files in `packages/events/src/outbox/`, two extended/new integration tests, no schema changes. No new dependencies.
</objective>

    1. Add a private field `#stopPromise: Promise<void> | null = null` to the class.
    2. Rewrite `stop()` as: fast-path `if (!this.#running) return;`, then `this.#stopped = true;`, then `this.#stopPromise ??= new Promise<void>((resolve) => { this.#stopResolver = resolve; });`, then `return this.#stopPromise;`. Key invariant: the `??=` must run BEFORE any `await`, so all concurrent callers see the same promise reference.
    3. In `#runLoop()`, after the `while` exits, capture the resolver into a `const resolver = this.#stopResolver;` local, set `this.#stopResolver = null;` and `this.#running = false;`, then `resolver?.();`. This sequence (capture-then-nullify-then-invoke) prevents the second concurrent stop() caller from racing on field-read.
    4. Do NOT clear `#stopPromise` on resolve — it is now the cached convergence point for any subsequent `stop()` callers after the loop exits.
    5. WHY-comment exactly one line at the field: `// TEN-16: cached so concurrent stop() callers converge — see packages/events/CLAUDE.md`. No other comments.
