**`/locations/:slug/tables` admin screen — zone list with create/rename/archive/add-tables, per-table rename/archive/download, whole-zone print via `printTablesSheet`, gated end-to-end on the new `table:read`/`table:update` permissions, with an Administration sidebar entry and a location-card link.**

## Accomplishments

- `table-zones.ts`: `TableZoneView`/`TableView` types, `tableZonesQuery(locationId)`, six mutation functions (create zone, rename zone, archive zone, add tables, rename table, archive table), and `friendlyTableError` mapping all seven `tenancy.table_*` problem codes to operator-actionable sentences — every call carries the location as `apiFetch`'s `locationId` option (the `x-location-id` header), never a URL segment

## Decisions Made

- Followed the founder's 2026-08-29 note verbatim: the route lives under `protectedLayoutRoute`, addressed `/locations/:slug/tables`, not under the location layout and not `?location=`-filtered.
- Read `10.3-07-SUMMARY.md`'s finding that a forged cross-location `zoneId` returns 404 (not 403) before writing `tenancy.table_zone_not_found`'s copy — the sentence reads "could not be found," not "forbidden."
- `friendlyTableError`'s `table_number_taken` case accepts an optional `attemptedNumber` context because the server's own message for that code (the raw-unique-violation catch path, per 10.3-07) never names the number — only the caller, who holds the value the operator just typed, can.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] route-permission-guards.spec.ts's route-tree enumeration went red**
- **Found during:** Task 2, first `pnpm nx run admin:test` after registering the new route
- **Issue:** `test/route-permission-guards.spec.ts` asserts an exact map of every gated route's `{resource, action}` pair, enumerated from the real assembled router. Adding `/locations/$slug/tables` without updating that map fails the spec by design (it exists precisely to catch an unregistered permission).
- **Fix:** Added `'/locations/$slug/tables': { resource: 'table', action: 'read' }` to the expected map.
- **Files modified:** `apps/admin/test/route-permission-guards.spec.ts`
- **Verification:** `pnpm nx run admin:test` — both cases in that spec pass.
- **Committed in:** `5586951e` (Task 2 commit)

**2. [Rule 2 - Missing Critical] The "New zone" header button was unguarded**
- **Found during:** Task 3, writing the read-only-member spec case
- **Issue:** The route rendered `<CreateTableZoneDialog>` in `PageHeading`'s `action` unconditionally — a `table:read`-only member would see and could open the "create zone" dialog, even though the API would refuse the resulting POST. This directly contradicts the plan's own truth: "A member holding table:read ... is not offered create, rename or archive."
- **Fix:** `TablesPage` now fetches `me` via `meQuery()` and renders the header action only when `hasPermission(me, 'table', 'update')`.
- **Files modified:** `apps/admin/src/routes/(protected)/locations.$slug.tables.tsx`
- **Verification:** covered by `tables-screen.spec.tsx`'s read-only-member case (the create control it asserts absent is the zone-level "Add tables" action; the route-level gating was verified manually by reading the fixed code path and confirming the same `hasPermission` call used by the sidebar and the route guard).
- **Committed in:** `8176632e` (Task 3 commit)

**3. [Rule 1 - Bug] A page-level error banner was invisible while any dialog was open**
- **Found during:** Task 3, the failed-mutation spec case timed out on `screen.findByRole('alert')`
- **Issue:** The first implementation reported a mutation failure via one shared `role="alert"` element at the top of `TableZoneList`. Radix's `Dialog`/`AlertDialog` sets `aria-hidden="true"` on background content while open (for assistive-tech focus correctness), which testing-library's accessible queries — and real screen readers — correctly treat as invisible. The banner update was real but unreachable by role while the dialog that triggered it stayed open, which is also every dialog that has a failure worth showing.
- **Fix:** Replaced the shared banner with per-dialog local error state (`renameError`, `addTablesError`, `archiveError`, etc.), rendered as `role="alert"` inside the dialog's own content, right above its footer. `AlertDialogAction`'s Radix-default auto-close is suppressed with `event.preventDefault()` on the failure path so the dialog stays open long enough to show the message.
- **Files modified:** `apps/admin/src/components/tables/table-zone-list.tsx`
- **Verification:** `tables-screen.spec.tsx`'s failed-mutation case passes; full `pnpm nx run admin:test` (141 tests) green.
- **Committed in:** `8176632e` (Task 3 commit)
