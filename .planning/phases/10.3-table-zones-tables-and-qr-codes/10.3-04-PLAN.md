Seed tenant A with a zone on location A1 holding tables numbered `1` and `2`, and a second zone on location A2 also holding a table numbered `1`.

Cover, one `it` per claim:

1. Tenant isolation on both tables — a `withTenant` read under tenant B's context returns zero `table_zones` and zero `restaurant_tables` rows.
2. Composite FK, zone → location — a tenant-B insert into `table_zones` carrying tenant A's `location_id` is rejected with an error.
3. Composite FK, table → zone — a tenant-B insert into `restaurant_tables` carrying tenant A's `zone_id` is rejected with an error.
4. This is the assertion that proves the policy exists; a guard-level 403 in an e2e test would pass whether or not the policy is there, because `LocationScopeGuard` checks the bound location and never an id in a path, and `ScopedTx` filters tenant only.
5. RESTRICTIVE location policy on `restaurant_tables` — same shape.
6. RESTRICTIVE `WITH CHECK` — an insert of a `table_zones` row whose `location_id` is A2 while the session is bound to A1 is rejected.
7. Partial unique index — inserting a second active table numbered `1` into the A1 zone fails; a table numbered `1` in the A2 zone succeeds (already seeded, assert it exists); and after updating the first table's `status` to `'archived'`, inserting a new active table numbered `1` into the same zone succeeds. That last case is what makes TBL-04's "archived rows are excluded from the number-uniqueness check" real rather than incidental.
8. No hard deletes — assert `has_table_privilege('resto_app', 'public.restaurant_tables', 'DELETE')` is false, and the same for `table_zones`.

| Boundary                                                       | Description                                                                              |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| tenant A session → tenant B rows                               | Every read and write on the new tables                                                   |
| location-A-scoped session → location B rows of the same tenant | A zone or table id in a route path is the vector; RLS is the only database-layer defence |
| erasure job → the tenant's whole graph                         | Runs `SECURITY DEFINER`, must delete every child before the parent                       |
