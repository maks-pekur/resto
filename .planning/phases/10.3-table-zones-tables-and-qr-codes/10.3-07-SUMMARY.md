## Accomplishments

- `TableZonesController`: `GET /`, `POST /`, `PATCH /:zoneId`, `PATCH /:zoneId/archive`, `POST /:zoneId/tables`, `PATCH /:zoneId/tables/:tableId`, `PATCH /:zoneId/tables/:tableId/archive` — one route gated on `table:read`, six on `table:update`, none on `location:*`, none carrying a location id

## Issues Encountered

- **Task 3, case 2 acceptance text vs. reachable behavior:** the plan's case 2 specifies `code === 'tenancy.table_bulk_limit_exceeded'` for a `tableCount: 201` POST. In practice `CreateTableZoneInputSchema` (10.3-06) already caps `tableCount` at `MAX_TABLES_PER_BULK_CALL` (200) via `.max(...)`, so `RestoZodValidationPipe` refuses 201 with `validation.failed` before `CreateTableZoneService`'s own re-check can run — `TableBulkLimitExceededError`/`tenancy.table_bulk_limit_exceeded` is structurally unreachable from either bulk-creation route (`POST /`, `POST /:zoneId/tables`) over HTTP, by construction, since `AddTablesInputSchema` carries the identical `.max(200)`. It exists for a future non-HTTP caller (10.3-06 SUMMARY's own stated rationale). The e2e case was adjusted to assert `validation.failed` — the refusal and the "writes nothing" guarantee both still hold; only the specific code differs from the plan's literal text. Flagging here rather than silently deviating from the plan's stated criterion.
- **Case 6's specific status:** the plan asked to record which of 404/403 a forged cross-location `:zoneId` mutation produces. Confirmed 404 for both `PATCH /:zoneId` (rename) and `PATCH /:zoneId/archive` — `LocationScopeGuard` passes (the member's header matches their own session pin at location A), so the refusal comes entirely from the repository's `findZoneById(zoneId, locationId=A)` returning `null` for a zone that belongs to B, which the service maps to `TableZoneNotFoundError` → `NotFoundException`. Plan 10.3-11's admin error copy should treat a forged/cross-location zone id as "not found," not "forbidden."
- **`PUBLIC_APEX_DOMAIN` route taken:** the env-var route (`process.env.PUBLIC_APEX_DOMAIN = 'resto.app'` set before `startRealStack`), not a seeded custom domain. Every `qrUrl` in case 1 carries `https://<tenantSlug>.menu.resto.app/?t=<tableId>`.
