<objective>
Introduce a dedicated `table` permission resource with two actions, and re-sync it onto every existing tenant's manager preset.

Purpose: CONTEXT D-12 said the floor screen would be gated on `location: ['update']` and both persona reviews proved that description false against the code. `system-roles.ts` gives `admin` only `location: ['read']`, so gating on `location:update` would have made the entire table surface owner-only — including reading it. Worse, `location:update` also opens `PATCH /v1/tenancy/locations/:id/archive` on a `@LocationNeutral()` controller, so any custom role minted to let a shift manager reprint a sticker could also archive the restaurant's other venue by editing a UUID. D-17 supersedes D-12 and splits the gate.
Output: `table: ['read', 'update']` registered once, inherited everywhere, and existing tenants' preset rows updated.
</objective>

## Trust Boundaries

| Boundary                                       | Description                                                                                                        |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| owner → custom role definition                 | An owner mints a custom role; whatever actions that role carries become reachable by a non-owner member            |
| custom role → `@LocationNeutral()` controllers | A granted action opens every route gated on it, across every controller, including ones that ignore location scope |
