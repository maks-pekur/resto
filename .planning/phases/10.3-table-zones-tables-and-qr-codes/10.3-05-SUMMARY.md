# Phase 10.3 Plan 05: Table zone/table domain, repository, and guest URL service Summary

**TableZone/RestaurantTable aggregates, a TABLE_ZONE_REPOSITORY Drizzle implementation that composes an explicit `locationId` predicate on every path except the public table-resolution lookup (which runs inside a new `withoutLocation` ALS frame), and GuestMenuUrlService — the single server-side place the QR sticker URL shape is written down.**

## Accomplishments

- `TableZone` / `RestaurantTable` aggregates (rename/renumber + archive mutators) and seven new tenancy domain errors, zero framework/persistence imports
- `TableZoneRepository` interface + `TABLE_ZONE_REPOSITORY` Symbol, owning both entities under one port
- `TableZoneDrizzleRepository`: every method except `findActiveTableForResolution` composes an explicit `eq(locationId, ...)` predicate; zone-with-N-tables and archive-cascade are each one transaction; the batch insert is a single multi-row `.values([...])` call, never a per-row loop; no `DELETE` anywhere
- `withoutLocation(op)` added to `packages/db/src/context.ts` (re-exported from `@resto/db`) — drops `locationId` from the ALS frame so `findActiveTableForResolution` cannot be defeated by a stray or forged `x-location-id` header
- `GuestMenuUrlService.execute({ tenant, tableId })` builds `https://<host>/?t=<tableId>` from the tenant's primary verified custom domain, else `<slug>.menu.<PUBLIC_APEX_DOMAIN>`; five spec cases, two asserting the exact string

## Decisions Made

- Followed the plan's `Location`/`LocationRepository` templates for both new aggregates and the port shape.
- `TableZoneSnapshot.id` / `RestaurantTableSnapshot.id` / `zoneId` are plain `string`, not new `@resto/domain` branded id types — `packages/domain` is outside this plan's `files_modified`, and `tenantId`/`locationId` already reuse the existing `TenantId`/`LocationId` brands.
- `GuestMenuUrlService` exposes `execute(input)` (CLAUDE.md's single-public-method convention) rather than the plan's alternative `buildTableQrUrl` name.
- `createZoneWithTables`/`addTables` insert values omit `id`/`status`/timestamps entirely, relying on the schema's own `gen_random_uuid()`/`now()`/`'active'` defaults, then read the generated values back via an explicit `.returning({ ...columns })`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Worktree `node_modules` symlink chain resolved `@resto/db`/`@resto/events` to the MAIN CHECKOUT, hiding the new `withoutLocation` export from `api:typecheck`**
- **Found during:** Task 2, first `pnpm nx run api:typecheck` after adding the repository file
- **Issue:** `apps/api/node_modules` (and `packages/events/node_modules`) in this worktree are single ABSOLUTE symlinks to the MAIN CHECKOUT's equivalent directories (`/Users/mp_dev/projects/RestOS/apps/api/node_modules`, not this worktree's own copy) — confirmed with `cd .../node_modules/@resto/db && pwd -P`. `apps/api/tsconfig.json`'s extends chain (`@resto/config-typescript/node.json` → `./base.json`) carries no `paths`/`baseUrl`, so `@resto/db` resolves via plain package (`main`/`exports`) resolution through that symlink chain, not via `tsconfig.base.json`'s path mapping. Because `packages/events` (a real dependent of `@resto/db`) resolves its OWN `@resto/db` import the same broken way, and TypeScript deduplicates modules by Package ID (`name@version`) across the whole compilation, the FIRST `@resto/db` resolution TS completed (from `packages/events`, landing on the main checkout's stale copy) was reused for every subsequent `@resto/db` import in the program, including from our own worktree file — even though our file's own relative symlink chain would otherwise have resolved correctly. Net effect: `withoutLocation`, added only to this worktree's `packages/db/src/context.ts`, was invisible to `api:typecheck`. This contradicts my prompt's stated hazard note ("tsc and vitest path-map correctly") — that appears true for the common case but not for a brand-new export consumed within the same session across a `packages/events → packages/db` internal dependency edge.
- **Fix:** Added two shadow `node_modules` directories closer to the source root than the broken absolute symlinks, so Node/TS ancestor-directory resolution hits them first: `apps/api/src/node_modules/@resto/{db,domain,events}` and `packages/events/src/node_modules/@resto/{db,domain}`, each a fresh symlink pointing directly at this worktree's own `packages/*` (verified with `pwd -P` after `cd`-ing through the new link). Purely additive — the pre-existing (broken) symlinks were never touched or replaced. `node_modules/**` is gitignored, so this fix is invisible to `git status` and cannot be accidentally committed.
- **Files modified:** none tracked by git (filesystem-only, inside `.../node_modules/`, gitignored)
- **Verification:** Cleared stale `.tsbuildinfo` files, reran `tsc -p apps/api/tsconfig.json --noEmit` directly and via `pnpm nx run api:typecheck --skip-nx-cache` — both clean after the fix (confirmed the `withoutLocation` error was gone, isolating the remaining two errors as real type issues, fixed separately below).
- **Committed in:** n/a (filesystem/environment only, not a tracked change)

**2. [Rule 1 - Bug] Bare `.returning()` after `insertInto`/raw `tx.insert` degraded to `unknown`-typed rows**
- **Found during:** Task 2, same `api:typecheck` run
- **Issue:** `scoped.insertInto(schema.tableZones, {...}).returning()` and the raw `tx.insert(schema.restaurantTables).values([...]).returning()` calls in `createZoneWithTables`/`addTables` returned a loosely-typed `{ [x: string]: unknown }` shape instead of the schema's row type — a real type-safety gap (a caller could silently receive `unknown` fields with no compile-time catch), not a stylistic nit. Root cause: `ScopedTx.insertInto`'s cast-heavy return type (`ReturnType<RestoTx['insert']>['values'] extends (v: never) => infer R ? R : never`) doesn't propagate column inference through a bare `.returning()`.
- **Fix:** Switched all three `.returning()` calls to an explicit column-selection object (`{ id: schema.tableZones.id, tenantId: schema.tableZones.tenantId, ... }`) matching each `ROW_TO_*_SNAPSHOT` mapper's expected input shape — the same explicit-selection convention already used throughout `catalog-drizzle.repository.ts`.
- **Files modified:** `apps/api/src/contexts/tenancy/infrastructure/table-zone-drizzle.repository.ts`
- **Verification:** `tsc -p apps/api/tsconfig.json --noEmit` clean; `pnpm nx run api:lint` clean.
- **Committed in:** `ef55c770` (part of Task 2 commit)
