<interfaces>
<!-- Geometry decided here so the implementer does not invent it. All numbers are millimetres. -->

A4 portrait is 210 × 297. A 2 × 3 grid gives cells of 105 × 99.

Named constants the geometry module exports:

- `PAGE_WIDTH_MM = 210`, `PAGE_HEIGHT_MM = 297`
- `COLUMNS = 2`, `ROWS = 3`, `CODES_PER_PAGE = 6`
- `CELL_WIDTH_MM = 105`, `CELL_HEIGHT_MM = 99`
- `CODE_FOOTPRINT_MM = 84` — the whole drawn code INCLUDING its quiet zone, which is what a human perceives as "the code". Inside D-09's "roughly 8–9 cm".
- `CUT_BOX_MM = 90` — the hairline cut guide, drawn 3 mm outside the footprint on every side so scissors never have the quiet zone as their target. Leaves 7.5 mm horizontal and 4.5 mm vertical margin inside the cell.
- `QUIET_ZONE_MODULES = 4` — the QR spec's mandatory margin, on all four sides.

`moduleSizeMm(matrixSize)` returns `CODE_FOOTPRINT_MM / (matrixSize + 2 * QUIET_ZONE_MODULES)`. `matrixSize` MUST come from the actual generated symbol, never a hardcoded number: the sticker URL length varies with tenant slug and apex domain, and a longer custom domain pushes the symbol from Version 5 (37 × 37) to Version 6 (41 × 41). A hardcoded module count silently produces an undersized quiet zone (RESEARCH.md Pitfall 6).

`layoutSheet(count)` returns, for each index 0..count-1, its `{ page, column, row, footprintX, footprintY, cutBoxX, cutBoxY, gutterTextX, gutterTextBaselineY }`. Ordering is left to right then top to bottom, one zone per document — that ordering IS the requirement, not an implementation detail, because a sheet of identical unlabelled squares has nothing else telling the operator which sticker belongs to which table (CONTEXT D-08).

The gutter baseline sits below the cut box, inside the 4.5 mm offcut band, so the number is gone once the sticker is trimmed (CONTEXT D-24).

Packages, from RESEARCH.md (versions and bundle sizes verified live against npm and Bundlephobia on 2026-08-29; the NAMES are `[ASSUMED]`):

- `qrcode@1.5.4` — 23.4 KB min / 8.75 KB gzip, MIT, no runtime deps, no postinstall, repo `github.com/soldair/node-qrcode`
- `jspdf@4.2.1` — 400 KB min / 127 KB gzip, no postinstall, repo `github.com/parallax/jsPDF`
- `@types/qrcode@1.5.6` — dev only

Assumption A2, flagged LOW and actionable: `QRCode.create(text, { errorCorrectionLevel: 'M' })` is expected to return an object whose `.modules` is a bit-matrix of shape `{ size: number, data: Uint8Array }`, indexed `data[row * size + col]`. Verify against the installed package's own TypeScript declarations before writing the PDF assembler. Documented fallback if it differs: `QRCode.toString(url, { type: 'svg' })` piped through `svg2pdf.js` (+24.9 KB gzip) — a different drawing call, not a redesign.

Write `generate-tables-pdf.ts` exporting `generateTablesPdf(input)` where `input` carries the zone name (for the PDF filename only, never printed on a sticker) and an ordered list of `{ tableId, number, ordinal, qrUrl }`. The `qrUrl` is supplied by the server per CONTEXT D-21 — this module must never compose a URL from parts, because the guest host is server-only state and a tenant may sit on a verified custom domain that no formula derives.

Both `qrcode` and `jspdf` must be reached through `await import(...)` inside the function body. A top-level import would put roughly 136 KB gzip into the admin's initial bundle for a screen an operator opens during setup and rarely again (CTO MEDIUM-6).

Sort the list by `ordinal` ascending with `number` as the tiebreaker before laying anything out. Sorting on the free-text `number` alone would produce 1, 10, 11, 2, 20 — which silently inverts the only thing that makes an unlabelled sheet usable, and looks correct on a six-table demo (CONTEXT D-23). Filter out anything the caller passed that is not active; archived tables must not appear in the document.

Create the document as A4 portrait in millimetre units. For each table: generate the symbol at error-correction level M, read `matrixSize` back from the generated object, compute the module size with `moduleSizeMm(matrixSize)`, and draw each dark module as a filled `rect` of that size, offset by the 4-module quiet zone from the footprint origin. Vector rectangles, not a rasterised image — a 90 mm code at 300 dpi is roughly 1060 px per side and a 50-table zone becomes nine sheets of large base64 PNGs assembled in a browser tab, in a document whose only purpose is printing (RESEARCH.md "Don't Hand-Roll"). Then draw the hairline cut-guide square at the `CUT_BOX_MM` position with a thin line width and no fill, and print the table number at the gutter baseline at a small font size. Start a new page every six codes.

Return the PDF as a Blob (or trigger the download directly, matching whatever download idiom the admin app already uses) with a filename derived from the zone name.

Write `download-table-svg.ts` exporting `downloadTableSvg({ number, qrUrl })`, which dynamically imports `qrcode`, calls its SVG string form at error-correction level M with the 4-module margin, and downloads the result as `.svg`. SVG is the locked format because it is vector, opens in any editor and at any print shop, and is the right input for the sticker templates the founder plans to design later (CONTEXT D-10).

Neither file may import from `apps/qr-menu` or add any dependency to it — QR generation stays on the admin surface (SPEC constraint; the guest app only ever reads a label from the API).
