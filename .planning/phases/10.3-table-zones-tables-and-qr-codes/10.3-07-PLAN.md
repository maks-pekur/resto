<!-- Route table, decided here so it is not invented at implementation time. -->
`@Controller('v1/tenancy/table-zones')`, class-level `@RequiresTenantContext()`. Deliberately NOT `@LocationNeutral()`: the whole surface needs a bound location so `LocationScopeGuard` runs and `requireLocationContext()` resolves.

| Method | Path                               | Permission              |
| ------ | ---------------------------------- | ----------------------- |
| GET    | `/`                                | `{ table: ['read'] }`   |
| POST   | `/`                                | `{ table: ['update'] }` |
| PATCH  | `/:zoneId`                         | `{ table: ['update'] }` |
| PATCH  | `/:zoneId/archive`                 | `{ table: ['update'] }` |
| POST   | `/:zoneId/tables`                  | `{ table: ['update'] }` |
| PATCH  | `/:zoneId/tables/:tableId`         | `{ table: ['update'] }` |
| PATCH  | `/:zoneId/tables/:tableId/archive` | `{ table: ['update'] }` |

No location id appears in any path. `LocationScopeGuard` (`apps/api/src/contexts/identity/interfaces/http/guards/location-scope.guard.ts:33,61-76`) keys entirely on the ALS-bound location and never on a route parameter, and `@LocationNeutral()` short-circuits it outright — so a `/locations/:id/zones` route would let an operator scoped to B mutate A's tables by editing a UUID. The zone and table ids that unavoidably do appear are covered by the repository's explicit location predicate (plan 10.3-05) plus the RESTRICTIVE RLS policy (plan 10.3-01).

Cover, one `it` per claim:

1. **Bulk create** — the owner POSTs a zone with `tableCount: 20` bound to location A; the response carries 20 tables numbered `"1".."20"` in that exact order, each with a non-empty `qrUrl` that ends in `/?t=<that table's id>`. Assert the ordering as an exact array; a 20-table zone in lexicographic order still puts 1, 10, 11, 12 first and looks plausible at a glance.
2. **Cap refused, nothing written** — a POST with `tableCount: 201` returns 400 with `code === 'tenancy.table_bulk_limit_exceeded'`, and a follow-up GET shows the zone count unchanged.
3. **Number uniqueness** — adding a table and renaming it to `"1"` inside the same zone returns 409 with `code === 'tenancy.table_number_taken'`; the same number in a second zone of the same location succeeds.
4. **Read gate** — the `table:read`-only member GETs the list successfully and reads `qrUrl`, and receives 403 on create, on rename and on archive. This is the criterion that a manager can reprint a damaged sticker without being handed the ability to archive a location.
5. **Location isolation, read** — the member scoped to location A, sending `x-location-id: A`, does not see location B's zones in the list.
6. **Location isolation, mutation** — the same member attempts `PATCH /:zoneId` and `PATCH /:zoneId/archive` against a zone that belongs to location B while still sending `x-location-id: A`, and is refused (404 or 403 — assert the specific status the implementation produces and state it in the SUMMARY). Then assert directly against Postgres that the target zone's `name` and `status` are unchanged. Asserting only the HTTP status would pass on the guard check alone, while a code path that skipped the guard would still have written.
7. **Owner sees both** — the owner, switching `x-location-id` between A and B, gets each location's own zones.
8. **Archive cascade** — archiving the 20-table zone returns success, and a direct Postgres read shows the zone plus all 20 tables at `status = 'archived'` with zero active rows left in that zone.

## Trust Boundaries

| Boundary                               | Description                                                                                         |
| -------------------------------------- | --------------------------------------------------------------------------------------------------- |
| operator session → zone/table mutation | The caller's permissions and location scope decide what the request may touch                       |
| route path → target row                | `:zoneId` and `:tableId` name rows whose location `LocationScopeGuard` never checks                 |
| custom role → this surface             | An owner may mint a role carrying `table:update`; that role's reach is whatever these routes expose |
