## Trust Boundaries

| Boundary                                                    | Description                                                                                                                        |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| operator session → `table_zones` / `restaurant_tables` rows | A zone or table id necessarily appears in a PATCH path; the caller's location authority is bound in ALS, not derived from the path |
| tenant A session → tenant B rows                            | Every read and write on the new tables crosses this boundary through `ScopedTx` + RLS                                              |
| GDPR erasure job → location children                        | `tenancy_erase_tenant` runs `SECURITY DEFINER` and must be able to delete every child before the parent                            |

## STRIDE Threat Register

| Threat ID | Category               | Component                                                                 | Disposition | Mitigation Plan                                                                                                                                                                                         |
| --------- | ---------------------- | ------------------------------------------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-10.3-01 | Tampering              | `table_zones.location_id`, `restaurant_tables.zone_id` supplied on insert | mitigate    | Composite FK `(child_id, tenant_id) → parent(id, tenant_id)` per ADR-0020 I-2 on all three parent links; a cross-tenant id is rejected by Postgres, not by application code                             |
| T-10.3-02 | Elevation of Privilege | Cross-location write via a zone id in a route path                        | mitigate    | `table_zones_location_iso` / `restaurant_tables_location_iso` RESTRICTIVE policies copied from `menu_stop_list_location_iso`; the repository-layer predicate is the second layer, added in plan 10.3-05 |
| T-10.3-03 | Information Disclosure | Cross-tenant read of zones and tables                                     | mitigate    | `*_iso` PERMISSIVE policy on `tenant_id = current_tenant_id()` plus `FORCE ROW LEVEL SECURITY` on both tables                                                                                           |
| T-10.3-04 | Repudiation            | GDPR erasure silently failing for any tenant that used the feature        | mitigate    | Two DELETE statements added to `tenancy_erase_tenant` between `orders` and `locations`; proven by the integration test in plan 10.3-04                                                                  |
| T-10.3-05 | Denial of Service      | Hard delete of a table that historic orders reference                     | mitigate    | `resto_app` gets no DELETE grant on either table; `orders_table_fk` is `ON DELETE RESTRICT`; the lifecycle is `status = 'archived'`                                                                     |
| T-10.3-SC | Tampering              | npm/pip/cargo installs                                                    | mitigate    | No package installs in this plan.
