<objective>
Make `AuthGuard` require **agreement** between the operator's session tenant and the tenant the
request binds, rather than merely the absence of disagreement — and measure, before changing
anything, what the current gap was worth.

Purpose: the phase moves the operator's tenant out of the URL and into the Better Auth session.
That chain is only as strong as the guard that validates it. Today
`auth.guard.ts:119-136` short-circuits on `principal.tenantId &&`, so a session with **no** active
organization skips the comparison entirely and whatever `x-tenant-id` arrived binds the ALS tenant
unchecked (07.4-CONTEXT D-02).

Output: a committed route census with a drift gate; a guard that rejects both the "no active
organization" case and the "not a member" case; unit tests for all three rejection paths, each
shown failing before it is shown passing.
</objective>

Region A, the cross-check (currently at `:119-136`), verbatim:

    const principal = buildPrincipal(sessionData, alsTenantId);

    if (
      principal.kind !== 'anonymous' &&
      'tenantId' in principal &&

    }

Region B, the base-role enrichment (currently at `:153-156`), verbatim:

    if (principal.kind === 'operator' && principal.tenantId) {
      const role = await this.lookupBaseRole(principal.userId, principal.tenantId);
      if (role) principal.baseRole = role;
    }

`lookupBaseRole` (same file) selects `memberTable.role` where `userId` and `tenantId` match,
`.limit(1)`, then splits a CSV `role` string and returns the highest of `owner` / `admin` / `staff`
present — **returning `undefined` both when no member row exists and when a member row exists
carrying only a custom role slug** (D-15, phase 08.3). Those two cases are not the same and this
plan must stop conflating them.

`buildPrincipal` (same file, `:239-253`) sets `operator.tenantId` **only** when
`session.session.activeOrganizationId` is present:

    ...(session.session.activeOrganizationId
      ? { tenantId: session.session.activeOrganizationId }
      : {}),

so `principal.tenantId` is `undefined` for a session with no active organization — which is exactly
what makes Region A's `principal.tenantId &&` clause skip the whole comparison.

`apps/api/test/unit/identity/auth-guard.spec.ts` already provides the doubles this plan needs:
`buildContext(req)`, `buildAuthStub(sessionResult)`, `buildLookupStub(archivedAt)`, and a module-level
`authDb` whose chained `select().from().where().limit()` resolves to `[{ role: 'owner' }]`.
`@resto/db`'s `getTenantContext` is `vi.mock`ed at the top of the file; `mockGetTenantContext`
controls the ALS tenant per test.

Route decorators, for the census: `@RequiresTenantContext()` and `@Permissions({...})` are imported
from `apps/api/src/shared/auth`. Both appear at class level (`catalog.controller.ts:107`,
`table-zones.controller.ts:105`) and at method level (`tenants.controller.ts:79-81`), so the census
must handle both.

Two edits to `apps/api/src/contexts/identity/interfaces/http/guards/auth.guard.ts`.

**Edit 1 — Region A** (the cross-check quoted in `<interfaces>`). Replace the single condition with a
form that is "must agree" for operators and stays "must not disagree" for everyone else:

  - derive `principalTenantId` as `principal.kind !== 'anonymous' && 'tenantId' in principal ? principal.tenantId : undefined`;
  - for `principal.kind === 'operator'`, the mismatch condition is
    `alsTenantId !== undefined && principalTenantId !== alsTenantId`;
  - for every other kind, keep the existing condition
    (`principalTenantId !== undefined && alsTenantId !== undefined && principalTenantId !== alsTenantId`);
  - throw the same `ForbiddenException({ code: 'auth.tenant_mismatch', message: 'Principal tenant does not match request tenant.' })`.

`x-tenant-id` arrived.

**Edit 2 — Region B** (the base-role enrichment). Replace `lookupBaseRole` with `lookupMembership`,
returning `null` when the `member` query yields no row and `{ role }` otherwise, where `role` is the

the "no row" signal is new. Then:

  - when `principal.kind === 'operator' && alsTenantId !== undefined`: call
