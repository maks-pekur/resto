# Phase 07.4 Plan 01: AuthGuard tenant agreement + route census Summary

**AuthGuard now requires the session's tenant to *agree* with the request's bound tenant (not merely not-disagree), and rejects an operator with no `member` row for that tenant — closing the `principal.tenantId &&` short-circuit that let a session with no active organization bind any `x-tenant-id`.**

## Performance

- **Duration:** ~45 min
- **Completed:** 2026-09-05T13:18Z
- **Tasks:** 2/2
- **Files modified:** 5 (2 created, 3 modified)

## Accomplishments

- Wrote `tenant-context-route-census.mjs`, a regex-based walker over `apps/api/src/**/*.controller.ts` that enumerates routes carrying `@RequiresTenantContext` without `@Permissions`, with a `--check` drift gate against a committed baseline.
- Confirmed the census set is empty on the current tree (57 `@RequiresTenantContext` routes total, all 57 also carry `@Permissions`) — verified two ways: the script's own `--json` output, and an independent per-file `grep -c` cross-check.
- Closed the two elevation-of-privilege holes named in 07.4-CONTEXT D-02: Region A's cross-check now requires *agreement* for operator principals (`alsTenantId !== undefined && principalTenantId !== alsTenantId`) instead of skipping entirely when `principal.tenantId` is falsy; Region B's base-role enrichment is now a membership *gate* (`auth.tenant_membership_missing`) keyed on `alsTenantId`, not an enrichment-only lookup keyed on the principal's own copy of the tenant.
- `lookupBaseRole` no longer exists; `lookupMembership` distinguishes "no member row" (`null`) from "row present with only a custom role slug" (`{ role: undefined }`), so a custom-role-only operator (D-15, phase 08.3) is still admitted with `baseRole` undefined rather than locked out.

## Decisions Made

- Census set is empty today. This is not treated as "nothing to do" — the baseline is committed precisely so the *next* route that adds `@RequiresTenantContext` without `@Permissions` fails CI immediately (verified live, see Task 1 RED/GREEN transcript below).
- `lookupMembership`'s primary call site is keyed on `alsTenantId` (the tenant actually bound to `ScopedTx`/RLS), not `principal.tenantId` (the session's own copy) — per plan `<action>`, this is deliberate: the two can diverge is exactly the class of bug this plan closes.
