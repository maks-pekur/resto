Mount the admin SPA at `<apex>/admin` and make every absolute navigation it performs aware of that
prefix.

map says it lives. The two are separate because the first is a trust-boundary change and this one is
a routing change — and because doing them together would put a `basepath` diff in the same review as
a tenancy diff.

tested against the real routes rather than asserted, and the two absolute navigations that would
otherwise 404 fixed.

- **Do not change `build.outDir`, `apps/admin/wrangler.jsonc`, Worker routes, or add any
  `cp dist/admin/index.html dist/index.html` step.** The nested-directory asset layout exists only to
  satisfy Cloudflare Workers Static Assets' subdirectory serving (research Pattern 4a / M-09), and it
  only makes sense together with the `assets.directory` and `not_found_handling` settings that phase
  7.5 writes. Half of it here would produce a `dist/index.html` nobody serves. State it as a handoff
  instead (see Task 1).
- **Do not reintroduce a tenant anywhere in the URL**, including as a `$tenantSlug` route param.
- The route-tree extraction is a **move, not a rewrite**. Do not reorder route registration: the
  `locationRouteTree` must stay last in `protectedRouteTree` because `/$locationSlug` matches any
  first segment, and every static root segment is reserved against location slugs. Reordering it
  silently breaks route resolution in a way no type checker sees.
- Comments: zero. The one existing D-21 comment in `vite.config.ts` explaining `host: true` is deleted
  with the code it explains.
- No new package is installed by this plan.
</constraints>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL path → application | `/admin/*` is now the operator surface on a host shared with the marketing landing; `/v1/*` and `/api/*` on the same host are the API, routed by Caddy |
| dev server → network | `host: true` binds the Vite dev server beyond loopback |
| emailed link → application | the password-reset `redirectTo` is composed client-side and sent to Better Auth |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07.4-05-01 | Denial of Service | 401 redirect to a path that no longer exists | mitigate | `adminPath('/login?expired=1')`, asserted under both `BASE_URL` values. Without it an expired session lands on a 404 and the operator cannot reach sign-in |
| T-07.4-05-02 | Denial of Service | password-reset links pointing at a 404 | mitigate | `adminPath('/reset-password')`, asserted. The link is emailed, so a wrong value is discovered by a locked-out operator, not by CI |
| T-07.4-05-03 | Spoofing | Vite dev server reachable off-loopback | mitigate | `host: true` and `allowedHosts` deleted along with the wildcard-host mechanism they served. Vite's `allowedHosts` check is the CVE-2025-24010 class of control; removing the binding removes the need for it |
| T-07.4-05-04 | Tampering | route registration reordered during the extraction | mitigate | The extraction is a move; `locationRouteTree` stays last because `/$locationSlug` matches any first segment. The parameterised deep-link case in Task 1 fails if the ordering breaks |
| T-07.4-05-05 | Denial of Service | `basepath` silently ignored | mitigate | The negative case (`/dashboard` must NOT match) is what distinguishes a working `basepath` from an ignored option; M-13 read the `.d.ts` but never ran it |
| T-07.4-05-SC | Tampering | npm/pip/cargo installs | n/a | This plan installs nothing |
</threat_model>
