<objective>
Take the tenant out of the admin's URL entirely, and replace the property that the host used to
enforce for free with one the codebase enforces on purpose.

Purpose: `apps/admin/src/lib/admin-host.ts` derives a tenant from the hostname and five call sites
hard-navigate to `<slug>.<admin-apex>`. Under the single-apex scheme the session's
`activeOrganizationId` is the sole selector and the URL carries no tenant (07.4-CONTEXT D-01).

The subtle half is D-04. Phase 10.2 closed "a stale query cache serving another organization's data
after a switch" with a hard cross-origin navigation. Measured in Chromium (research M-10):
`location.assign()` to a same-origin path still discards a module-scope object (stamp 40 → 4.7, new
realm), and `history.pushState` — what TanStack Router's `navigate()` does — does not. So the
property survives, but under the host scheme it was structurally impossible to get wrong, and on a
path it is one refactor away. **The property stops being enforced by physics and starts needing to be
enforced by the codebase.**

Output: one `switchTenant()` helper, an ESLint rule confining the switch endpoint to it, a
base-path-aware path helper, and the deletion of every host-derived tenant mechanism.
</objective>

<interfaces>
`apps/admin/src/lib/query-client.ts` creates the `QueryClient` **at module scope**:

    export const queryClient = new QueryClient({ defaultOptions: { queries: { staleTime: 30_000, retry: 0 }, mutations: { retry: 0 } } });

There is no `persistQueryClient` and no `createSyncStoragePersister` anywhere in `apps/admin/src`, so
the cache has no storage backing that could outlive the document. A new document is therefore
sufficient, and `location.assign` gives one.

`apps/admin/src/lib/api-client.ts` — `apiFetch<T>(path, opts)` returns
`{ status: number; ok: boolean; data: T | null }`. It attaches `x-tenant-id` from a **2-second
module-scope `sessionCache`** of the BA session (`:20-39`). On a client-side switch it would send
the *previous* `activeOrganizationId` against a session bound to the new one, which `AuthGuard`
rejects as `auth.tenant_mismatch` (403). That fails closed — but if an executor meets that 403 while
testing, the fix is the full reload, never weakening the guard.

The five host-dependent navigations, verbatim:

    main.tsx:139-157   reconcileHostWithSession() — parseTenantSlugFromHost + apiFetch('/v1/me/tenants') + window.location.replace(adminUrlForTenant(...))
    pick-tenant.tsx:46 window.location.assign(adminUrlForTenant(res.data.slug, '/dashboard'))
    login.tsx:129      window.location.assign(adminUrlForTenant(switchRes.data.slug, safeNext(next ?? '/dashboard')))
    onboarding/index.tsx:44  previewHost = adminUrlForTenant(slugifyTenantName(displayName) || 'your-restaurant').replace(/^https?:\/\//, '')
    onboarding/index.tsx:71  window.location.assign(adminUrlForTenant(tenant.slug, '/dashboard'))

`login.tsx:108-129` is the awkward one. It POSTs the switch, **then** reads `/v1/me` for `baseRole`,
**then** reads the session for `activeLocationId`, **then** either `navigate({ to: '/pick-location' })`
or hard-navigates. So the destination is only known after two reads that happen after the switch.

`apps/admin/eslint.config.mjs` currently declares **no** `no-restricted-syntax` of its own. The shared
base does: `packages/config-eslint/base.mjs:123` sets
`'no-restricted-syntax': ['error', ...FORBIDDEN_CORRELATION_ID_LITERALS]`, and `:120-123` records the
reason it must be spread at every site — **flat-config rule arrays do not merge across config
objects**, so a new `no-restricted-syntax` entry that omits the spread silently deletes the
correlation-id rule for the matched files. `FORBIDDEN_CORRELATION_ID_LITERALS` is exported from
`@resto/config-eslint/base` (`packages/config-eslint/package.json` exports `"./base": "./base.mjs"`).

Vite exposes the configured `base` at runtime as `import.meta.env.BASE_URL`. It is `'/'` today and
becomes `'/admin/'` in plan 07.4-05. `apps/admin/test/env.spec.ts` already demonstrates that
`import.meta.env` is a mutable object under Vitest and can be set per-test.
