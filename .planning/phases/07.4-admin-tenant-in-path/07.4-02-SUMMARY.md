# Phase 07.4 Plan 02: Delete the browser's tenant selector Summary

**Guest checkout (`createOrder`, `createPaymentIntent`, `getOrderStatus`) now calls `/v1/...` same-origin with no `x-forwarded-host`; the header exists in exactly one file (`lib/api-client.ts`, server-only), pinned by a committed source-tree test.**

## Accomplishments

- Deleted `getApiOrigin()`, the `host` parameter, and the `x-forwarded-host` header from `checkout-api.ts`'s private `apiFetch` — browser calls now hit the root-absolute path (`/v1/orders`, etc.) directly, same-origin.
- Added `fetchOrderStatus` to the server-only `api-client.ts`, following `fetchMenuPublic`'s exact shape (`await headers()`, forward real inbound Host), with `cache: 'no-store'` since order status is per-request guest state.
- Repointed the confirmation page's SSR read from `getOrderStatus` (browser module) to `fetchOrderStatus` (server-only module); the `headers()` call and local `host` binding it used are gone from the page — that plumbing lives in `api-client.ts` now.
- Added a dev-only Next `rewrites()` for `/v1/:path*`, gated `NODE_ENV !== 'production'`, so local dev keeps working without Caddy while production leaves `/v1/*` entirely to Caddy.
- Wrote `no-client-tenant-header.spec.ts`, a source-tree gate asserting the exact file set containing `x-forwarded-host` is `['lib/api-client.ts']` and that that file is `server-only` — proven RED (naming `lib/checkout-api.ts`) against the pre-fix source, then GREEN.
- Extended `checkout-api.spec.ts` with a same-origin-path assertion and a "no tenant-selecting header" assertion for all three exported callers — proven RED against the pre-fix source (URL assertions failed on the literal `http://localhost:3000/...` origin; the header assertions failed `expected true to be false`), then GREEN.
