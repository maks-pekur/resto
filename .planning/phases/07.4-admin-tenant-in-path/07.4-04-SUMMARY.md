# Phase 07.4 Plan 04: Admin tenant out of the URL, switch confined to one module Summary

**Deleted every host-derived tenant mechanism from the admin SPA (admin-host.ts, VITE_ADMIN_HOST_SUFFIX, the main.tsx bootstrap reconciliation) and replaced the five ad-hoc hard-navigations with one `switchTenant()` helper whose full-document-load property is now enforced by an ESLint rule, not by the host boundary that used to make it structurally impossible to get wrong.**

## Performance

- **Tasks:** 2/2
- **Files modified:** 15 (4 created, 2 deleted, 9 modified)

## Accomplishments

- `adminPath(path)` composes an absolute path against `import.meta.env.BASE_URL`, read at call time (not module scope) so plan 05's base-path flip needs zero code changes here — proven by the `BASE_URL='/admin/'` spec case passing today, before that base exists anywhere in config.
- `switchTenant(organizationId, next?)` is now the only module permitted to name `/api/auth/switch-organization`: POSTs the switch, resolves `next` (awaiting it if it's a callback), clears the shared `queryClient`, then `window.location.assign()`s — a full document load, never a router `navigate()`. The callback form is what lets `login.tsx` read `/v1/me` and the session **after** the switch while keeping the single navigation inside this one module.
- ESLint `no-restricted-syntax` in `apps/admin/eslint.config.mjs` confines three shapes to `switch-tenant.ts`: the switch-organization string literal, its template-literal form, and `organization.setActive` calls generally — with `signup.tsx` explicitly allowlisted (first bind of a freshly created org, no prior cache to discard) and `FORBIDDEN_CORRELATION_ID_LITERALS` spread in, since `apps/admin/eslint.config.mjs` had never before declared its own `no-restricted-syntax` and the spread is what keeps the correlation-id rule alive for the matched files (flat-config rule arrays do not merge across config objects).
- Deleted `admin-host.ts` and its spec outright; deleted `VITE_ADMIN_HOST_SUFFIX` (replaced by `VITE_PUBLIC_APEX_DOMAIN`, dev default `localhost:3002` — the website's dev port, so the onboarding preview names a host that's actually reachable in dev); deleted `main.tsx`'s `reconcileHostWithSession()` bootstrap check and its now-dead imports.
- Rewrote all five host-dependent navigations: `pick-tenant.tsx`'s `pick()`, `login.tsx`'s post-switch branch (via the callback form), and `onboarding/index.tsx`'s preview host + post-create navigation, now all routed through `switchTenant()`.
- Repo-wide grep confirms both invariants: the five deleted identifiers (`VITE_ADMIN_HOST_SUFFIX`, `ADMIN_HOST_SUFFIX`, `adminUrlForTenant`, `parseTenantSlugFromHost`, `reconcileHostWithSession`) appear nowhere outside `.planning/`, and `/api/auth/switch-organization` appears in exactly one file: `apps/admin/src/lib/switch-tenant.ts`.

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `window.location` test-mock failed tsc's asymmetric-accessor setter type**
- **Found during:** Task 1, writing `switch-tenant.spec.ts`
- **Issue:** `window.location = { assign: assignMock } as unknown as Location;` passed at runtime (vitest's own global-population layer accepts it) but failed `tsc -p tsconfig.json --noEmit` with `Type 'Location' is not assignable to type 'string & Location'` — `lib.dom.d.ts` declares `Window.location` with an asymmetric get/set pair (`get location(): Location; set location(href: string)`), so TypeScript checks assignment against the narrower `string` setter type.
- **Fix:** Cast `window` itself to a structural type with `location: unknown` before assigning: `(window as { location: unknown }).location = {...}`. This sidesteps the real `Window` type's narrow setter without using `any`.
- **Files modified:** `apps/admin/test/lib/switch-tenant.spec.ts`
- **Verification:** `pnpm --filter admin exec tsc -p tsconfig.json --noEmit` clean; all 5 switch-tenant specs still pass.
- **Committed in:** `968f017a`

## Issues Encountered

- jsdom 25's real `Location` object is non-configurable and non-writable end to end (verified directly against a raw `new JSDOM()` instance: `Object.defineProperty(window, 'location', ...)`, direct `location.assign = fn`, and `delete window.location` all throw). This looked like it would make the plan's "with `window.location` stubbed" instruction impossible. Resolved by finding that vitest's own jsdom environment setup (`populateGlobal` in `vitest/dist/chunks/index.CmSc2RE5.js`) redefines every `Window`-key including `location` as a `configurable: true` accessor on `globalThis` backed by an internal override map — so a plain `window.location = {...}` assignment (not `Object.defineProperty`) works inside an actual vitest test even though it would fail against raw jsdom. Documented in `key-decisions` so a future reader doesn't have to re-derive it.
- `import.meta.url`, when read from inside a jsdom-environment vitest test, does not resolve to a `file://` URL usable by `node:fs` (Vite's browser-target transform of `import.meta.url` apparently routes through the DOM's `location`, which broke a second time once the test's `beforeEach` had already replaced `window.location` with the plain mock object). Resolved by computing the switch-tenant.ts source path via `node:path`'s `resolve(process.cwd(), ...)` instead, matching how the plan's own verify commands assume `pnpm --filter admin exec vitest run` runs with `apps/admin` as cwd.
