<objective>
Prove, against a real stack rather than a stubbed guard, that an operator whose session names tenant
A cannot reach tenant B's data by any route this phase makes reachable.

Purpose: plan 01 changed `AuthGuard` and covered it with unit tests over mocked doubles. This phase
moves the tenant out of the URL and makes the session the sole selector, so the property deserves an
integration-level proof through the real middleware → guard → `ScopedTx` → RLS chain. The founder's
brief names three attack shapes explicitly: a crafted path, a stale session, and a session with no
active organization at all.

Output: one e2e spec with six assertions — five rejections and one positive control — each shown
failing before it is shown passing.
</objective>

`AuthGuard` after plan 01 throws two distinct codes, both as `ForbiddenException` rendered by
`ProblemDetailsFilter` as `application/problem+json`:
  - `auth.tenant_mismatch` — the request binds a tenant the operator principal does not name
  - `auth.tenant_membership_missing` — the operator names the bound tenant but holds no `member` row

`TenantContextMiddleware.resolveTenantOnly` (`tenant-context.middleware.ts:89-120`) resolves in
order: `x-tenant-id` → `x-tenant-slug` (gated) → `effectiveHost(...)`. `effectiveHost`

non-empty string**, so assertion A3 requires `process.env.TRUST_PROXY` to be set in the spec's env
block. Use a CIDR (`'0.0.0.0/0'`), not `'true'` — the literal `true` is rejected by
`env.schema.ts`'s `superRefine` outside dev/test and using a CIDR keeps the test env production-shaped.

`organization-switch.e2e.spec.ts` is the reference for the env block, and its header documents why

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator browser → API | session cookie plus `x-tenant-id`, `x-forwarded-host` and a URL path, all attacker-influenceable except the cookie's contents |
| session row → ALS tenant | the chain this phase makes load-bearing: cookie → BA session → `activeOrganizationId` → `alsTenantId` |
| ALS tenant → Postgres | `ScopedTx` filter plus RLS `app.current_tenant`; a wrong `alsTenantId` is a correct query against the wrong tenant |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07.4-03-01 | Information Disclosure | `x-tenant-id` from an operator bound elsewhere | mitigate | A1 asserts 403 `auth.tenant_mismatch` end to end |
| T-07.4-03-02 | Elevation of Privilege | session with no `activeOrganizationId` | mitigate | A2 asserts 403 through the real middleware, not a mocked ALS |
| T-07.4-03-03 | Spoofing | `x-forwarded-host` naming another tenant | mitigate | A3, with A3-pre proving the forged host genuinely resolves to tenant B first |
