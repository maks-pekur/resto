## 6. Real Production Bugs Found and Fixed (Task-Fidelity Payoff)

This is the section the plan's own threat model (T-10-13-01) exists to produce: the browser-smoke discipline caught bugs no mocked-repository or in-memory-aggregate test could see. All were found while driving `adm-02`/`adm-03` against the real stack, fixed, and re-verified with zero regressions across the batches in §7.

1. **`OrdersEmptyState` crash on malformed API response** (commit `e199067`) — `?? []` only guards `null`/`undefined`, not a wrong-shaped truthy value (a transient 403 returns a problem-details _object_ as `data`). `domains.find is not a function` tripped a permanent React error boundary, making the Orders page unusable until a hard remount. Fixed with `Array.isArray()` guards.
2. **`refund_failed` feed count bug** (commit `48d0669`) — `total` was the pre-filter DB row count, never recomputed after the post-fetch `hasFailedRefund` filter; `RefundFailedBanner` showed a wildly wrong count.
3. **Rate-limiter architecture gap on `/api/auth/*`** (commits `fb6f81a`, `76168f5`) — BA-mounted routes bypass the NestJS-guarded general rate limiter and shared a per-IP bucket with all other anonymous traffic; Phase 10's new 3-concurrent-5s-polling Orders page was the first feature to generate enough `get-session` call volume to exhaust a low-cap bucket (signup/signin) via a shared counter with a high-cap route (public). Fixed with session-cookie-keyed bucketing plus client-side session-lookup coalescing. This directly matches the CLAUDE.md-stated "Friday-evening simultaneous order spikes" peak-load concern.
4. **`initial-brand-drizzle.repository.ts` ALS-binding crash** (commit `cbd7268`) — `TenantContextMiddleware` bound an AsyncLocalStorage tenant context for `/api/auth/*` requests whenever a tenant happened to resolve (dev-fallback slug or host match); Better Auth's org-switch brand/location auto-pin hook then calls `db.withTenantId(...)`, which asserts no ALS is already bound (ADR-0020 I-6) — the assertion threw, silently swallowed, and the operator's session never got `activeBrandId` pinned. Symptom: the Orders feed query stayed permanently `enabled: false`, showing loading skeletons forever. Fixed by excluding `/api/auth/*` from `TenantContextMiddleware` entirely (matching the existing code-comment assumption that BA hooks run outside ALS).
5. **Stale CORS default excluding the website's real dev port** (commit `be3359d`) — `CORS_ALLOWED_ORIGINS` defaulted to `:3003`, a port no app in the repo runs on; `apps/website`'s own `dev`/`start` scripts use `:3002`. Any local dev-stack boot with the default env silently CORS-blocked the checkout confirmation page's live status polling from the browser (server-side render worked; client-side poll failed with an opaque network error).
6. **`tenant:read` missing from every preset staff role** (commit `ed4d30a`) — **ship-blocking.** `manager`/`cashier-foh`/`kitchen` (the only roles real, non-owner staff are ever assigned via `/v1/roles/:slug/assign`) never had `tenant: ['read']`, which `/v1/me/brands` requires. Found via `adm-02` case 8 (the non-owner permission-boundary case), which failed identically across two separate debugging sessions before the real 403 was traced past the frontend's silent-swallow. Fixed by adding `tenant: ['read']` to all three presets, matching `SYSTEM_ROLES.staff`'s existing (but never-assigned-in-practice) grant.
7. **`seed-tenants.ts` — stale `:3000` API origin default + missing `Origin` header** (commits `8fb8842`, `169c00b`) — the stale port default (predating the 08.5 port move to :5001) meant `signInAndGetCookie`/`setActiveOrg` always failed on connection-refused, masking a second, independent bug: neither function ever sent an `Origin` header, tripping Better Auth's own `MISSING_OR_NULL_ORIGIN` origin-check. Fixing the port default alone (Task 1's documented in-flight repair) unmasked the second bug immediately — `adm-00-smoke-walk.spec.ts` scenario 1 now reaches a live server and passes for the first time this session.

All seven are Rule 1/2/3 auto-fixes per the executor's deviation rules (bugs directly blocking correctness, discovered while executing this plan's own file list or its immediate consequences) — none required founder sign-off to fix, and all are re-verified clean in the batches below.
