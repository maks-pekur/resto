**Security-posture decision, locked here (CONTEXT.md Claude's Discretion; RESEARCH E.17 / Assumption A4):** `GET /v1/orders/:id/status` **stays `@Public()`**. The order id is a `randomUUID()` — a 122-bit random capability token in all but name — and adding a second signed token buys little while adding real friction to a feature whose entire value (D-16) is "share this link, watch it update". The mitigation is response minimisation and a **frozen** contract, because the real risk Skeptic MED-7 names is unbounded growth of an already-public payload as more surfaces consume it. Record this decision in the SUMMARY and add a WHY-comment above `OrderStatusResponseSchema` stating: this is a deliberate capability URL; the payload is frozen; do not add fields without revisiting the posture.

**Fix the ETA mapping.** Replace `eta: snap.scheduledFor ? snap.scheduledFor.toISOString() : null` with `etaAt: snap.etaAt ? snap.etaAt.toISOString() : null`. Rename the field `eta` → `etaAt` so no consumer can keep silently reading the old meaning, and add a WHY-comment naming D-15 and the fact that `scheduledFor` is the guest's requested time.

**Freeze the contract** as exactly these fields, and no more:

- `status: z.string()` — the raw order status; the guest-facing label mapping lives in the website (UI-SPEC §11/§12), never here.
- `shortNumber: z.number().int().nullable()` — the daily number the guest sees.
- `orderNumber: z.string()` — retained for support lookups and because it is already public; the website stops displaying it (UI-SPEC §11).
- `total: z.string()`, `currency: z.string()` — retained; already public, and the guest tracker's refund line needs the amount.
- `etaAt: z.string().datetime({ offset: true }).nullable()`.
- `fulfillmentMode: z.enum(['dine_in','pickup','delivery'])` — the tracker's last step label swaps on it (UI-SPEC §11). **`delivery` is a label only**: do not add any dispatch/"on its way" field, because Phase 9 does not exist and the feed must not render a lifecycle the backend cannot back (Skeptic HIGH-6).
- `cancelReason: z.string().nullable()` — the canonical code only. The guest-safe phrase mapping happens in the website's copy deck; the operator-facing chip label never reaches the guest (D-09).
- `canceledFromStatus: z.string().nullable()` — lets the tracker choose between "Ресторан не смог принять ваш заказ" (rejected pre-accept) and "Заказ отменён рестораном" (cancelled after accept), per UI-SPEC §11.

Add **no** guest PII: no `customerName`, `customerPhone`, `customerEmail`, no item-level breakdown, no `cancelNote` (free text an operator wrote for internal use), no `acceptedByUserId` or `canceledByUserId` (internal operator identities).

In `orders.controller.spec.ts`, add a contract test that asserts the response object's key set is **exactly** the nine fields above — a set-equality assertion, so a future field addition fails the test rather than silently widening a public endpoint. Add cases: an order with `etaAt` set returns it as an ISO-8601 string with offset; an order with `etaAt` null but `scheduledFor` set returns `etaAt: null` (proving the two are no longer conflated); a canceled order returns its `cancelReason` code and `canceledFromStatus`.
