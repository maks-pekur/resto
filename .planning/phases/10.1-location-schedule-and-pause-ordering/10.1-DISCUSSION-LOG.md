## Pause semantics

| Option | Description | Selected |
|--------|-------------|----------|
| 20 min / 40 min / until next opening | "Until next opening" comes from the schedule — for a 02:00-closing bar that is tomorrow evening, not midnight | ✓ |
| 20 min / 40 min / rest of day | Easier to explain; a late-night venue un-pauses itself at midnight mid-service | |
| 20 and 40 minutes only | Minimum code; longer closures force a schedule edit that is easy to forget to revert | |

| Option | Description | Selected |
|--------|-------------|----------|
| "Closed until a date" in the same menu | Same pause, with a date picker. Near-free, covers holidays without a calendar | ✓ |
| No — edit the schedule instead | Fewer buttons; relies on the operator remembering to revert | |

| Option | Description | Selected |
|--------|-------------|----------|
| Auto-resume on expiry | Nobody forgets to turn ordering back on; no evening lost to a stale pause | ✓ |
| Auto-resume + prominent notice | Same, plus "ordering resumed" in the feed so the kitchen is not surprised | |
| Operator confirms manually | Safest for the kitchen; loses an evening the first time someone forgets | |

| Option | Description | Selected |
|--------|-------------|----------|
| Pause applies to the whole location | One button, no branching during a rush. Reserve the DB field for a future split | ✓ |

**Notes:** Reviewers disagreed here — the skeptic wanted "rest of day" cut entirely, the product strategist wanted "closed until a date" added. The founder took both: kept the third duration (made computable by the mandatory schedule) and added the date variant.

## Claude's Discretion

Decided without the founder (infrastructure and correctness, per the standing plain-language preference):

- Storage shape — columns + `jsonb` on `locations`, no new child table (avoids a ~140-line `tenancy_erase_tenant` rewrite, an RLS migration, a composite FK, and an isolation fixture).
- How open/closed reaches the guest — rides the existing `/v1/menu/availability` endpoint; ETag must stop being keyed purely on a write counter or a clock-driven schedule change will serve stale "open" 304s forever.
- Time evaluation in TypeScript as a pure domain policy, called before pricing; no date library exists in the repo and the one hand-rolled helper is DST-fragile.
- Which context owns the write path (`tenancy`) and how `ordering` reads it (Symbol port).
- Emitting a `tenancy.*` pause event so the audit trail comes free and Phase 18 SSE gets a push signal.
- Closing the cross-location authorization hole on the new path-param route (a scoped cashier could otherwise pause another location by changing a UUID).
- Folding the new location read into the query `CreateOrderService` already makes — net −1 round-trip.
- Real IANA timezone validation, typing `locations.contacts`, and removing the dead `showLocationBadge` flag.
