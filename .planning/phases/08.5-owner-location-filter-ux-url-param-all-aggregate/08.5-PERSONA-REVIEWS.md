**Reviewers:** persona-cto, persona-skeptic (security-sensitive phase — reworks `LocationScopeGuard` + session model).

Full detail: [`08.5-PERSONA-CTO.md`](./08.5-PERSONA-CTO.md), [`08.5-PERSONA-SKEPTIC.md`](./08.5-PERSONA-SKEPTIC.md).

## Convergence — both personas independently found the same two BLOCKs

### BLOCK-1 — `all`/aggregate endpoints have NO backend owner-only gate (BOLA/BFLA)

The `all` aggregate must be `@LocationNeutral()` to span locations → `LocationScopeGuard` short-circuits (`location-scope.guard.ts:27-31`). The other guards do not fill the gap: `BrandScopeGuard` admits any member reachable to the brand (`brand-scope.guard.ts:57-76`); the wired `BetterAuthPermissionChecker` is tenant-wide, not location-aware; `LocationPermissionChecker` is built but **not wired** (08.4 gap b). **Net:** a non-owner staff scoped only to location A, holding `menu:read`, could call `?location=all` and read locations B/C. "Owner-only" (decision 2) is a **UI affordance, not a backend control.** There is **no reusable owner-only primitive** in the repo (only inline `baseRole === 'owner'` checks).
**Remediation:** introduce an explicit backend owner-only gate (`@OwnerOnly()` guard/decorator, or inline `if (baseRole !== 'owner') throw NotFoundException()` — 404 preserves existence-hiding) on every aggregate endpoint; aggregate query stays ScopedTx tenant+brand-bound; e2e: non-owner `?location=all` → 403/404 with no other-location data.

### BLOCK-2 — Seed D-4 mis-describes the guard; the literal reading is a security regression

Owners already `return true` at `location-scope.guard.ts:65`, **before** the pin-vs-request 404 at lines 67-70. That comparison is reached **only by non-owners** and is the STAFF isolation control (existence-hiding 404 + one-active-location per D-10/D-11). "Drop the comparison on the owner path" describes a path that does not exist; deleting lines 67-70 (the only literal reading) regresses existence-hiding **404→403** (breaks `location-isolation.e2e.spec.ts:177`) and lets multi-location staff free-switch by editing `x-location-id`.
**Remediation:** the owner change is **purely client-side** (`x-location-id` sourced from `?location` instead of the session pin). **Leave the guard's non-owner path untouched.** The real `all` fix is `@LocationNeutral()` on the new aggregate endpoints (the 08.4 gap is a `location.context_required` 403, not a pin 404). Add a guard regression test pinning staff `x-location-id ≠ pin → 404` and staff out-of-scope → 403.
