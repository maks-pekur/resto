<objective>
Introduce the reusable backend owner-only authorization primitive that BLOCK-1 (D-09) requires: an opt-in `@OwnerOnly()` metadata decorator plus an `OwnerOnlyGuard` registered as a fifth global `APP_GUARD`. This is the un-bypassable backend control that the `all`/aggregate endpoints (plan 03) will carry. Because those endpoints must be `@LocationNeutral()` to span locations (which short-circuits `LocationScopeGuard`), and `BrandScopeGuard` admits any brand-reachable member, "owner-only" cannot be a UI affordance — it must be a guard.

This plan ALSO nails down BLOCK-2 (D-08): the owner filter rework is purely client-side, so `location-scope.guard.ts` is NOT touched here or anywhere in this phase. The staff pin-vs-request 404 (existence-hiding) and the non-owner scope path are the STAFF isolation control and must remain intact.

Purpose: give plan 03 a declarative, unit-tested, fail-closed owner-only gate that follows the codebase's existing metadata-guard convention (@Permissions / @BrandNeutral / @LocationNeutral).
Output: `@OwnerOnly()` decorator + barrel export, `OwnerOnlyGuard` + unit spec, guard registration, and a confirmed-untouched `location-scope.guard.ts`.
</objective>

| T-085-02 | Information Disclosure (existence hiding) | denial response for non-owner | mitigate | Guard throws bare 404 (not 403/`{code}`) — does not confirm the endpoint or the owner-only property to an unauthorized caller (V4.3). |
