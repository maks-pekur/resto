# Phase 08.5 Plan 04: Client-side location authority (plumbing) Summary

**apiFetch is now a dumb passthrough keyed on an explicit `opts.locationId` (no more session-read for location); `?location=all|<uuid>` is a typed, zod-validated, layout-inherited search param; and one `useEffectiveLocation()` hook is the single per-role authority (owner: URL + alphabetical default + client-only invalid fallback; staff: session pin, unchanged) — closing the two-source-of-truth HIGH ahead of plan 05's switcher/surface-reads wiring.**

## Accomplishments

- `apiFetch` no longer reads `session.activeLocationId` anywhere — the ONLY producer of `x-location-id` is `opts.locationId`, and `'all'`/`undefined` both omit the header (D-12)
- `?location=all|<uuid>` is a zod-validated (`z.union([z.literal('all'), z.string().uuid()]).optional()`), layout-level search param on `$brandSlug`, inherited by every descendant route (D-01)
- `useEffectiveLocation()` is the one hook every location-scoped query call site uses: owner branch reads the URL, defaults to the first active location alphabetically when absent/invalid (D-03, FLAG documented inline), and client-navigates (`replace: true`) away from an invalid/archived/foreign value without ever trusting that value as server authority (D-18); staff branch is untouched (session pin only, D-04)
- `stopListQuery(brandSlug, locationId)` + new `stopListAggregateQuery(brandSlug)` (targeting `/v1/catalog/stop-list/aggregate` with `locationId: 'all'`) exist with distinct query keys and the `AggregateStopListResponse`/`AggregateStopListItemApi` client types matching plan 03's wire shape
- Fixed the compile break `stopListQuery`'s new required param caused in the dashboard and stop-list page (both were relying on the now-retired owner session pin, so they were already silently broken for owners post-08.5-02) — both now resolve their location via `useEffectiveLocation()` instead

## Decisions Made

- `useEffectiveLocation` takes no arguments and derives `isOwner` from `meQuery()` internally (rather than accepting it as a prop) so every call site gets the D-12 single-authority guarantee automatically, matching the plan's "one hook, not scattered `isOwner ? … : …`" intent.
- Confirmed `meLocationsQuery()` (`GET /v1/me/locations`) already returns only the active locations of the session-pinned active brand for an owner (verified in `member-location-scope-drizzle.reader.ts`) — reused directly rather than adding a second brand-locations fetch.
- `useNavigate({ from: brandSlugLayoutRoute.fullPath })` is required for the D-18 fallback redirect to type-check; `useNavigate()` with no `from` types the `search` updater's return as `never`.
