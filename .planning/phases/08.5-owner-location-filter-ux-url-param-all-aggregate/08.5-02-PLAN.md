<objective>
Retire the owner-side server session pin cleanly (D-13) and shrink the non-owner brand-switch attack surface (D-14), without regressing the staff pin or the 08.4-11 `resetActiveLocation` fix. After this phase the owner's location authority is the URL `?location` param (plans 04/05), so the owner should no longer be able to server-pin a location; and under the staff login-to-brand model (D-15) the non-owner `set-active-brand` path is a reachable scope-mutation endpoint that should be closed outright.

This plan also records the explicit LOW-11 decision (role-change mid-session pin staleness): we ACCEPT the current fail-closed behavior and document it — we do NOT add session-invalidation to `afterUpdateMemberRole` this phase (rationale below).

Purpose: make the owner authority migration structurally clean on the backend and remove a latent BFLA vector, while proving the staff model is preserved.
Output: owner-branch no-op in `set-active-location.service.ts`, `NonOwnerBrandSwitchForbiddenError` + early guard + controller mapping, and updated/added e2e coverage.
</objective>
