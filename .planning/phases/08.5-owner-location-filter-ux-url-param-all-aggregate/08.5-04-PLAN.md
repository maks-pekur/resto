<objective>
Establish the client-side location authority so there is EXACTLY ONE source of truth per role (D-12), closing the two-source-of-truth HIGH. Today `apiFetch` unconditionally echoes `session.activeLocationId` as `x-location-id` for every caller — the same class of bug 08.4 had for the owner pin. This plan makes `apiFetch` a dumb passthrough (explicit `locationId` opt, no session read for location), lifts `?location` to a typed search param on the `$brandSlug` layout (D-01), and introduces one shared `use-effective-location` hook that branches on `isOwner`: owner reads the URL (default = first active location alphabetically when absent, D-03; invalid/archived/foreign falls back client-side to the default, D-18); staff reads the session pin unchanged and ignores any URL param.

This is the plumbing layer — the switcher and the surface reads (dashboard, stop-list) consume it in plan 05.

Purpose: remove the header ambiguity structurally (only one code path produces `x-location-id`) and expose `?location` to every descendant route.
Output: reworked `apiFetch`, `?location` validateSearch, the `use-effective-location` hook, and the location-aware catalog query factories.
</objective>
