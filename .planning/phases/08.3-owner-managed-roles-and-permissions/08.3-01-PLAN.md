<objective>
Land the platform-prerequisite groundwork that makes better-auth `dynamicAccessControl` safe and functional: add the `ac` permission resource, rename all colon-bearing action names, grant `ac` to owner only, define the `NON_DELEGATABLE` allowlist, add the three role-definition audit event contracts + audit target-kind mapping, and flip the `dynamicAccessControl` flag with a role cap.

This is the BLOCKING foundation — every other 08.3 plan (wrappers, assignment, UI, e2e) depends on the `ac` resource existing and the flag being on. Without this, better-auth's role-CRUD gate (`{ ac: ['create'] }`) returns 403 for everyone including the owner (CTO C-2, verified against installed BA 1.4.22 source).

Purpose: Convert "flip the flag" (a no-op / dead plugin) into a working, guarded dynamic-RBAC substrate.
Output: Modified domain RBAC primitives, new `non-delegatable.ts`, three new event contracts, audit map extension, flipped flag, updated regression specs.
</objective>
