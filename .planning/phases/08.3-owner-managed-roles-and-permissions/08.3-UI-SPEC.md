## Spacing Scale

Inherited from project. 8-point scale, multiples of 4 only. Values match Tailwind's default
spacing scale used throughout `apps/admin`.

| Token | Value                  | Usage                                                              |
| ----- | ---------------------- | ------------------------------------------------------------------ |
| xs    | 4px (`gap-1`, `p-1`)   | Icon gaps, inline badge padding                                    |
| sm    | 8px (`gap-2`, `p-2`)   | Compact row padding, button icon gap                               |
| md    | 16px (`px-4`, `gap-4`) | Default element spacing, card content padding                      |
| lg    | 24px (`px-6`, `gap-6`) | Section padding, card section breaks                               |
| xl    | 32px (`gap-8`)         | Layout gaps between major sections                                 |
| 2xl   | 48px (`py-12`)         | Empty-state vertical centering (matches `EmptyState` component)    |
| 3xl   | 64px                   | Page-level max-content gutter (not actively used in 08.3 surfaces) |

Exceptions:

- Permission catalog rows: 12px vertical padding (`py-3`) — between xs and md — to keep the
  grouped list scannable without consuming excessive vertical space on a tall form.
- Role-picker dropdown in team table: uses `h-8` (32px height) `Select` with `size="sm"` — standard shadcn token.

Source: existing `apps/admin` patterns (`team.tsx`, `settings.tsx`, `group-editor-shell.tsx`,
`danger-zone-card.tsx` — all confirmed via codebase scan).

## Color

Tailwind CSS 4 CSS-variable tokens from the `neutral` shadcn palette. No hex values are
hardcoded — always use semantic tokens.

| Role            | Token                                        | Usage                                            |
| --------------- | -------------------------------------------- | ------------------------------------------------ |
| Dominant (60%)  | `bg-background` / `bg-muted`                 | Page background, table row default               |
| Secondary (30%) | `bg-card` / `bg-muted/50`                    | Cards, table headers (`bg-muted/50`), sidebar    |
| Accent (10%)    | `bg-primary` / `text-primary`                | See reserved-for list below                      |
| Destructive     | `text-destructive` / `border-destructive/50` | Archive role button, occupied-role block message |

Accent (`bg-primary` / `text-primary`) reserved for:

1. The "Create role" primary CTA button (`Button variant="default"`)
2. The "Save" button on the role editor (`Button variant="default"`)
3. The "Assign" action in the per-member role picker submit path
4. Focus ring on currently selected permission toggle (`:focus-visible` ring inherits `ring-ring`)

Nothing else receives accent color — preset cards, permission toggles, member-count badges all
use `secondary`, `outline`, or `ghost` variants.

Source: `danger-zone-card.tsx` (`border-destructive/50`, `text-destructive`), `badge.tsx`
(variant map), existing button usage throughout admin app.

## Interaction Contracts

### Surface 1: Roles Page (`/$brandSlug/roles`)

**Layout:** `PageHeading` with title "Roles" and "Create role" button in the action slot.
Below: `Table` with columns [Name | Members | Actions]. Each row shows the role display name,
a `Badge variant="secondary"` with member count (e.g. "3 members"), and ghost icon buttons
for Edit (`Pencil`) and Archive (`Archive`).

**System roles row behavior:** System roles (`owner`, `admin`, `staff`) are listed as
read-only rows with a `Badge variant="outline"` labeled "System" and no Edit/Archive actions.
They provide the starting point for "duplicate" in the preset-first flow.

**Non-owner access:** Render `EmptyState variant="forbidden"` with heading "Owner access
required" and body "Only the account owner can manage roles." No table rendered.

**Empty state (no custom roles):** `EmptyState variant="empty"` with heading "No custom roles
yet", body "Start from a preset — duplicate a built-in role and adjust its permissions to
match the job.", and action button "Create role" (navigates to `/$brandSlug/roles/new`).

**Loading state:** Three `Skeleton` rows in a table container (`rounded-md border`).

### Surface 2: Role Editor (`/$brandSlug/roles/$roleId`)

**Layout:** `PageHeading` with role name as title (or "New role" for create) and "Save role"
/ "Create role" button in the action slot (`Button variant="default" size="sm"`). Below: two
`Card` sections stacked with `gap-6`.

**Card 1 — Role details:**

- `CardTitle`: "Role name"
- `Input` for role name: 1–64 chars, validated on blur and on submit. Error shown as
  `text-destructive text-sm` below the input.
- "Start from a preset" link (`Button variant="ghost" size="sm"`) — opens `PresetPicker`
  Sheet. Visible only when creating a new role (`$roleId === "new"`).

**Card 2 — Permissions:**

- `CardTitle`: "Permissions"
- `CardDescription`: "Select what members with this role can do."
- `PermissionCatalog` component: resource groups as `Collapsible` sections. Each group header
  shows the resource label (e.g. "Menu") and a `ChevronRight` icon that rotates on expand.
  Within each group: one row per action with `Switch` (on/off) and action label. NON_DELEGATABLE
  actions (`tenant:delete`, `tenant:transfer`, `billing:update`, `ac:*`, `staff:remove`) are
  absent from the DOM — hidden, not disabled. `Separator` between groups.

**Edit confirm dialog (blast-radius warning, D-11):**

- Triggered when saving changes to an existing role that has >= 1 member assigned.
- `AlertDialog` (not Dialog) — blocks interaction until dismissed.
- Body shows member count. If 0 members, no dialog; save fires immediately.

**Create flow (presets-first, D-07):**

- New role page renders with empty `Input` and all switches off.
- "Start from a preset" Sheet (`PresetPicker`) shows 3 preset cards. Each card: title
  (Manager / Cashier-FoH / Kitchen), 1-line description of the job, and "Use this preset"
  button. Selecting a preset closes the Sheet and pre-fills the role name and all relevant
  permission switches.
- Owner can then rename and adjust before saving.

**Archive action:**

- "Archive role" button: `Button variant="outline"` with `text-destructive` class and
  `Archive` lucide icon. Shown only on edit (not on create).
- If the role has assigned members: button is replaced by a disabled button with tooltip "Reassign
  members first" and the occupied-role inline message above it.
- If the role has 0 members: button triggers `AlertDialog` for confirmation.

### Surface 3: Active-member assignment (Team page extension, D-10)

**Layout extension in `team.tsx`:**

- Existing pending-invitations section stays at the bottom (unchanged).
- New "Active members" section added above it, within the same `div.flex.flex-col.gap-4.px-4.lg:px-6`.
- "Active members" rendered as `Table` with columns [Member | Current role | Actions (owner-only)].
  - Member column: email address (`text-sm`)
  - Current role column: `Badge variant="outline"` with role name (system role label or custom
    role display name)
  - Actions column (owner-only): `Select` component with `size="sm"` listing all available
    roles (system roles + non-archived custom roles). On change: optimistic update +
    `POST /v1/roles/assign`. Non-owners see the role badge but no Select picker.
- "D-03 callout" (informational): Below the member table, a `p className="text-muted-foreground text-xs"` note:
  "Role permissions apply across all brands. Brand access is controlled separately via brand scope."
  This surfaces the brand-scope orthogonality (D-03 research finding that causes confusion).

**Self-assignment block:** If the current user's own row would show the role picker, the
Select is disabled and has `title="You cannot change your own role"`.

## State Machine: Role Editor

```
CREATE FLOW
  idle (new role form, empty)
    → [click "Start from a preset"]
      → preset-sheet-open
        → [select preset] → idle-with-preset-prefilled
        → [dismiss sheet] → idle
    → [edit name/permissions] → dirty
      → [click "Create role"] → saving
        → [success] → redirect to roles list
        → [422 name taken] → dirty (error shown)
        → [403 subset violation] → dirty (error shown)
        → [network error] → dirty (toast error)

EDIT FLOW
  idle (existing role loaded)
    → [edit name/permissions] → dirty
      → [click "Save role", 0 members] → saving → success toast → idle
      → [click "Save role", N > 0 members] → blast-radius-confirm-open
        → [confirm] → saving → success toast → idle
        → [cancel] → dirty
      → [server error] → dirty (toast error)
    → [click "Archive role", 0 members] → archive-confirm-open
      → [confirm] → archiving → redirect to roles list
      → [cancel] → idle
    → [click "Archive role", N > 0 members] → occupied-block (button disabled, inline message)
```

## Accessibility Contract

- All `Switch` toggles: `aria-label="{action} for {resource}"` — e.g. `aria-label="Read for Menu"`.
  Do not rely on adjacent text alone since the switch is inline with prose.
- `AlertDialog` components: focus is trapped inside the dialog. "Cancel" is the default focused
  element (not the destructive confirm), matching the existing `DangerZoneCard` pattern.
- `Select` role picker in member table: `aria-label="Role for {email}"`.
- Empty state and forbidden state: `role="status"` and `role="alert"` respectively (matches
  existing `EmptyState` component contract).
- `Collapsible` permission groups: `aria-expanded` toggled by shadcn primitive; the trigger
  button must have `aria-label="{Resource} permissions"`.
- `Table` in roles list: `scope="col"` on `<th>` elements (shadcn `TableHead` renders `<th>`).
- All icon-only buttons (`Pencil`, `Archive` in roles table): `aria-label` required —
  e.g. `aria-label="Edit Manager role"`, `aria-label="Archive Manager role"`.
