## Deviations from Plan

### [Rule 3 - Blocking, then fixed] Real 500 in `/v1/roles`, `/v1/roles/:slug/assign`, and PUT `/v1/roles/:slug`

- **Found during:** Task 3 — the cross-tenant spec's `beforeAll` sanity `GET /v1/roles` returned 500.
- **Root cause:** better-auth's `listOrgRoles` returns a **bare array**, not `{ roles: [...] }`. `ListRolesService`,
  `AssignRoleService`, and `UpdateRoleService` all read `result.roles` → `undefined.filter/.find` → 500 on
  every call. Unit tests passed because their mocks returned the wrong `{ roles: [...] }` shape (mock-fidelity trap).
  Secondary bug: BA's `listOrgRoles` never surfaces the custom `archived_at` column, so the D-12 archived-role
  filter (`!r.archivedAt`) could never exclude archived roles — they would leak into the list and the assignment picker.
- **Fix (commit `feb9a11`):** New `listActiveCustomRoles(authDb, organizationId)` helper reads `organization_role`
  directly with `archived_at IS NULL` (the same table `archive-role`/`seed-preset-roles` already query), parsing the
  `permission` JSON text column. `list/assign/update` role services now use it; the wrongly-typed `listOrgRoles`
  is removed from the bridge. Unit mocks rewritten to drive the real helper with production-shape rows
  (permission as a JSON string), so the parse path is actually exercised.
- **Files:** list-active-custom-roles.ts (new), list-roles.service.ts, assign-role.service.ts, update-role.service.ts,
  role-api.bridge.ts, role-services.spec.ts, assign-role.spec.ts.

### [Rule 1 - Bug] Cross-tenant spec assertions targeted the wrong response shape

- **Found during:** Task 3 — after the 500 fix, 3 cross-tenant assertions still failed.
- **Issue:** Tests read `GET /v1/roles` as a bare array of `{ roleSlug }`; the endpoint returns `{ roles: [{ id, role, permission }] }`
  (the contract the plan-04 UI consumes and the spec's own `beforeAll` already used). The DELETE test asserted a
  status code (`not.toBe(204)`) as an isolation proxy, but archive is an idempotent org-scoped no-op.
- **Fix:** Tests read `{ roles: [{ role }] }`; the DELETE test now asserts the real isolation property — after tenant A's
  delete attempt, tenant B's role still exists. Archive semantics left unchanged (idempotent, codebase-consistent).
