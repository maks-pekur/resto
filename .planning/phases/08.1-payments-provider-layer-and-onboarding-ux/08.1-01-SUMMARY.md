# Phase 08.1 Plan 01: Reshape Stripe Connect from Tenant to Brand Aggregate — Summary

Per-brand Stripe Connect linkage replacing the defunct per-tenant stripe columns: migration 0057, Brand aggregate with payment behavior, BrandRepository global lookup + atomic update with outbox events.

## What Was Built

**Migration 0057** adds 6 columns to `brands` (`payment_provider`, `account_type`, `stripe_charges_enabled`, `stripe_payouts_enabled`, `stripe_onboarding_status`, `stripe_requirements_due`) with 3 check constraints, and drops 5 stripe columns from `tenants` with no backfill (no live connected accounts — D-06).

**Brand aggregate** (`brand.aggregate.ts`) now has:

- `BrandSnapshot` with 8 payment fields
- `canAcceptPayments()` — true only when `stripeAccountId !== null && stripeChargesEnabled`
- `linkPaymentAccount(accountId, accountType)` — sets account + transitions to `pending`, pushes `BrandPaymentAccountLinked` event
- `applyPaymentCapabilities(input)` — updates 4 capability fields, pushes `BrandPaymentCapabilitiesApplied` event
- `pullEvents()` — drains event queue

**BrandRepository** interface gains:

- `findByStripeAccountId` — `withoutTenant` global lookup for webhook routing
- `updatePaymentConnection` — `withTenant` ScopedTx update + `buildEnvelope`/`appendToOutbox` for each drained event in one atomic transaction (ADR-0020 I-4)

**Event contracts** `BrandPaymentAccountLinkedV1` and `BrandPaymentCapabilitiesAppliedV1` added to `packages/events/src/contracts/tenancy.ts` and exported from the package index.
