## What Was Built

**Task 1 — Signed single-use OAuth state + env:**

- `oauth-state.ts`: `encodeOAuthState({ brandId, nonce }, secret)` — HMAC-SHA256 over base64url JSON `{ brandId, nonce, iat }`; `verifyOAuthState(state, secret)` — constant-time compare, 10-minute TTL, returns null on any failure. `OAUTH_NONCE_COOKIE = '__Host-resto_oauth_nonce'` exported as the canonical cookie name.
- `env.schema.ts`: `STRIPE_CONNECT_OAUTH_REDIRECT_URL: z.string().url().optional()` added alongside the existing `STRIPE_CONNECT_CLIENT_ID`.

**Task 2 — OAuth start + callback:**

- `StartBrandOnboardingService.startOAuth(slug)`: resolves brand via `requireTenantContext()` + `findByTenantAndSlug`, generates a nonce + signed state, builds the full `connect.stripe.com/oauth/authorize` URL with `response_type=code`, `client_id`, `scope=read_write`, `redirect_uri`, `state`. Returns `{ authorizeUrl, nonce }`.
- `StartBrandOnboardingService.handleOAuthCallback({ code, state, nonce, slugFromPath })`: verifies the signed state (rejects null → `BadRequestException`); asserts `verified.nonce === input.nonce` (replay rejection); resolves brand from `state.brandId` via `brandRepo.findById` — `slugFromPath` is never used to select or authorize the brand. Calls `provider.exchangeOAuthCode({ code })`, links via `brand.linkPaymentAccount(accountId, 'standard')`, calls `provider.retrieveAccount` optimistically to seed capabilities (swallows errors; `account.updated` webhook is authoritative). Persists via `brandRepo.updatePaymentConnection`. Returns redirect URL built from `ADMIN_WEB_URL` (no open-redirect: validated to start with `https?://`).
- `BrandOnboardingController`: `@Get('oauth/start')` (guarded: `@Permissions transfer`, `@RequireActiveTenant`, `@RequireBrand`) sets `__Host-resto_oauth_nonce` via raw `Set-Cookie` header. `@Get('oauth/callback')` (`@Public()`) reads the nonce from `req.headers.cookie`, clears it via `Max-Age=0` header before any side effect, 302-redirects to the validated admin URL.
- 11 unit tests: oauth-state round-trip, tampered signature, wrong secret, no-dot state, expiry; service `startOAuth` URL structure + signed state carries brandId; `handleOAuthCallback` links as standard from state.brandId (not slug); tampered-state rejection; nonce-mismatch (replay) rejection; `access_token` never stored on brand snapshot.

**Task 3 — Admin Standard CTA + resumable method choice:**

- `brand-payments-api.ts`: `startBrandOAuth(brandSlug)` → `GET /v1/tenancy/brands/${brandSlug}/onboarding/oauth/start` returning `{ authorizeUrl }`.
- `brands.$slug.payouts.tsx`: method-choice block: "Create new (Express)" primary `Button` + "Connect existing (Standard)" secondary `Button variant="outline"` calling `oauthMutation.mutate()` → `window.location.href = authorizeUrl`. When `accountType === 'standard'` the page renders `StandardAccountView` (own-dashboard copy, charges/payouts status badges, no embedded component). Resumability: top-level branch on `accountType` returned by `getBrandPaymentStatus`; a returning operator with `accountType='standard'` sees the Standard surface immediately on page load.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] @fastify/cookie not installed**

- **Found during:** Task 2 — `FastifyReply.setCookie` / `clearCookie` TypeScript errors.
- **Issue:** `@fastify/cookie` is not installed in `apps/api`; `FastifyReply` has no `setCookie`/`clearCookie` methods without it.
- **Fix:** Used `res.raw.setHeader('Set-Cookie', ...)` for setting and clearing the `__Host-` cookie, and `req.headers.cookie` + inline `parseCookieHeader` for reading. Produces identical cookie semantics without a new dependency.
- **Files modified:** brand-onboarding.controller.ts

**2. [Rule 1 - Bug] vitest ESM — `require()` not available in test module**

- **Found during:** Task 2 RED phase — initial test used `require()` which fails in vitest ESM mode.
- **Fix:** Switched to static `import` of `StartBrandOnboardingService` and direct constructor call for test instantiation; wrapped the `startOAuth` test in `runInTenantContext` to satisfy `requireTenantContext()`.
- **Files modified:** brand-onboarding-oauth.spec.ts

## Threat Surface Scan

All new endpoints are within the plan's `<threat_model>`:

- `GET oauth/start` — guarded by `@Permissions transfer` + `@RequireActiveTenant` + `@RequireBrand`; nonce cookie is `HttpOnly`, `SameSite=Lax`, `__Host-` prefix (path-locked).
- `GET oauth/callback` — `@Public()` but brand is resolved exclusively from the HMAC-verified `state.brandId`; nonce cleared on first use; redirect only to `ADMIN_WEB_URL`-origin URL validated with `^https?:\/\/` check.
- `access_token` never persisted — only `stripe_user_id` stored as `stripeAccountId`.
