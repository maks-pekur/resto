# Phase 08.1 Plan 03: Per-brand account + currency resolution at checkout Summary

Eliminated the `StripeConnectPort`/`STRIPE_CONNECT_PORT` abstraction from the tenancy bounded context and routed all Stripe operations through `PaymentProviderPort`/`PAYMENT_PROVIDER_PORT` in the payments bounded context. Webhook handler and controller now resolve `BrandRepository` for account lookup and delegate signature verification to the provider port.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Unused variable `piObj` in handlePaymentIntentSucceeded**

- **Found during:** Task 2 pre-commit ESLint hook
- **Issue:** `piObj` was declared as a cast of `pi` but only used as `typeof piObj` in a type position — ESLint flagged `@typescript-eslint/no-unused-vars`
- **Fix:** Replaced the runtime variable with an inline `interface PiObject` declaration; removed the dead `pi` + `piObj` variables
- **Files modified:** `handle-stripe-event.service.ts`
- **Commit:** included in `de8d9e1`

**2. [Rule 2 - Missing critical] ProvisionTenantService Stripe no-op removed**

- **Found during:** Task 3 — `STRIPE_CONNECT_PORT` no longer in `TenancyModule` exports
- **Issue:** `ProvisionTenantService` injected `STRIPE_CONNECT_PORT` to call `ensureExpressAccount` which was a no-op placeholder. With the port removed there was no valid binding.
- **Fix:** Removed the `stripe` dependency entirely from `ProvisionTenantService`; the no-op call was purely a placeholder and carried no semantics. Spec updated to match single-argument constructor.
- **Files modified:** `provision-tenant.service.ts`, `test/unit/tenancy/provision-tenant.service.spec.ts`
- **Commit:** included in `eaefc59`

**3. [Rule 3 - Blocking] TenantRepository mocks in unit tests had stale `findByStripeAccountId`**

- **Found during:** Task 3 — removing `findByStripeAccountId` from `TenantRepository` interface broke 6 mock objects in unit tests
- **Fix:** Removed `findByStripeAccountId` from all `TenantRepository` mock shapes; `BrandRepository` mocks are unaffected (that method remains on `BrandRepository`)
- **Files modified:** 5 unit test files + `tenant-context.middleware.spec.ts`
- **Commit:** included in `eaefc59`

**4. [Rule 4 mitigated - Architecture] Circular dependency TenancyModule ↔ PaymentsModule**

- **Found during:** Task 3 design — plan said to add `PaymentsModule` import to `TenancyModule` for `PAYMENT_PROVIDER_PORT`, but `PaymentsModule` already imports `TenancyModule`
- **Resolution:** Placed `StripeProviderAdapter` factory directly in `TenancyModule` (not `PaymentsModule`), exported `PAYMENT_PROVIDER_PORT`. `PaymentsModule` receives the token via its existing `TenancyModule` import. No circular dependency, no `forwardRef`.
