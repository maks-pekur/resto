# RES-236 Phase 3b — Composite tenant FK migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apply ADR-0020 I-2 (composite tenant FK) to all currently-existing tenant-scoped child tables, while repairing the Phase 3a oversight that left migration `0024_brand_domains_composite_fk.sql` unregistered in the drizzle journal.

**Architecture:** Mechanical extension of the Phase 3a pattern (commit `b834444`). One hand-authored SQL migration (`0025`) with 15 statements (3 parent unique indexes + 6 child FK DROP/ADD pairs). One parametrized regression spec asserting cross-tenant child inserts fail with Postgres SQLSTATE `23503` under `withoutTenant` (so the structural FK is the only guard left, not RLS). Journal-entry fix in the same PR so both `0024` and `0025` actually apply.

**Tech Stack:** Drizzle ORM (`drizzle-orm`, `drizzle-kit`), Postgres 16, `postgres` driver, Vitest, `@testcontainers/postgresql`.

**Spec:** [`docs/superpowers/specs/2026-05-24-res-236-phase-3b-design.md`](../specs/2026-05-24-res-236-phase-3b-design.md)

**Branch:** `res-236` (already off `main` at `b834444`).

**PR title (final):** `feat(db): composite tenant FK for remaining tenant-scoped children (RES-236)`
